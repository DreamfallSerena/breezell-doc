# Git

Breezell 1.4.59 には、IntelliJ IDEA 風の Git が加わりました。コミットするファイルを選ぶだけでなく、ファイルの一部だけをコミットできます。AI の会話が変更したファイルは会話ごとにまとまります。ブランチのグラフを見たり、変更を棚上げしたり、プッシュする前に送られるコミットを確認したり、対話的に Rebase したりできます。ブランチのポップアップでは、チェックアウト、比較、マージもできます。[Agents ページ](/ja/agents-page)でも IDE でも使えます。

| 用語 | 意味 |
| --- | --- |
| チェック | 次のコミットに含めること。チェックしていない変更は作業ツリーに残り、コミットされません。 |
| ハンク | ファイルの中の、ひとまとまりの連続した変更。ファイルの一部のハンクだけをチェックできます。 |
| 棚上げ | 変更をいったん脇に置いて作業ツリーをきれいにし、あとで戻せるようにすること。 |
| 上流 | 現在のブランチが追従するリモートのブランチ。たとえば `origin/main`。 |

## 開き方 {#open}

- **Agents ページ**：左側のリスト上部の **Git**。横の数字は、このプロジェクトで変更のあるファイルの数です。クリックするとページの中央に Git が開きます。左上の矢印（**会話に戻る**）か `Esc` で会話に戻ります。
- **IDE**：コマンド パレット（`Ctrl+Shift+P`）で `Git: Commit…`、`Git: Push…`、`Git: Update Project`、`Git: Show Log`、`Git: Show Shelf`、`Git: Branches…` のいずれかを実行すると、**Git** という名前のタブが開きます。内容は Agents ページの Git と同じです。
- どのページでも、`` Alt+` `` で **Git 操作** メニューが開きます：**コミット…**、**プッシュ…**、**プロジェクトの更新**、**ブランチ…**、**ログ**、**シェルフ**、**フェッチ**。

## 表示されるプロジェクト {#project}

- Git は見ている会話に従います。このウィンドウのプロジェクトの会話ならそのリポジトリ、ほかのプロジェクトの会話ならそのプロジェクトのリポジトリで、上部にプロジェクト名が表示されます（ホバーテキスト「「*プロジェクト名*」の Git（そのウィンドウから）」）。WSL や SSH のプロジェクトも同じです。
- そのプロジェクトのウィンドウが開いていないときは、Breezell が画面に出さずにバックグラウンドで開きます。そのあいだページには「「*プロジェクト名*」のウィンドウに接続しています…」と表示されます。
- 1 つのプロジェクトに複数のリポジトリがあるときは、リポジトリ名（**リポジトリを切り替え**）をクリックして選びます。
- まだ Git リポジトリではないフォルダーには、「このプロジェクトはまだ Git リポジトリではありません。」と **リポジトリを初期化** ボタンが表示されます。

上部の行は、左から順に次のとおりです。

- ブランチ名：[ブランチのポップアップ](#branches)を開きます。横の同期状態は IDE のステータス バーのものと同じで、クリックしたときの動作も同じです。
- **プロジェクトの更新**（下向きの矢印）：[プロジェクトの更新](#update)を参照してください。
- **プッシュ…**（上向きの矢印）：[プッシュ](#push)を参照してください。
- **その他の Git 操作**（⋯）：IDE のソース管理の「⋯」メニューと同じです。たとえばプル、リモート、タグ、ワークツリーです。

下に 3 つのタブがあります：**コミット**（変更の数つき）、**ログ**、**シェルフ**。

## コミット {#commit}

### コミットするものをチェックする {#check}

- すべてのファイルにチェックボックスがあります：**チェック：次のコミットに含める**、**チェックを外す：次のコミットに含めない**。グループの見出しのチェックボックスは、グループ全体をまとめてチェックしたり外したりします。一部だけチェックされているときは、横線が表示されます。
- ファイルの一部だけをコミットするには、ファイル名の前の矢印（**ハンクを表示（ファイルの一部だけをコミット）**）をクリックして、含めたいハンクをチェックします（**このハンクをチェック：次のコミットに含める**）。新規、削除、バイナリのファイルにはハンクがなく、ファイル全体でチェックします。
- ファイル名をクリックすると、そのファイルの変更が開きます。Agents ページではページの右側に、IDE ではエディター領域に開きます。
- ファイルを右クリックすると、IDE 標準のファイル操作（たとえば変更の破棄）のほかに、**棚上げ…** と **履歴を表示**（ログで、そのファイルのコミットだけを表示）があります。

### グループ {#changelists}

- **「Agent · *会話のタイトル*」**：AI の会話が変更したファイルが、会話ごとのグループになります。複数の会話が変更したファイルは、最も新しい会話のグループに入ります。これで、ある会話が行ったことだけをコミットできます。
- **変更**：それ以外の変更したファイル。
- **バージョン管理外のファイル**：Git がまだ追跡していない新しいファイル。最初はたたまれています。

### メッセージとコミット {#message}

- **コミット メッセージ** 欄にメッセージを書いて、**コミット** をクリックします（`Ctrl+Enter`、macOS は `Cmd+Enter`）。**コミットしてプッシュ…** は、コミットのあとに[プッシュ](#push)を開きます。
- 入力欄の横の 2 つのボタン：**コミット メッセージの履歴**（以前使ったメッセージを選べます）と **AI でコミット メッセージを書く（チェックした変更から）**。
- **前回のコミットを修正**：チェックすると、チェックした変更が新しいコミットではなく直前のコミットに入り、そのコミットのメッセージが入力欄に入ります。
- **変更を棚上げ…**：チェックしたファイル（何もチェックしていないときはすべての変更）を[シェルフ](#shelf)に入れます。
- **チェックした変更を AI にレビューさせる**：レビューの依頼文が入力済みの新しい会話が開くので、確認して送信します。AI は問題点を指摘するだけで、ファイルは変更しません。

### マージの競合 {#conflicts}

マージ、Rebase、Cherry-Pick、Revert で競合が起きると、**コミット** タブの上部に **マージの競合** とファイルの数が表示されます。

- 各ファイルの横の **解決…** でマージ エディターが開きます。ほかのプロジェクトのファイルは、そのウィンドウで解決します（**そのウィンドウで解決…**）。
- **AI に競合を解決させる**：両方の側で残すべきものを残して競合マーカーを取り除くよう AI に頼む、新しい会話が開きます。コミットはせず、マージや Rebase を自分で続行することもありません。
- すべて解決したら **続行** をクリックします。Rebase と Cherry-Pick では、現在のコミットを **スキップ** することもできます。**中止** は開始前の状態に戻します。

## ログ {#log}

- ブランチのグラフつきでコミットを表示します。下へスクロールすると古いコミットが読み込まれます。
- 上部のフィルター：**テキストまたはハッシュ**、**作成者**、**パス**、そしてどのブランチの履歴を表示するか（**どのブランチの履歴か**）：**すべてのブランチ**、**現在のブランチ**、または特定の 1 つのブランチ。
- コミットをクリックすると、リストの横に詳細と変更したファイルが表示されます。ファイルをクリックすると、そのコミットでの変更が見られます。**ローカルと比較** は、代わりにそのコミットと作業ツリーで異なるファイルを一覧にします。

コミットを右クリックしたとき：

| 項目 | 内容 |
| --- | --- |
| **リビジョン番号をコピー** | コミットのハッシュをコピーします。 |
| **このリビジョンをチェックアウト** | そのコミットをチェックアウトします（どのブランチにも属しません）。 |
| **ここから新規ブランチ…**、**ここに新規タグ…** | そのコミットを起点にブランチやタグを作ります。 |
| **チェリーピック** | そのコミットの変更を現在のブランチに適用します。 |
| **コミットを元に戻す** | そのコミットの変更を打ち消す新しいコミットを追加します。 |
| **現在のブランチをここにリセット** | **Soft：変更を残してチェック**、**Mixed：変更を残し、チェックしない**、**Hard：変更を破棄**（もう一度確認されます）。 |
| **コミットを取り消す** | 現在のブランチの最新のコミットにだけあります。そのコミットを取り除き、変更はチェックされた状態で戻り、メッセージは入力欄に戻ります。 |
| **コミット メッセージを編集…**、**コミットを削除…** | [対話的な Rebase](#rebase) で、そのコミットのメッセージを変えるか、取り除きます。 |
| **ここから対話的にリベース…** | [対話的な Rebase](#rebase)を参照してください。 |

[ブランチのポップアップ](#branches)で現在のブランチとの「比較」を選ぶと、ログにはそのブランチにあって現在のブランチにないコミットだけが表示されます（「*ブランチ*」にあり「*現在のブランチ*」にないもの）。**ブランチに戻る** で通常のログに戻ります。

### 対話的な Rebase {#rebase}

- ログで **ここから対話的にリベース…** を選ぶと、そのコミットから最新までのすべてのコミットが一覧になります。
- 各コミットに対して、**ピック**、**メッセージ変更**、**スカッシュ**、**フィックスアップ**、**削除** のいずれかを選び、**上へ**・**下へ** で順番を変えます。メッセージ変更とスカッシュでは、その場で **新しいメッセージ** や **スカッシュ後のコミットのメッセージ** を書けます。
- **リベースを開始** をクリックします。コミットしていない変更はいったん脇に置かれ、終わると戻ります。競合が起きたら、[マージの競合](#conflicts)と同じように対処します。

## シェルフ {#shelf}

- 棚上げした変更と、そのファイルを一覧にします。
- **棚から戻す**：変更を作業ツリーに戻し、シェルフから取り除きます。
- **適用して棚に残す**：作業ツリーに戻し、シェルフにもコピーを残します。
- **削除**：変更を捨てます（もう一度確認されます。削除した変更は失われます）。

## プッシュ {#push}

- **プッシュ…** は、先にプッシュされるコミットを一覧にします。現在のブランチにまだリモートのブランチがないときは、**新しいブランチ** と表示されます。
- リモートにこちらにないコミットがあるときは、プッシュが拒否される場合があるという警告が出ます。先に **プロジェクトの更新** を実行できます。
- オプション：**タグをプッシュ**、そして **強制プッシュ（with lease）**。後者は、リモートが前回見たときのままのときだけ強制するので、他の人がプッシュしたばかりのコミットを上書きすることはありません。
- プッシュするものがないときは、「プッシュするコミットはありません（リモートと同じです）。」と表示されます。

## ブランチのポップアップ {#branches}

上部のブランチ名をクリックするか、`Git: Branches…` を実行するか、**Git 操作** で **ブランチ…** を選びます。

- よく使う操作が先頭にあります：**プロジェクトの更新**、**コミット…**、**プッシュ…**、**新規ブランチ…**、**タグまたはリビジョンをチェックアウト…**。
- そのあとに **最近**、**ローカル**、**リモート** が続きます。ローカルのブランチの横の星は **お気に入りに追加** で、お気に入りはローカルのブランチの先頭に並びます。
- ブランチには、リモートとの差が表示されます（↑ はまだプッシュしていないコミット、↓ はまだプルしていないコミット）。リモートのブランチが削除されたときは **上流が削除済み** と表示されます。

ブランチを選ぶと、できることが表示されます。

- **チェックアウト**：リモートのブランチは、同じ名前のローカルのブランチとしてチェックアウトされます。
- **「*ブランチ*」から新規ブランチ…**、**チェックアウトして「*現在のブランチ*」にリベース**、**「*現在のブランチ*」と比較**、**「*ブランチ*」と作業ツリーの差分を表示**。
- **「*現在のブランチ*」を「*ブランチ*」にリベース**、**「*ブランチ*」を「*現在のブランチ*」にマージ**。
- **名前を変更…** と **削除**。リモートのブランチには **リモートから削除** があります。マージされていないブランチを削除するときは、もう一度確認されます。

チェックアウトするとローカルの変更が上書きされるときは、Breezell が **スマート チェックアウト** を提案します。変更を棚上げし、チェックアウトして、変更を戻します。

## プロジェクトの更新 {#update}

**プロジェクトの更新** はフェッチしてから、現在のブランチを上流に合わせて最新にします。コミットしていない変更はそのあいだ脇に置かれ、終わると戻ります。終了時に「更新しました：N 件のコミットを取り込みました。」または「すでに最新です。」と表示されます。

初期設定ではマージで更新します。代わりに Rebase にするには、設定で `breezell.git` を検索し、Update Method を rebase にします（この設定の文言は英語です）。

## IDE のキー {#keys}

IntelliJ IDEA の Git キーを使うには、設定で `breezell.git` を検索し、Idea Keymap をチェックします（初期設定ではオフです）。

| キー | 操作 |
| --- | --- |
| `Ctrl+K` | コミット |
| `Ctrl+Shift+K` | プッシュ |
| `Ctrl+T` | プロジェクトの更新 |
| `Alt+9` | ログ |
| `Alt+0` | コミット |

macOS では `Ctrl` の代わりに `Cmd` を使い、ログとコミットは `Cmd+9` と `Cmd+0`、**Git 操作** は `Ctrl+V` です。これらのキーをオンにすると、IDE 標準の `Ctrl+K` で始まる組み合わせと `Ctrl+T` の代わりになります。`` Alt+` `` は設定が不要で、いつでも使えます。

## 現在の制限 {#limits}

- とても大きなファイルとバイナリ ファイルは、変更内容が表示されません。大きすぎるファイルはハンクに分けられず、ファイル全体でチェックします。
- 変更したファイルがとても多いときは、一部だけが一覧になり、残りは件数で示されます。完全なリストは IDE のソース管理にあります。
- 範囲にマージ コミットがあるときは、対話的な Rebase はできません。最初のコミットは前のコミットにスカッシュやフィックスアップできず、取り消すこともできません。
- ほかのプロジェクトの Git は、そのプロジェクトのウィンドウを経由します。そのウィンドウが閉じたときは、ページに「「*プロジェクト名*」のウィンドウは閉じられました。」と表示されます。**再試行** をクリックすると、もう一度接続します。
- Git 以外のソース管理は、シンプルな表示です：**コミット メッセージ**、**コミット**、変更のリスト。
