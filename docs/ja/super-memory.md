# Super Memory

**Super Memory** は Breezell が独自に開発した記憶システムです。Breezell に組み込まれた 2 つのモデルを使用して、会話から有用な情報を抽出します。これらのモデルの正式名称は公開されていません。

記憶の抽出は Breezell 内部のモデルパイプラインで処理されるため、ユーザーが設定したモデルのトークンやトークン枠は消費しません。

## Super Memory が抽出できる情報

抽出した情報は、次の種類に分類されます。

- **Memory：** 後で役立つ可能性がある事実、設定、継続的な指示、決定事項。
- **Skill：** タスクの中で見つかった再利用可能な方法やワークフロー。
- **Experience：** 過去の作業から得られた結果、教訓、実践的な知識。
- **Trajectory：** タスク、決定、目標が時間とともに進んだ過程。
- **Resource：** 作業に関連する有用なファイル、リンク、ツール、参考資料。

これらの項目は会話から自動的に抽出、分類され、後のやり取りで関連するコンテキストとして呼び出せます。

## 記憶の表示と絞り込み

![Super Memory パネル](/super-memory/super-memory-panel.png)

パネルでは次の表示と操作を利用できます。

- **Memories、Context、Insights：** 抽出された記憶、構成されたコンテキスト、記憶全体から得られた分析を切り替えます。
- **検索：** テキストを使用して保存済みの項目を検索します。
- **優先度：** **P0**、**P1**、**P2**、またはすべての優先度で絞り込みます。
- **種類：** Memory、Skill、Experience、Trajectory、Resource で絞り込みます。
- **状態：** **Active** と **Dormant** の項目を分けて表示します。
- **容量カウンター：** 項目の総数と、常駐項目、記憶、スキル、経験で使用している現在の容量を確認します。
- **Select：** 選択モードを開き、管理する項目を個別に選択します。

項目が存在しない場合は、会話から記憶が自動抽出されることが表示されます。会話を続けると、ユーザーが手動で入力しなくても有用な項目がここに追加されます。

## 主な利点

Super Memory は、強力な自動抽出と効率的で制御性の高い検索を組み合わせています。

- **強力な抽出：** Breezell 内部の 2 つのモデルが会話を分析し、有用な情報を Memory、Skill、Experience、Trajectory、Resource の構造化された項目に変換します。手動入力は必要ありません。
- **効率的な検索：** 種類、優先度、状態、鮮度、コンパイル済みメモリインデックスを使用して、保存済みのすべての項目を同等に扱うのではなく、現在のタスクに関連する情報へ検索範囲を絞ります。
- **制御可能なコンテキスト注入：** Context 画面では、現在のターンに注入されたスナップショット、次のターンのメモリインデックスプレビュー、推定トークン数を確認できます。
- **明確なライフサイクル管理：** P0 永続、P1 30 日、P2 7 日の優先度と Active、Dormant の状態を組み合わせ、重要な知識を維持しながら一時的な情報の保持期間を短くできます。
- **確認可能な知識状態：** コンパイル状態、ソースとコンパイラーのバージョン、古いリソース、失敗、検証、修正、鮮度、未同期件数を確認できます。
- **トークンの可視化：** 抽出処理はユーザーが設定したモデルのトークンを消費しません。検索された記憶がリクエストに注入されると、そのリクエストのコンテキストに含まれます。プレビューと節約統計により、この使用量を確認できます。

## Context と検索制御

![Super Memory の Context 画面](/super-memory/super-memory-context.png)

**Context** 画面では、会話で記憶がどのように使用されるかを確認できます。

- **Current Turn Injection：** 現在の会話ターンに注入された記憶のスナップショットを表示します。スナップショットがない場合は、空の状態が明確に表示されます。
- **Memory Index Preview：** 次のターン用に準備されたインデックスと推定トークン数をプレビューします。
- **Conversation Turns：** 現在のスレッドのターン数を表示し、ターン単位の記憶利用を確認できます。

これにより、記憶が注入されたか、次に何が準備されるか、おおよそのコンテキストコストを確認できます。

## Insights とシステム状態

![Super Memory の Insights 画面](/super-memory/super-memory-insights.png)

**Insights** 画面では、記憶システムの状態と効果をまとめて確認できます。

- **Project Knowledge Health：** 最終コンパイル、コンパイラーとソースのバージョン、古いリソース、失敗したコンパイル、検証または修正された件数を表示します。
- **Token Savings：** 十分な利用記録がある場合にトークン節約量を表示します。
- **Viking Filesystem：** Memories、Skills、Experiences、Trajectories、Resources、Unsynced の件数を表示します。
- **Priority Distribution：** P0 永続、P1 30 日、P2 7 日の分布を表示します。
- **Freshness Pulse：** 24 時間以内、7 日以内、30 日以内、それより古い知識に分類します。

Context と Insights により、Super Memory が何を抽出し、何を検索対象にする可能性があり、保存された知識がどの程度新しく健全であるかを確認できます。

## Active と Dormant

Active の記憶は、関連する情報を呼び出すために利用可能な状態です。Dormant の記憶は保持されますが、Active の集合から分離されます。これにより、後で必要になる可能性がある情報を残しながら、現在のコンテキストを整理できます。

## デモ：修復作業を再利用可能な記憶に変換する

この例では、意図的に不具合を含めた HTML タスクマネージャーを使用し、短い修復作業を Super Memory が再利用可能な知識に変換する過程を示します。

依頼では、想定された UI や機能を変更せずに、タスクの作成、削除、完了状態、フィルター、カウンター、localStorage の永続化、キーボード入力、完了タスクの削除に関する問題をコード全体から特定して修正するよう AI に求めています。

### 1. タスクマネージャーを調査して修復する

Breezell は各症状を別々の不具合として扱うのではなく、コードを調査して共通の根本原因を特定し、実装を修正して一連の動作を検証します。

![タスクマネージャーを修復する Breezell](/super-memory/task-manager-repair.png)

修復には、シリアライズと解析、重複読み込み、破損した保存データ、空タスクの検証、安定したタスク ID、キーボード操作、完了状態の切り替え、対象を指定した削除、フィルター、カウンター、完了タスクの消去が含まれます。

### 2. 最初の P2 Resource 記録

小規模なテストであり、最初の結果が主に具体的なファイル編集を示しているため、Super Memory は **test.html** の 2 つの編集箇所を **P2 Resource** として最初に記録します。

![修復から作成された P2 Resource 記録](/super-memory/p2-resource-records.png)

この記録には、何をどこで変更したかが保存されます。短期的な実装の詳細には P2 の低い優先度を与えつつ修復履歴を残すため、後で AI が変更箇所を確認できます。

### 3. より深い振り返りを促す

この小規模なデモでは、ユーザーが次のように質問します。

> この問題を解決して、どのような教訓を得ましたか？

![修復から得た教訓をまとめる AI](/super-memory/repair-lessons.png)

回答では、共有状態の所有元を直すこと、コレクション要素を安定した ID で扱うこと、派生状態をすべての描画経路で再計算すること、永続化を検証済みデータ境界として扱うこと、真偽条件を慎重に確認すること、不正な入力経路を終了させること、時刻だけを ID にしないこと、現実的な一連の操作で機能を検証することなど、再利用可能な教訓が抽出されます。

### 4. 構造化された修復知識を抽出する

修復をより深く検討した後、Super Memory は価値の高い構造化項目を追加します。

- 共有タスク状態と安定した ID の修復に関する **P1 Experience**。
- 保護されたシリアライズと解析によって破損した localStorage 永続化を修復する **P1 Skill**。
- 複数の不具合と解決過程をまとめた **P2 Trajectory**。
- 編集箇所を保存する最初の **P2 Resource** 記録。

![振り返り後の構造化された修復記憶](/super-memory/structured-repair-memories.png)

### このデモで分かること

- **抽出の深さは価値に応じて変化します：** 小さな編集は P2 Resource から始まり、再利用可能な根本原因の知識は P1 Skill や Experience として記録されます。
- **記憶の種類ごとに役割が異なります：** Resource と Trajectory は何が起きたかを、Skill と Experience はどのように、なぜ解決したかを保存します。
- **優先度を制御できます：** P1 は再利用性の高い知識を長く保持し、P2 は短期的な詳細を永続的な重みを与えずに利用可能にします。
- **将来の AI 作業で利用できます：** 後のタスクでは元の会話だけに頼らず、関連するファイル履歴、修復方法、エンジニアリング上の教訓を検索できます。
- **通常は手動で質問する必要はありません：** この質問は小さなテストで明確な結果を示すために使用しています。長期的または重要な不具合では、ユーザーが質問しなくても Super Memory が永続的な修復経験を自動的に検出、記録できます。
