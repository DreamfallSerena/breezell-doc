# 更新履歴

## 1.4.54 · ホットアップデート · 2026-11-09

1.4.5 向けのホットアップデートで、再インストールは不要です：Breezell が自動で案内するほか、Box サイドバー下部の「アップデート」で確認することもできます。

### プロジェクトグループ

- **会話の中でグループを提案：** 会話の中で開いている別のプロジェクト（名前、パス、ファイル、API や ポート番号）に触れると、入力欄の上に「これらのプロジェクトを同じグループにしますか？」が表示され、触れたプロジェクトにはチェックが入っています。「グループにする」または「グループにして 1 つのウィンドウにまとめる」を押します。「今回はしない」や「これらは今後聞かない」も選べます。押さなければ何も変わらず、AI はいつもどおり答えます。
- **グループのページ：** 「プロジェクトグループとメモリ共有」はエディター領域のタブとして開くようになりました。エクスプローラー上部の「現在」「すべて」の横にあるボタンから開きます。「Folders」ビューをエクスプローラーの外に移した場合はそのタイトルバーにも同じボタンがあり、コマンドパレットからも開けます。
- **メンバーの場所：** タブには各メンバーがどの環境（Windows、WSL、SSH）にあるか、そしてウィンドウが開いているか、閉じているがここからファイルを読めるか、閉じているかが表示されます。閉じているメンバーには「開く」があります。
- **プロジェクトの追加：** 「開いているウィンドウを追加」または「フォルダーを選んでグループに追加…」で追加できます。フォルダーのウィンドウを開いておく必要はありません。
- **グループの管理：** グループ名の変更、「グループから抜ける」、「グループを解散」（2 回押すと解散）ができます。グループに入っていないときは、ここでグループを作るか、ほかのグループに加わることができます。

### グループのプロジェクトと一緒に作業

- **グループのプロジェクトを読む：** AI はグループにどのプロジェクトがあるかを知っていて、それらに触れるとファイルを読めます。別の環境にあるプロジェクト（たとえば Windows のウィンドウから見た WSL のプロジェクト）は、そのウィンドウが開いているあいだ読めます。開いていないときは、それを開くよう案内されます。
- **グループのプロジェクトを変更：** 「AI がグループのプロジェクトを変更できるようにする」をオンにすると、AI はそれらのファイルを変更し、そのフォルダーでコマンドを実行することもできます。既定ではオフです。
- **会話の共有：** 「会話を共有」をオンにすると、「グループのプロジェクトの会話…」でほかのプロジェクトの会話を「表示」したり、「このウィンドウで続ける」、「次のメッセージに添付」したりできます。「グループのプロジェクトに任せる…」は作業を別のプロジェクトのウィンドウに任せ、終わったら知らせます。
- **1 つのウィンドウ：** 「1 つのウィンドウにまとめる」は、グループのプロジェクトを複数のフォルダーを持つ 1 つのウィンドウで開きます。Windows と WSL のプロジェクトも一緒にまとめられます。元のウィンドウは閉じ、会話はコピーされ、タイトルの前にどのプロジェクトのものかが付きます。「別々のウィンドウに戻す」で元に戻せます。

### チャット

- **チャットタブとコードタブを同じ列に：** チャットタブをコードタブと同じ列に置けるようになりました。履歴からファイルのタブの列にドラッグした会話、「エディタータブで開く」、チャットタブの「New Chat」は、置いた場所にとどまり、別の列に移されなくなりました。
- **会話履歴のタイトルと日時を修正：** 複数のフォルダーを持つワークスペースで開いたことのあるプロジェクトを単独で開くと、会話のタイトルが最初の一文になり、日時がすべて開いた時刻になっていました。現在は各プロジェクトの会話が元のタイトルと日時を保ちます。

### WSL

- **空のウィンドウを修正：** ショートカットから WSL のプロジェクトを開くと、ウィンドウに何も表示されないことがありました（エクスプローラーが空で、ソース管理に「No source control providers registered」と表示される）。現在は正常に接続してプロジェクトを表示します。

## 1.4.53 · ホットアップデート · 2026-11-08

1.4.5 向けのホットアップデートで、再インストールは不要です：Breezell が自動で案内するほか、Box サイドバー下部の「アップデート」で確認することもできます。

### タイトルバー

- **検索ボックスが戻りました：** タイトルバー中央は 1.4.52 より前の検索ボックスに戻り、クリックすると検索が開きます。通知ベルと更新ボタンはその隣に戻り、更新の進行状況（確認、ダウンロード、インストール）も再び更新ボタンに表示されます。管理者として実行しているときは、ワークスペース名の後ろの表示が文字に戻ります。
- **カプセルはプラグイン「アクティビティアイランド」に：** 1.4.52 の伸び縮みするカプセルは Breezell に組み込まれなくなり、プラグインマーケットのオープンソースのプラグイン「アクティビティアイランド」になりました。使いたい人は自分でインストールできます。インストールしなければ、タイトルバーはもとのままです。

### アクティビティアイランド プラグイン

- **インストール：** Box ▸ プラグイン ▸ マーケット で「アクティビティアイランド」を探します。Breezell 1.4.53 以降が必要で、それより古いバージョンにはインストールされません。
- **タイトルバーでは：** ふだんはワークスペース名を表示し、クリックすると検索が開きます。AI が作業しているあいだはカプセルが広がり、次のものを表示します：
  - 今のステップ。たとえば「考え中」「app.ts を編集中」「コマンドを実行中」
  - 作業しているモデルのアイコンと経過時間
  - 「確認待ち」「完了」「エラーが発生しました」。「表示」でその会話が開きます。
  - ビルドやテストのタスクの進行状況。失敗したときは「表示」でそのターミナルが開きます。
- **Breezell を離れたとき：** ほかのアプリに切り替えたり Breezell を最小化したりすると、カプセルはタイトルバーから画面上部へ飛んでいき、すべてのアプリの上に浮かびます。何も起きていないときは「すべて順調」と表示されます。Breezell に戻ると、タイトルバーへ飛んで戻ります。
- **パネルを開く：** 画面上部に浮かんでいるカプセルをクリックすると、パネルが広がります：
  - 進行中または確認待ちの会話がいくつあるか、それぞれの会話が今何をしていて、どのくらい実行されているか
  - 「会話を読み取る」を許可すると、それぞれの返信の最後の数文も表示されます。
  - 会話をクリックすると、その会話へ直接移動します。「エディターに戻る」で Breezell に戻ります。
  - パネルの外をクリックするか Esc を押すと閉じます。
- **Breezell のウィンドウが複数あるとき：** 画面上部のアイランドはひとつだけで、すべてのウィンドウをまとめて表示し、あなたの対応が最も必要なものが先頭に並びます。パネルはウィンドウごとにまとめられ、「移動」でそのウィンドウに切り替わります。
- **権限：** ほかのアプリの上に浮かぶことと会話を読み取ることは、どちらも初めて必要になったときに確認されます。浮かぶことを許可しなければ、アイランドはタイトルバーに留まります。会話の読み取りを許可しなければ、パネルには各ウィンドウの AI が何をしているかだけが表示されます。
- **システム：** Windows、macOS（フルスクリーンのアプリの上も含む）、Linux の X11 セッションで浮かべられます。Linux の Wayland セッションではアイランドはタイトルバーに留まり、最初に一度だけそのことが表示されます。
- **設定：** 機能オプション ▸ プラグイン の「アクティビティアイランド」の下で「Breezell を離れたり最小化したりしたとき、アイランドを画面上部で他のアプリの上に浮かべます…」をオフにすると、アイランドは常にタイトルバーに留まります。動きを減らす設定がオンのときは、アニメーションなしでそのまま移動します。

### スーパーメモリー

- **プロジェクトグループ：** エクスプローラーのプロジェクト一覧で、「現在」「すべて」の隣のボタンから「プロジェクトグループとメモリ共有」が開きます。「新しいグループ…」でグループを作成でき、プロジェクトは「グループへ移動」と「グループから外す」で出し入れできます。「グループ名を変更」と「グループを解散」もあります。
- **メモリーの共有：** グループで「メモリを共有」をオンにすると、同じグループのプロジェクトどうしで互いのメモリーを呼び出します。それぞれのメモリーは、引き続きそれを学んだプロジェクトに属します。既定はオフです。
- **メモリーライブラリにソースを表示：** 「メモリーライブラリ」では：
  - 同じグループのほかのプロジェクトから来たメモリーには「プロジェクト名 から」と表示されます。
  - あるメモリーがこのプロジェクトで使ってみて合わなかったときは「このプロジェクトには当てはまらない」と表示されます。もとのプロジェクトでの扱いには影響しません。
  - 共有がオンのときは「すべてのソース」「このプロジェクト」「グループのプロジェクト」で絞り込めます。
- **別のシステムで開いた同じプロジェクト：** 同じプロジェクトを Windows、WSL、Linux、macOS、または SSH 経由で開くと、同じプロジェクトとして認識され、メモリーも一緒についてきます。それぞれの環境で一度開くと有効になります。
- **意味で思い出す（今後提供）：** Box ▸ スーパーメモリー ▸「予算とメンテナンス」に「意味で思い出す」カードが加わりました。言い回しが違うメモリーや、別の言語で書かれたメモリーも見つけられるようにするものです。この機能は次の Breezell の完全インストール版で提供されます。今回のホットアップデートでは何もダウンロードされず、カードには「次の Breezell の完全インストール版で使えるようになります。それまでは言葉だけで呼び出します。」と表示され、呼び出しはこれまでどおり行われます。

### 削除された実験的機能

- **設定の「実験的機能」タブから 5 つの機能が削除されました：**
  - 「メモリー事前分析」と、それに伴う「メモリー分析」タブ
  - 「ヒューマン・イン・ザ・ループ」
  - 「エンタングルメント厳格検証」と「厳格モードのモデル」
  - 「適応型エージェント戦略」
  - 「モデル自動ルーティング」
- **何もする必要はありません：** これらの機能をオンにしていた場合も、会話はいつもどおり進みます。モデルの選択で「Auto」を選んでいた場合は、チャット入力欄で選んだモデルが使われるようになります。

### プラグイン

- **プラグインにできる新しいこと：**
  - タイトルバー中央に独自のページを置き、検索ボックスの代わりにできます。これができるのは一度にひとつのプラグインだけです。
  - ほかのアプリの上に浮かぶ小さなウィンドウを表示できます。
  - AI が今どのステップにいるか、どのモデルを使っているか、ビルドやテストのタスクの進み具合を知ることができます。ただし、メッセージの内容は見えません。
  - 同じプラグインが Breezell の別々のウィンドウで連携できます。たとえば、最後に使ったウィンドウにだけまとめをひとつ表示する、といったことです。
- **新しい権限スイッチが 2 つ：** Box ▸ プラグイン ▸ インストール済み に次のものが加わりました：
  - 「ほかのアプリの上に浮かぶ小さな独自ウィンドウを表示する（キーボード入力は受け取れない）」：初めて使うときに確認されます。
  - 「Agent が何をしているか（現在の手順、扱っているファイル名、モデル、経過時間）とバックグラウンドタスクの進み具合を見る（メッセージの内容は含まない）」：既定でオンで、オフにすることもできます。
- **すでにインストールしたプラグインは影響を受けず**、更新する必要もありません。

## 1.4.52 · ホットアップデート · 2026-11-07

1.4.5 向けのホットアップデートで、再インストールは不要です：Breezell が自動で案内するほか、Box サイドバー下部の「アップデート」で確認することもできます。

### タイトルバー

- **検索ボックスが、今の状態を映すカプセルに：** タイトルバー中央の検索ボックスが、表示する内容に合わせて伸び縮みするカプセルになりました。ふだんはこれまでどおり検索と通知ベルが入っていて、クリックすると検索が開きます。表示される言葉は Breezell の表示言語に従います。
- **AI が何をしているか、ひと目でわかる：** 会話の実行中、カプセルには次のものが表示されます：
  - 作業しているモデルのアイコン
  - 今のステップ：「考え中」「回答を作成中」「app.ts を編集中」「README.md を読み込み中」「コードを検索中」「コマンドを実行中」「ツールを使用中」「サブタスクを待機中」「コンテキストを圧縮中」「再接続中」
  - このターンが始まってからの時間
  - 複数の会話が同時に動いているときは「+2」のような数。開いている会話がその中にあれば、それが優先して表示されます。
  - ステップが続けて素早く変わってもちらつきません。どの文言も少しのあいだ表示されます。
- **確認待ち：** AI があなたの回答や承認を待って止まると、カプセルに「確認待ち」（複数あるときは「3 件の会話が確認待ち」）と表示され、「表示」でその会話が開きます。あなたを待っている会話は、作業中の会話より先に表示されます。
- **完了、またはエラー：** ターンが終わると「完了」と所要時間（「所要 1:23」）が数秒表示されます。エラーで終わったターンは「エラーが発生しました」と表示され、「表示」でその会話が開きます。自分で停止したターンは何も表示されません。
- **ビルドやテストのタスク：** ビルドやテストなど、実行したタスクは「build を実行中」と時間を表示します。終わると「build 完了」と所要時間、失敗したときは「build 失敗」と終了コードを表示し、「表示」でそのターミナルが開きます。バックグラウンドで動き続ける監視タスクは表示されず、自分で停止したタスクも表示されません。
- **AI の作業中に動くタスク：** AI の作業中にタスクが動くと、タスクはカプセル右側の小さな点になります。ポインターを重ねると名前が、クリックするとターミナルが開きます。
- **更新と通知がひとつの場所に：**
  - 新しいバージョンへの更新の進行状況（確認、ダウンロード、インストール）と、更新があるときのボタンが、隣の専用表示ではなくカプセルに表示されるようになりました。
  - 通知ベルはカプセルの端にあり、通知パネルはカプセルから広がり、カプセルへ戻っていきます。動きを減らす設定がオンのときは、パネルはそのまま表示されます。
  - デバッグツールバーが同じ場所にあるあいだは、デバッグのボタンを操作できるよう、カプセルはふだんの状態のままです。
- **管理者として実行しているとき：** ワークスペース名の後ろに盾のアイコンが表示されるようになり、名前を押しのける文字は出なくなりました。
- **キーボード：** 通知ベルで Enter またはスペースを押すと、検索ではなく通知が開きます。カプセル内のボタンも Enter とスペースで操作できます。

### AI によるファイル編集

- **パスが少し違っても「ファイルを読み込めない」で終わらない：** AI が存在しないパスのファイルを編集しようとしたとき（たとえばフォルダーをひとつ書き忘れたとき）、これまでは読み込みエラーだけが返り、エクスプローラーにはファイルがあるのに「開けない」と伝えていました。再起動しか効かないように見えることもよくありました。現在は：
  - AI はそのパスが存在しないことと、ワークスペース内にある同じ名前のファイルを知り、正しいファイルを編集します。
  - その名前のファイルがワークスペースにないときは、ほかのフォルダーを当て推量で探し続けず、ファイルの場所をあなたに尋ねます。
  - 新しいファイルを作るつもりだった場合は、そのまま作成します。
- **Windows：理由なく失敗していた AI の編集が通るように：** Windows では、問題のない AI の編集や新規ファイルが拒否されることがありました。現在は AI が書いたとおりに処理されます。これまでは：
  - 内容が途中で切れたものとして扱われ、AI が編集を小さく分けて何度もやり直し、同じように失敗していました。
  - あるいは、ひとつの呼び出しで別々のファイルを指していると拒否されたり、開けないパスに書き込まれたりしていました。

## 1.4.51 · ホットアップデート · 2026-11-06

1.4.5 向けのホットアップデートで、再インストールは不要です：Breezell が自動で案内するほか、Box サイドバー下部の「アップデート」で確認することもできます。

### チャット

- **スクリーンショットの多い長い会話も続けられます：** 1 つの会話でスクリーンショットを何枚も送ったあと、メッセージが通らなくなることがありました。エラーには `NGHTTP2_ENHANCE_YOUR_CALM` が含まれ、診断はネットワークが原因だと示していました。今は次のとおりです：
  - 以前に貼り付けた画像が、そのあとのメッセージの負担にならなくなったため、会話を続けられます。
  - AI が以前の画像をもう一度見る必要があるときは、記憶から説明するのではなく、その画像を開き直します。
  - メッセージに添付した画像は必ず送られ、編集したメッセージや再送したメッセージの画像も同様です。
- **AI が開いた画像も同様です：** AI が見るために開いた画像は、会話の残りの部分にずっと残らなくなり、必要になったときに開き直します。複数の画像を一度に開いたときは、そのすべてを見ます。
- **表がチャットの幅で折り返します：** 返答内の表は最も長い行の幅になり、横にスクロールする必要がありました。今はチャットの幅で折り返します：
  - 見出しは単語の間でのみ改行され、CJK のラベルは分割されません。
  - 表内のパスや名前が、1 行に 1 文字ずつ押し縮められることはありません。
  - 単語 1 つがチャットの幅より広い場合にのみ、表が横にスクロールします。
- **太字の見出しが上の段落にくっつかなくなりました：** 返答内で独立した行にある太字の見出し（「(2) ...」「(3) ...」など）が直前の段落の末尾にくっつき、文中の太字の語句の前のスペースが消えていました（「this is **important**」が「this isimportant」になっていました）。どちらも修正しました。
- **ストリーミング中も太字の見出しの位置が同じに：** 返答のストリーミング中、独立した行にある太字の見出しは、返答が終わるまで本文から 1 段分離れていました。今はストリーミング中から最終的な間隔になり、思考テキストでも同様です。
- **長い会話でのサッシのドラッグがなめらかに：** 会話が長くなっても、チャットのサイズ変更が遅くならなくなりました。

### Box

- **起動時に Box ページが空白にならなくなりました：** Box ページで Breezell を閉じると、次に開いたときに左のナビゲーションだけが表示され、その横に何もありませんでした。今は閉じたときのページで開きます。

### インターフェース

### アカウントとサインイン

- **サインインが理由もなく切れなくなりました：** アカウントに何の問題もないのにサインアウトされたり、まったくサインインできなかったりする人がいました。今は次のとおりです：
  - ネットワークの切断、ウェブサイトに接続できない、チャレンジページ、プロキシのエラー、複数のウィンドウを開いている、1 台のコンピューターに Breezell が 2 つインストールされている、コンピューターの時計がずれている、といったことでサインアウトされなくなりました。サインアウトされるのは、Breezell が本当にあなたのサインインを終了したときだけです。
  - ウィンドウ間でサインイン状態が一致するため、サインインが失われているのにサインイン中と表示するウィンドウはなくなりました。
  - Box で設定したプロキシが唯一のインターネットへの経路である場合、サインインもそのプロキシを使います。
  - サインインコードを入力したとき、Breezell は、コードが使えなかったのか、このネットワークからの試行が多すぎるのか、Breezell に接続できないのかを区別して伝えます。
  - サインアウトされたときは、その理由を示します：「このデバイスはサインアウトされました」または「サインインの有効期限が切れました」。
- **サインインの期限切れ後も Breezell のモデルが失敗し続けることはなくなりました：** 以前はサインインの期限が切れると、再びサインインするまですべてのメッセージが失敗していました。今は Breezell が自動で続けます。
- **6 台目のデバイスは拒否されるだけ：** 以前は 6 台目のデバイスでアカウント全体が 24 時間ブロックされ、他の 5 台もサインアウトされていました。今は新しいデバイスだけが拒否されます：そのデバイスはサインインページに留まって理由を示し、他の 5 台はそのまま使えます。すべての枠が埋まった状態でスリープから復帰したデバイスは、サインインしたまま待機中であることを示し、枠が空くと自動で続けます。アカウントページでこのことを説明しています。閉じたエディターが、デバイスの枠を何時間も占有することもなくなりました。

  - 待機行の「スキップ」でそのまま続行します。回答後に停止または新しいメッセージを送ると、チェックだけが終了します。

### メモリ

- **文脈で、どの言語でも呼び出せます：** メモリは、あなたの依頼、その前の会話、開いているファイルを読む小さなローカルモデルが選ぶようになりました。キーワードや固定の単語リストは廃止されました。タイ語、ヒンディー語、韓国語、アクセント付きのラテン文字を含むどの言語でも機能し、会話にも追随します。何も名指ししない短い追撃でも、その会話が扱っているメモリを見つけます。古いメモリや休眠中のメモリにも公平な機会があり、ターンが明確に必要とするとき休眠中のメモリは目を覚まします。学習していないテストセット（10 言語）で、メモリを必要としたターンがメモリを得た割合は 41% から 62% に上がりました。
- **AI はメモリを段階的に調べられます：** `memories_recall` は索引（種類、優先度、状態、日付、一致の仕方）を一覧し、つながりを含む完全な記録を開き、AI が結果を絞り込めます：正確なテキスト、日付、種類、優先度、またはクエリの別の言い方で。Super Memory プランは不要になり、検索時に古いメモリが古さで押し下げられることもなくなりました。チャットカードは開かれたすべての記録を表示します。
- **メモリの状態がより明確に：** チャットは、メモリの呼び出しが実行中であること、そのターンでメモリを使わなかったこと、関連するメモリがすでにこの会話の前の方にあることを示します。大きなライブラリでも呼び出しでウィンドウが固まらなくなりました。後のメモリが誤りだと示したメモリは保持され、置き換えたものへのリンク付きで「無効」と印が付き、二度と渡されません。メモリとして見える内容にツール名は現れません。

### ネットワークと信頼性

- **VPN の変化後も軌道に戻ります：** VPN やプロキシクライアントが切れて戻ると、リクエストが死んだ接続のまま数分待つことがありました。失敗したリクエストがあると、次は新しい接続を開き、システムプロキシを読み直します。
- **遅い回答が約 2 分で失敗しなくなりました：** Breezell のモデルでは、最初の一言まで数分考えるモデルや、2 分以上かかる画像が 524 エラーで失敗していました。接続は開いたまま保たれ、待ち時間はエディターが決めます。
- **設定でき、学習する first-byte タイムアウト：** Box ▸ ネットワークとチャット ▸ First-byte timeout：40（既定）、60、90、120、180 秒、または 20〜240。その上限内で、待ち時間は各モデル自身の最近の first byte に適応するため、固まったリクエストはより早く再試行されます（10 秒ではなく 2 秒ごとに確認）。ネットワーク健全性の一覧は、各リクエストが再試行された理由（例：「retry #1 after no first byte」）と first-byte の待ち時間を表示します。
- **チャットリクエストに HTTP/2：** チャットのリクエストは既定で HTTP/2 を使い、直接接続でも HTTP・HTTPS・SOCKS プロキシ経由でも同様です。Box ▸ ネットワークとチャット で HTTP/1.1 に戻せます。応答前に HTTP/2 接続を閉じたサーバーには、リクエストが再送されます。
- **再試行の規則を一か所に：** すべてのプロバイダーが同じ再試行規則に従います。あなたの停止後、クォータ切れ、拒否されたリクエスト、すでに見えているテキストのあとには再試行しません。「terminated」で切れたストリームは接続断として再試行されます。エラー文の「451」は地域ブロックと見なされなくなりました。

### チャット

- **新しい DarkSelene モード：** 入力欄の下のモードメニューで DarkSelene（「何かを作る前に、あなたの質問を分解します」）を選択します。何かを変更する前に、難解な質問や誤解されやすい質問を最後まで考え抜きます。非常に多くのトークンを消費するため、慎重に使ってください。
  - ステップ 1 · 作る前に理解する：質問を分解し、コードを調査し、疑問を投げかけ、検証し、可能性を導き出します。調査の前に「先読み」を書き出します。答えや完成した変更がどうなるべきか、そして何がそれを誤りだと証明するかです。調査はその点だけを確認します。コードが先読みをすぐに裏付けた場合、疑問と検証は省略されます。
  - 証拠で決着：コードやあなたの依頼で答えられる質問は、すべて DarkSelene 自身が答えます。あなたにしか決められないことだけが「あなたの見解」として尋ねられます。質問には 1 つずつ答えるか、「推奨で進む」を押します。
  - ステップ 2 · 実行とレビュー：用意したタスクはあなたのメッセージとして送信され、Agent が実行します。Agent の予期しない読み取りとすべての編集は、独立したレビュアーが証拠と照合して確認し（読み取りレビュー、コードレビュー）、その指摘は Agent が続行する前に返されます。
  - DarkSelene の最終要約には、レビューと確認で実際に裏付けられた内容だけが残ります。
- **バックグラウンドコマンドの完了を AI が受け取るようになりました：** 待機時間を超えてバックグラウンドに移ったコマンドは、以前はあなたが次のメッセージを送るまで報告されませんでした。現在は次のように動作します。
  - コマンドが終わるとすぐに、ターミナルカードが結果で更新されます。
  - AI がまだ応答している間は、次のステップで結果を受け取り、同じターンで処理します。失敗を修正するか、その結果を待っていた作業を続けます。
  - AI の応答がすでに終わっている場合は、コマンド終了の約 1.5 秒後に自動で新しいターンが始まり、1〜2 文で結果を報告します。ほぼ同時に終わった複数のコマンドでも、ターンは 1 つだけ始まります。
  - 自分で停止したコマンド（停止の丸印または Ctrl+C）、AI があなたの承認や回答を待っている間、停止を押した直後は、ターンは始まりません。
- **送信済みメッセージを編集して再送すると、元のメッセージが取り消されるようになりました：** 以前は誤字を直してもテキストが置き換わるだけでした。その誤字のせいで AI が変更したファイルや、そのターンから取ったメモリは残っていたため、AI はしばしば間違った方向に進み続けました。現在は編集して再送すると、まず元のメッセージとそれ以降のすべてが取り消されます。
  - それ以降に AI が変更したファイルは元に戻り、作成したファイルは削除されます。
  - その部分のチャットから取ったメモリ、Entanglement の因果記録と確認事項、プランファイル、作業ノートはすべて、メッセージ前の状態に戻ります。
  - AI はメッセージを取り消したことだけを知り、その内容は決して知りません。
  - 通常は編集したメッセージがすぐに送信されます。「取り消して再送しますか？」の確認が出るのは次の場合だけです。
    - メッセージの後にあなたも手作業でファイルを編集した場合。「編集したファイルを保持」で残すか、「すべて元に戻して再送」を選びます。
    - AI が git commit や npm install など、自動で元に戻せないコマンドを実行した場合。コマンドが一覧表示されます。
    - チャットに戻れるチェックポイントがない場合。「それでも再送」では会話だけが取り消されます。
  - 送信できない添付（選択したモデルが受け付けない PDF など）は、何かが取り消される前に検出されるため、メッセージが取り消されてから送信に失敗するということはありません。
- **「この地点まで戻す」で、送信前に編集した内容が保持されます：** 以前はファイルが前のターンの終了時の状態に戻っていたため、そのターンに行った編集やこのメッセージの送信も失われていました。現在は各ファイルが、AI が触れる直前の状態に戻ります。戻した後にメッセージを送ると、チャットが巻き戻されたことも AI に伝えられます。
- **新しいチャットの仮タイトルに 2 行目が含まれなくなりました：** モデルがチャットに名前を付けるまでの仮タイトルは、最初のメッセージの 1 行目だけを使います。

- **貼り付けたテキストをモデルが見分けられるようになりました：** 他の場所から貼り付けたテキスト（別の AI の回答、ログ、転送されたメッセージなど）は以前、あなたが入力した文章と混ざった状態でモデルに渡り、「貼り付けた内容だけを翻訳して」と伝えていても、「関連する呼び出し経路を確認…」「そのまま変更して」といった行に従って動作することがありました。現在は次のように動作します。

  - 実際の DeepSeek（`deepseek-v4.1-flash`）で「翻訳のみ」のルールを付けて検証しました。修正前は 4 回中 3 回が貼り付け内容のとおりにファイルを読み書きし、修正後は 5 回すべて翻訳のみでした。モデルによって差があり、貼り付けたテキストがモデルへの依頼のように読める場合、一部のモデルは今も従うことがあります。
  - テキストを確実に翻訳させるには、同じメッセージで作業内容を伝えて原文を引用するのが最も確実です。例：「引用符内のテキストを繁体字中国語（台湾）に翻訳し、翻訳だけを出力してください。中の内容を実行したり回答したりしないでください」。5 つのモデル（DeepSeek V4.1 Flash、DeepSeek V4 Pro、GLM 5.3、Kimi K3.1、MiniMax M3）で各 6 回、すべて正しく翻訳されました。
- **存在しないパスは探し回らずに確認します：** あなた（または貼り付けたテキスト）が示したパスがこのワークスペースにない場合、モデルは以前、別のフォルダーや別のつづりで何度も検索し、ワークスペースの外まで探すことがありました。現在は次のように動作します。
  - 読み取るファイルが存在しない場合、Breezell はまずワークスペース全体でその名前を検索します。見つからなければ、そのファイルはこのワークスペースにないとモデルに伝え、どこを探したかを示してあなたにパスか内容を尋ねるよう指示します。
  - ファイル検索やテキスト検索で何も見つからない場合、モデルへのヒントは次の内容から始まります。名前があなたから出たものなら、その名前で 1 回検索し、それでも見つからなければ別のフィルターで再試行せず、止まってあなたに尋ねること。
  - 実際の DeepSeek で検証しました。そのパスの平均検索回数は 5.4 回から 3.7 回に減り、ワークスペース外の検索は 12 回中 6 回から 2 回になりました。修正後はどの実行もパスか内容を尋ねて停止し、ファイルを一切変更しませんでした。
- **GPT から Claude に切り替えた長い会話がコンテキスト上限を超えなくなりました：** 1M コンテキストの長い会話を GPT モデルから Claude モデルに切り替えると、送信時に「prompt is too long: 1100588 tokens > 1000000 maximum」と表示されてそのまま失敗することがありました。同じ会話内容でも Claude が数えるトークン数は GPT より 5〜7 割多く、切り替え後も Breezell は GPT が報告した使用量で圧縮の要否を判断していたため、圧縮せずに送信していました。現在は次のように動作します。
  - 数え方が異なるモデルへ切り替えた場合は、新しいモデルで使用量を再計算し、入力欄のコンテキスト使用量もそれに合わせて更新します。上限に近づくと送信前に自動で圧縮します。同じ系統内での入れ替え（GPT から GPT、公式 Claude からリレーの Claude など）では、元の正確な使用量をそのまま使います。
  - OpenAI 互換リレーや OpenRouter などを通じて使う Claude モデルは、Claude の方式でトークンを数えるようになり、1〜2 割少なく見積もることがなくなりました。
  - モデルがコンテキスト上限超過を報告した場合、自動圧縮は必ず古い内容を先に畳み込んでから再試行します。以前はすでに圧縮済みの長い会話で何も畳み込まずにそのまま再送してしまい、また失敗することがありました。
- **停止した後や応答の途中で新しいメッセージを送った後、モデルは前の応答が未完了だと分かります：** 以前は応答が中断されてもモデルには分からず、途中までの作業を引き続き行うべきものと捉えたり、一言の補足をタスク全体と解釈したりすることがありました。現在は次のように動作します。
  - 入力欄の停止ボタン（四角いアイコン）または Esc を押してからメッセージを送ると、モデルはあなたが意図的に止めたと認識します。続行を求めたり、その作業への追加や修正があったりしない限り、作業を続けず、自分から話題にすることもありません。
  - 応答の実行中にキューで「すぐに送信」を押した場合、新しいメッセージが直前の作業への追加や修正（例：「別途、電話番号は読み取り専用にして」「続けて」）であれば、その変更を反映して作業を完了します。別の用件であれば新しい用件だけを行い、前の応答が未完了であることに最大 1 文で触れます。
  - 同じファイルやページに触れているだけの新しい依頼は、以前の作業を続ける指示としては扱われません。

### メモリ

- **メモリファイルが検索結果に出なくなりました：** メモリファイル（プロジェクト内の `.breezell/memories/workspace_memories.md` とホームフォルダーの `global_memories.md`）は、書かれた時点の状況を記したメモです。コード検索では以前、コードと一緒に返されていたため、モデルがずっと古い記述を現在の仕様と誤認し、あなたが直前に依頼した内容を取り消すことがありました。現在は次のように動作します。
  - テキスト検索、シンボル検索、ファイル名検索は、無視対象のファイルを含めるよう指定しても、この 2 つのメモリファイルを返しません。同じフォルダーのルールファイル（`global_rules.md`、`global_skills.md` など）と `.breezell/` 配下のその他のファイルは従来どおり検索され、時点付きのメモとしては扱われません。
  - モデルがメモリファイルを直接開いた場合は、記載が古くなっている可能性のある時点付きメモであると伝えられます。最新の依頼と現在のコードが優先され、モデルは食い違いを指摘し、その項目を更新するか尋ねます。
  - モデルはメモリを「この日時点の状況」として条件付きで書き、恒久的な規則としては書きません。自身の変更で項目が誤りになった場合は、同じターンでその項目を更新または削除します。
- **会話から抽出されたメモリは、その会話に注入されなくなりました：** 「メモリ N 件を注入（… 常駐 · … 関連）」の関連メモリに、現在の会話から抽出されたメモリが含まれなくなりました。その内容は会話内に順序付きですでに存在し、メモリとして再注入されると恒久的な規則のように読めて、モデルを以前の依頼へ引き戻したり、他の会話のメモリの枠を奪ったりしていました。他の会話ではこれらのメモリは従来どおり使われ、ご自身で保存したメモリは影響を受けません。メモリとコードが食い違う場合、モデルは依頼していないコードを変更せず、その点を指摘するようになりました。

### エディター

- **「N 個のファイルを変更」バーの「次へ →」が反応しませんでした：** AI がファイルを編集すると、エディター下部に「9 個のファイルを変更」と「次へ →」が表示されます。その一覧の最初のファイルが開けなくなっている場合（後から削除・名前変更された、または以前のセッションの変更が残っている）、「次へ →」は何も反応しませんでした。開いているファイルが一覧にないため、クリックするたびに同じファイルを再試行し、ボタンが機能しなかったのです。現在は次のように動作します。
  - 開けないファイルは飛ばし、開ける次の変更済みファイルへ移動します。以下も同様です。
    - バーの左右の矢印（前／次のファイル）
    - ショートカット Ctrl+Alt+Shift+→／←（Mac：Ctrl+Option+→／←）
  - 一覧のどのファイルも開けない場合は、理由が通知で表示されます。
  - フォーカスがエディターにない場合（別のパネルをクリックした直後など）でもボタンが機能します。
  - リモートワークスペース（SSH、WSL）に残った変更が、Breezell の再起動後に開けないローカルパスとして戻ることがなくなりました。

### Entanglement モード

- **「ヒューマンインザループモード」がツール指定を受け付けないモデルで止まらなくなりました：** 「Entanglement モードの厳格な検証」の「ヒューマンインザループモード」を有効にすると、Breezell はモデルに質問パネルで要件を確認するよう求めます。これに対応できないモデルがあります。GLM は要求を無視してテキストで回答し、その応答はエラー（AI_ToolChoiceViolationError）として破棄され、エラーカードはネットワークの問題だと表示していました。Kimi と DeepSeek V4 は思考を有効にしていると、この要求をそのまま拒否します（HTTP 400）。確認が完了せず、以降のメッセージも同じように失敗し続けていました。現在は次のように動作します。
  - モデルが質問パネルを使わずテキストで回答した場合、その応答は保持されます。
  - モデルが拒否した場合は、ツールを指定せずに再送します。
  - Breezell はそのモデルを記憶し、以後は質問パネルを使うよう求めません。
  - モデルは応答内で質問するようになり、行には「このモデルは質問パネルを使えないため、応答内で質問します。次のメッセージが回答になります」と表示されます。回答すると「会話内で理解を確認しました」と表示され、確認が完了してツールが解放されます。
  - エラーカードは、指定したツールをモデルが呼び出さなかったことを正しく示し、ネットワークの問題とは表示しません。

## 1.1.5 · 2026-05-24

### 新機能

- **チャットの引用とコピー**：チャットでテキストを選択すると、リスト、コードブロック、ファイル名タグを保持したまま Markdown 引用にすばやく変換したり、直接コピーしたりできます。
- **バックグラウンドコマンドの自動通知**：長時間実行されるターミナルタスクの完了時に通知を自動送信し、進捗を何度も確認する必要をなくしました。
- **数式のレンダリング**：チャットで $x^2$ や $...$ を含む LaTeX 数式を正しく表示できるようになりました。
- **エラー表示の再設計**：エラーメッセージを展開可能なカードで表示し、完全なエラー内容をワンクリックでコピーできます。
- **SSH リモート開発の完全サポート**：リモート SSH ホストでのすべてのツール呼び出しを完全にサポートしました。
- **ストリーミング停止の診断**：ストリーミング応答が停止したとき、上流の遅延やネットワークバッファリングなどの原因を詳細に示します。
- **モデルコンテキスト使用量バー**：モデルセレクターで現在のセッションのトークン使用量をカテゴリ別に確認できます。
- **「デフォルトモデル」ラベル**：モデルセレクターでデフォルトモデルを明確に識別できるようになりました。
- **長期メモリパネルのアップグレード**：「たった今」「今日」「今週」などの時間タグ、すりガラス風のスタイル、メモリリコールカードを追加しました。
- **ストリーミング中のプランタイトル表示**：モデルがプランを生成すると、ストリーミング出力中にプランタイトルを表示します。
- **永続エラーの自動リトライ省略**：認証失敗などの永続エラーに対して、意味のない自動リトライを行わなくなりました。
- **新しいモデルのサポート**：Gemini 3.5、Qwen 3.7 などのモデルをサポートしました。
- **ロシア語インターフェースのサポート**。
- **チャットツールカードの展開**：検索結果やファイル読み取りなどのツール出力を折りたたみ・展開できるようになりました。

### 修正

- ストリーミング応答のタイムアウトを120秒から180秒に延長し、推論が遅いモデル向けに中間 UI プロンプトを追加しました。
- 設定ページのドロップダウンメニューのレイヤー問題を修正し、サードパーティプロバイダーのメニューが隠れないようにしました。
- `[object Object]` のエラー表示問題を修正しました。
- エラードロワーのコピー機能が動作しない問題を修正しました。
- ファイルパスのプロンプトボックスがフリーズし、スクロールしても残る問題を修正しました。
- チャットのテキスト選択カラースキームを最適化し、壊れていたスタイル変数を修正しました。
- モデルセレクターのスクロール貫通を修正し、モデルメニューをスクロールしても下のチャット領域がスクロールしないようにしました。
- 思考モードのスキーマ互換性を修正し、Claude プロトコルでの推論パラメーター互換性を改善しました。
- 複数ファイルのストリーミングプレビューを最適化し、リアルタイムの「N 件の変更」表示が遅れないようにしました。
- スクロール、間隔、配置、アニメーション、ツールチップなど、多数の UI 細部を修正しました。

### 最適化

- **基盤技術スタックのアップグレード**：Electron を 42.2.0 に更新し、Chromium 148、Node.js 24、V8 14.8 を含めました。
- **メモリ管理の最適化**：大きなチャット履歴を自動的にディスクへ書き込み、推論記録を必要に応じて整理して、長い会話を軽量に保ちます。
- **Mermaid チャートレンダリングの強化**：キャッシュ管理を改善し、アンロード時に SVG を積極的にクリーンアップして、長いチャット中のメモリ蓄積を防ぎます。
