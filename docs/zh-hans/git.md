# Git

Breezell 1.4.59 加入了一套 IntelliJ IDEA 风格的 Git：勾选要提交的文件，甚至只提交文件的一部分；AI 对话改过的文件按对话分组；查看分支图、搁置更改、推送前先看要推送哪些提交、交互式 Rebase，还有一个能检出、比较、合并分支的分支菜单。在 [Agents 页面](/zh-hans/agents-page) 和 IDE 里都能用。

| 名词 | 意思 |
| --- | --- |
| 勾选 | 放进下次提交。没勾选的更改留在工作区，不会被提交。 |
| 分块 | 文件里一段连续的修改。可以只勾选其中几块。 |
| 搁置 | 先把更改收起来，让工作区回到干净的状态，之后再取回。 |
| 上游 | 当前分支跟踪的远程分支，例如 `origin/main`。 |

## 怎么打开 {#open}

- **Agents 页**：左侧列表上方的 **Git**，旁边的数字是这个项目有几个文件有更改。点一下会在页面中间打开 Git；点左上角的箭头（**回到对话**）或按 `Esc` 回到对话。
- **IDE**：在命令面板（`Ctrl+Shift+P`）执行 `Git: Commit…`、`Git: Push…`、`Git: Update Project`、`Git: Show Log`、`Git: Show Shelf` 或 `Git: Branches…`，会打开一个名为 **Git** 的标签页，内容和 Agents 页的 Git 一样。
- 不论在哪一页，按 `` Alt+` `` 都会打开 **Git 操作** 菜单：**提交…**、**推送…**、**更新项目**、**分支…**、**日志**、**搁置区**、**获取**。

## 显示哪个项目 {#project}

- Git 跟着你正在看的对话：看这个窗口的项目的对话时，是它的仓库；看其他项目的对话时，是那个项目的仓库，上方会显示项目名称（提示文字““*项目名称*”的 Git，来自它的窗口”）。WSL 和 SSH 项目也一样。
- 那个项目没有开着窗口时，Breezell 会在后台开一个，你看不到它；页面会先显示“正在连接“*项目名称*”的窗口…”。
- 一个项目里有好几个仓库时，点仓库名称（**切换仓库**）选一个。
- 还不是 Git 仓库的文件夹，会显示“这个项目还不是 Git 仓库。”和 **初始化仓库** 按钮。

上方一行从左到右是：

- 分支名称：打开[分支菜单](#branches)。旁边的同步状态和 IDE 状态栏上的一样，点它的效果也一样。
- **更新项目**（向下的箭头）：见[更新项目](#update)。
- **推送…**（向上的箭头）：见[推送](#push)。
- **更多 Git 操作**（⋯）：和 IDE 源代码管理的“⋯”菜单一样，例如拉取、远程、标签和工作树。

下面有三个标签页：**提交**（旁边是更改的数量）、**日志**、**搁置区**。

## 提交 {#commit}

### 勾选要提交的内容 {#check}

- 每个文件前面有勾选框：勾选是 **勾选：加入下次提交**，取消是 **取消勾选：不放入下次提交**。分组标题上的勾选框一次勾选或取消整组；只勾了一部分时，它会显示一条横线。
- 只想提交文件的一部分：点文件名前的箭头（**显示分块（只提交文件的一部分）**），再逐块勾选（**勾选这一块：加入下次提交**）。新文件、删除的文件和二进制文件没有分块，只能整个文件一起勾选。
- 点文件名会打开这个文件的更改：在 Agents 页开在页面右侧，在 IDE 开在编辑区。
- 在文件上点右键，除了 IDE 原有的文件操作（例如放弃更改），还有 **搁置…** 和 **显示历史**（在日志里只看这个文件的提交）。

### 分组 {#changelists}

- **“Agent · *对话标题*”**：AI 对话改过的文件，按对话分成一组一组。同一个文件被好几个对话改过时，放在最近的那一组。这样你可以一次只提交某个对话做的事。
- **更改**：其他改过的文件。
- **未纳入版本控制的文件**：Git 还没跟踪的新文件，默认收起来。

### 写信息和提交 {#message}

- 在 **提交信息** 输入框写好信息，点 **提交**（`Ctrl+Enter`，macOS 是 `Cmd+Enter`）。**提交并推送…** 会在提交后打开[推送](#push)。
- 输入框旁的两个按钮：**提交信息历史**（选一条以前用过的信息）和 **用 AI 写提交信息（根据勾选的更改）**。
- **修改上次提交**：勾选后，勾选的更改会加进上一个提交，不另外创建新提交；输入框会带入那个提交的信息。
- **搁置更改…**：把勾选的文件（没有勾选时是全部更改）收进[搁置区](#shelf)。
- **让 AI 审查勾选的更改**：开一个新对话，输入框里已经写好审查的请求，你看过再发送。AI 只会指出问题，不会修改文件。

### 合并冲突 {#conflicts}

合并、Rebase、Cherry-Pick 或还原遇到冲突时，**提交** 标签页最上面会出现 **合并冲突** 和冲突文件的数量：

- 每个冲突文件旁有 **解决…**，会打开合并编辑器。其他项目的文件要到它的窗口解决（**到它的窗口解决…**）。
- **让 AI 解决冲突**：开一个新对话，请 AI 保留两边应该保留的改动并删除冲突标记。它不会自己提交，也不会继续合并或 Rebase。
- 全部解决后点 **继续**。Rebase 和 Cherry-Pick 还可以 **跳过** 当前这个提交；**中止** 会回到开始之前的状态。

## 日志 {#log}

- 列出提交和分支图，往下滚动会继续加载更早的提交。
- 上方可以筛选：**文字或哈希**、**作者**、**路径**，以及要看哪个分支的历史（**看哪个分支的历史**）：**所有分支**、**当前分支** 或某一个分支。
- 点一个提交，旁边会显示它的详情和改过的文件；点文件看那次的更改。**与本地比较** 会改成列出这个提交和当前工作区不同的文件。

在提交上点右键：

| 项目 | 作用 |
| --- | --- |
| **复制修订版本号** | 复制这个提交的哈希。 |
| **检出这个修订版本** | 检出这个提交（不在任何分支上）。 |
| **从这里新建分支…**、**在这里新建标签…** | 以这个提交为起点创建分支或标签。 |
| **拣选（Cherry-Pick）** | 把这个提交的改动应用到当前分支。 |
| **还原提交** | 新增一个提交，抵消这个提交的改动。 |
| **将当前分支重置到这里** | **Soft：保留更改并勾选**、**Mixed：保留更改，不勾选**、**Hard：丢弃更改**（会再问一次）。 |
| **撤销提交** | 只有当前分支最新的提交才有：拿掉这个提交，它的更改放回并勾选，信息放回输入框。 |
| **编辑提交信息…**、**删除提交…** | 用[交互式 Rebase](#rebase) 改这个提交的信息，或把它拿掉。 |
| **从这里交互式变基…** | 见[交互式 Rebase](#rebase)。 |

从[分支菜单](#branches)选“与当前分支比较”时，日志只列出那个分支有、当前分支没有的提交（在“*分支*”、不在“*当前分支*”）；点 **回到分支** 回到一般的日志。

### 交互式 Rebase {#rebase}

- 在日志选 **从这里交互式变基…**，会列出从那个提交到最新的所有提交。
- 每个提交选一种做法：**保留（Pick）**、**改信息（Reword）**、**压缩（Squash）**、**修正（Fixup）** 或 **删除**；用 **上移**、**下移** 调整顺序。改信息和压缩可以直接写 **新的信息** 或 **压缩后提交的信息**。
- 点 **开始变基**。还没提交的更改会先收起来，完成后放回。遇到冲突时照[合并冲突](#conflicts)处理。

## 搁置区 {#shelf}

- 列出搁置的更改和它们的文件。
- **取回**：放回工作区，并从搁置区移除。
- **应用并留在搁置区**：放回工作区，搁置区仍保留一份。
- **删除**：丢掉这份搁置的更改（会再问一次，删掉的更改会丢失）。

## 推送 {#push}

- **推送…** 会先列出要推送的提交。当前分支还没有远程分支时，会标示 **新分支**。
- 远程有这里没有的提交时会先提醒，因为推送可能会被拒绝；可以先点 **更新项目**。
- 选项：**推送标签**，以及 **强制推送（with lease）**：只有远程还停在你上次看到的位置时才会强制推送，不会盖掉别人刚推上去的提交。
- 没有要推送的提交时，会显示“没有要推送的提交，分支和远程一致。”

## 分支菜单 {#branches}

点上方的分支名称，或执行 `Git: Branches…`、在 **Git 操作** 菜单选 **分支…**，就会打开分支菜单：

- 最上面是常用的操作：**更新项目**、**提交…**、**推送…**、**新建分支…**、**检出标签或修订版本…**。
- 接着分成 **最近**、**本地**、**远程**。本地分支旁的星号可以 **加入收藏**，收藏的会排在本地分支的最前面。
- 分支后面会标出和远程的差距（↑ 是还没推送的提交，↓ 是还没拉取的提交）；远程分支被删掉时标示 **上游已删除**。

选一个分支，会列出可以做的事：

- **检出**：远程分支会创建一个同名的本地分支并检出。
- **从“*分支*”新建分支…**、**检出并变基到“*当前分支*”**、**与“*当前分支*”比较**、**显示“*分支*”与工作区的差异**。
- **将“*当前分支*”变基到“*分支*”**、**将“*分支*”合并到“*当前分支*”**。
- **重命名…**、**删除**；远程分支则是 **从远程删除**。删除还没完全合并的分支时，会再问一次。

检出会覆盖你在本地的更改时，Breezell 会问要不要用 **智能检出**：先把更改搁置，检出后再取回。

## 更新项目 {#update}

**更新项目** 会先获取，再把当前分支更新到它的上游；你还没提交的更改会先收起来，完成后放回。完成时会显示“已更新：拉入 N 个提交。”或“已是最新。”

默认用合并的方式更新。想改用 Rebase，在设置里搜索 `breezell.git`，把 Update Method 改成 rebase（这个设置的文字是英文）。

## IDE 的快捷键 {#keys}

想用 IntelliJ IDEA 的 Git 快捷键，在设置里搜索 `breezell.git`，勾选 Idea Keymap（默认不勾选）：

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+K` | 提交 |
| `Ctrl+Shift+K` | 推送 |
| `Ctrl+T` | 更新项目 |
| `Alt+9` | 日志 |
| `Alt+0` | 提交 |

macOS 上用 `Cmd` 取代 `Ctrl`，日志和提交是 `Cmd+9`、`Cmd+0`，**Git 操作** 菜单是 `Ctrl+V`。打开这些快捷键后，会取代 IDE 原有的以 `Ctrl+K` 开头的组合键和 `Ctrl+T`。`` Alt+` `` 不需要这个设置，一直都能用。

## 目前的限制 {#limits}

- 很大的文件和二进制文件不显示更改内容；太大的文件不能分块，只能整个文件一起勾选。
- 更改的文件很多时，只列出一部分，其余的会说明数量，完整列表在 IDE 的源代码管理。
- 范围内有合并提交时，不能交互式 Rebase；第一个提交不能压缩或修正到前一个提交，也不能撤销。
- 其他项目的 Git 要通过那个项目的窗口。那个窗口关掉时，会显示““*项目名称*”的窗口已经关闭。”，点 **重试** 再连一次。
- Git 以外的源代码管理只有简单的视图：**提交信息**、**提交** 和更改列表。
