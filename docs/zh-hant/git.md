# Git

Breezell 1.4.59 加入一套 IntelliJ IDEA 風格的 Git：勾選要提交的檔案，甚至只提交檔案的一部分；AI 對話改過的檔案按對話分組；看分支圖、擱置變更、推送前先看要推送哪些提交、互動式 Rebase，還有一個能簽出、比較、合併分支的分支選單。在 [Agents 頁面](/zh-hant/agents-page) 和 IDE 裡都能用。

| 名詞 | 意思 |
| --- | --- |
| 勾選 | 放進下次提交。沒勾選的變更留在工作區，不會被提交。 |
| 分段 | 檔案裡一段連續的修改。可以只勾選其中幾段。 |
| 擱置 | 先把變更收起來，工作區回到乾淨的狀態，之後再取回。 |
| 上游 | 目前分支追蹤的遠端分支，例如 `origin/main`。 |

## 怎麼打開 {#open}

- **Agents 頁**：左側清單上方的 **Git**，旁邊的數字是這個專案有幾個檔案變更。點一下會在頁面中間打開 Git；按左上角的箭頭（**回到對話**）或 `Esc` 回到對話。
- **IDE**：在命令選擇區（`Ctrl+Shift+P`）執行 `Git: Commit…`、`Git: Push…`、`Git: Update Project`、`Git: Show Log`、`Git: Show Shelf` 或 `Git: Branches…`，會打開一個名為 **Git** 的分頁，內容和 Agents 頁的 Git 一樣。
- 不論在哪一頁，按 `` Alt+` `` 都會打開 **Git 操作** 選單：**提交…**、**推送…**、**更新專案**、**分支…**、**日誌**、**擱置區**、**擷取**。

## 顯示哪個專案 {#project}

- Git 跟著你正在看的對話：看這個視窗的專案的對話時，是它的儲存庫；看其他專案的對話時，是那個專案的儲存庫，上方會顯示專案名稱（提示文字「「專案名稱」的 Git，來自它的視窗」）。WSL 和 SSH 專案也一樣。
- 那個專案沒有開著視窗時，Breezell 會在背景開一個，你看不到它；畫面會先顯示「正在連到「專案名稱」的視窗…」。
- 一個專案裡有好幾個儲存庫時，按儲存庫名稱（**切換儲存庫**）選一個。
- 還不是 Git 儲存庫的資料夾，會顯示「這個專案還不是 Git 儲存庫。」和 **初始化儲存庫** 按鈕。

上方一列從左到右是：

- 分支名稱：打開[分支選單](#branches)。旁邊的同步狀態和 IDE 狀態列上的一樣，點它的效果也一樣。
- **更新專案**（向下的箭頭）：見[更新專案](#update)。
- **推送…**（向上的箭頭）：見[推送](#push)。
- **更多 Git 操作**（⋯）：和 IDE 原始檔控制的「⋯」選單一樣，例如拉取、遠端、標籤和工作樹。

下面有三個分頁：**提交**（旁邊是變更的數量）、**日誌**、**擱置區**。

## 提交 {#commit}

### 勾選要提交的內容 {#check}

- 每個檔案前面有勾選框：勾選是 **勾選：加入下次提交**，取消是 **取消勾選：不放入下次提交**。分組標題上的勾選框一次勾選或取消整組；只勾了一部分時，它會顯示一條橫線。
- 只想提交檔案的一部分：按檔名前的箭頭（**顯示分段（只提交檔案的一部分）**），再逐段勾選（**勾選這一段：加入下次提交**）。新檔、刪除的檔案和二進位檔沒有分段，只能整個檔案一起勾選。
- 點檔名會打開這個檔案的變更：在 Agents 頁開在頁面右側，在 IDE 開在編輯區。
- 在檔案上按右鍵，除了 IDE 原本的檔案操作（例如捨棄變更），還有 **擱置…** 和 **顯示歷史**（在日誌裡只看這個檔案的提交）。

### 分組 {#changelists}

- **Agent · 對話標題**：AI 對話改過的檔案，按對話分成一組一組。同一個檔案被好幾個對話改過時，放在最近的那一組。這樣你可以一次只提交某個對話做的事。
- **變更**：其他改過的檔案。
- **未納入版本控制的檔案**：Git 還沒追蹤的新檔，預設收起來。

### 寫訊息和提交 {#message}

- 在 **提交訊息** 輸入框寫好訊息，按 **提交**（`Ctrl+Enter`，macOS 是 `Cmd+Enter`）。**提交並推送…** 會在提交後打開[推送](#push)。
- 輸入框旁的兩個按鈕：**提交訊息歷史**（選一則以前用過的訊息）和 **用 AI 寫提交訊息（依勾選的變更）**。
- **修改上次提交**：勾選後，勾選的變更會加進上一個提交，不另外建立新提交；輸入框會帶入那個提交的訊息。
- **擱置變更…**：把勾選的檔案（沒有勾選時是全部變更）收進[擱置區](#shelf)。
- **讓 AI 審查勾選的變更**：開一個新對話，輸入框裡已經寫好審查的請求，你看過再送出。AI 只會指出問題，不會修改檔案。

### 合併衝突 {#conflicts}

合併、Rebase、Cherry-Pick 或還原遇到衝突時，**提交** 分頁最上面會出現 **合併衝突** 和衝突檔案的數量：

- 每個衝突檔案旁有 **解決…**，會打開合併編輯器。其他專案的檔案要到它的視窗解決（**到它的視窗解決…**）。
- **讓 AI 解決衝突**：開一個新對話，請 AI 保留兩邊應該保留的改動並移除衝突標記。它不會自己提交，也不會繼續合併或 Rebase。
- 全部解決後按 **繼續**。Rebase 和 Cherry-Pick 還可以 **略過** 目前這個提交；**中止** 會回到開始之前的狀態。

## 日誌 {#log}

- 列出提交和分支圖，往下捲會繼續載入更早的提交。
- 上方可以篩選：**文字或雜湊**、**作者**、**路徑**，以及要看哪個分支的歷史（**看哪個分支的歷史**）：**所有分支**、**目前分支** 或某一個分支。
- 點一個提交，旁邊會顯示它的詳情和改過的檔案；點檔案看那次的變更。**與本機比較** 會改成列出這個提交和目前工作區不同的檔案。

在提交上按右鍵：

| 項目 | 作用 |
| --- | --- |
| **複製修訂版本號** | 複製這個提交的雜湊。 |
| **簽出這個修訂版本** | 簽出這個提交（不在任何分支上）。 |
| **從這裡新增分支…**、**在這裡新增標籤…** | 以這個提交為起點建立分支或標籤。 |
| **Cherry-Pick** | 把這個提交的改動套用到目前分支。 |
| **還原提交** | 新增一個提交，抵銷這個提交的改動。 |
| **將目前分支重設到這裡** | **Soft：保留變更並勾選**、**Mixed：保留變更，不勾選**、**Hard：捨棄變更**（會再問一次）。 |
| **撤銷提交** | 只有目前分支最新的提交才有：拿掉這個提交，它的變更放回並勾選，訊息放回輸入框。 |
| **編輯提交訊息…**、**刪除提交…** | 用[互動式 Rebase](#rebase) 改這個提交的訊息，或把它拿掉。 |
| **從這裡互動式 Rebase…** | 見[互動式 Rebase](#rebase)。 |

從[分支選單](#branches)選「與「目前分支」比較」時，日誌只列出那個分支有、目前分支沒有的提交（「在「分支」、不在「目前分支」」）；按 **回到分支** 回到一般的日誌。

### 互動式 Rebase {#rebase}

- 在日誌選 **從這裡互動式 Rebase…**，會列出從那個提交到最新的所有提交。
- 每個提交選一種做法：**保留（Pick）**、**改訊息（Reword）**、**壓縮（Squash）**、**修正（Fixup）** 或 **刪除**；用 **上移**、**下移** 調整順序。改訊息和壓縮可以直接寫 **新的訊息** 或 **壓縮後提交的訊息**。
- 按 **開始 Rebase**。還沒提交的變更會先收起來，完成後放回。遇到衝突時照[合併衝突](#conflicts)處理。

## 擱置區 {#shelf}

- 列出擱置的變更和它們的檔案。
- **取回**：放回工作區，並從擱置區移除。
- **套用並留在擱置區**：放回工作區，擱置區仍保留一份。
- **刪除**：丟掉這份擱置的變更（會再問一次，刪掉的變更會遺失）。

## 推送 {#push}

- **推送…** 會先列出要推送的提交。目前分支還沒有遠端分支時，會標示 **新分支**。
- 遠端有這裡沒有的提交時會先提醒，因為推送可能會被拒絕；可以先按 **更新專案**。
- 選項：**推送標籤**，以及 **強制推送（with lease）**：只有遠端還停在你上次看到的位置時才會強制推送，不會蓋掉別人剛推上去的提交。
- 沒有要推送的提交時，會顯示「沒有要推送的提交，分支和遠端一致。」

## 分支選單 {#branches}

按上方的分支名稱，或執行 `Git: Branches…`、在 **Git 操作** 選單選 **分支…**，就會打開分支選單：

- 最上面是常用的動作：**更新專案**、**提交…**、**推送…**、**新增分支…**、**簽出標籤或修訂版本…**。
- 接著分成 **最近**、**本機**、**遠端**。本機分支旁的星號可以 **加入我的最愛**，我的最愛會排在本機分支的最前面。
- 分支後面會標出和遠端的差距（↑ 是還沒推送的提交，↓ 是還沒拉取的提交）；遠端分支被刪掉時標示 **上游已刪除**。

選一個分支，會列出可以做的事：

- **簽出**：遠端分支會建立一個同名的本機分支並簽出。
- **從「分支」新增分支…**、**簽出並 Rebase 到「目前分支」**、**與「目前分支」比較**、**顯示「分支」與工作區的差異**。
- **將「目前分支」Rebase 到「分支」**、**將「分支」合併到「目前分支」**。
- **重新命名…**、**刪除**；遠端分支則是 **從遠端刪除**。刪除還沒完全合併的分支時，會再問一次。

簽出會覆蓋你在本機的變更時，Breezell 會問要不要用 **Smart Checkout**：先把變更擱置，簽出後再取回。

## 更新專案 {#update}

**更新專案** 會先擷取，再把目前分支更新到它的上游；你還沒提交的變更會先收起來，完成後放回。完成時會顯示「已更新：拉入 N 個提交。」或「已是最新。」

預設用合併的方式更新。想改用 Rebase，在設定裡搜尋 `breezell.git`，把 Update Method 改成 rebase（這個設定的文字是英文）。

## IDE 的快捷鍵 {#keys}

想用 IntelliJ IDEA 的 Git 快捷鍵，在設定裡搜尋 `breezell.git`，勾選 Idea Keymap（預設不勾選）：

| 快捷鍵 | 作用 |
| --- | --- |
| `Ctrl+K` | 提交 |
| `Ctrl+Shift+K` | 推送 |
| `Ctrl+T` | 更新專案 |
| `Alt+9` | 日誌 |
| `Alt+0` | 提交 |

macOS 上用 `Cmd` 取代 `Ctrl`，日誌和提交是 `Cmd+9`、`Cmd+0`，**Git 操作** 選單是 `Ctrl+V`。打開這些快捷鍵後，會取代 IDE 原本以 `Ctrl+K` 開頭的組合鍵和 `Ctrl+T`。`` Alt+` `` 不需要這個設定，一直都能用。

## 目前的限制 {#limits}

- 很大的檔案和二進位檔不顯示變更內容；太大的檔案不能分段，只能整個檔案一起勾選。
- 變更的檔案很多時，只列出一部分，其餘的會說明數量，完整清單在 IDE 的原始檔控制。
- 範圍內有合併提交時，不能互動式 Rebase；第一個提交不能壓縮或修正到前一個提交，也不能撤銷。
- 其他專案的 Git 要透過那個專案的視窗。那個視窗關掉時，會顯示「「專案名稱」的視窗已經關閉。」，按 **重試** 再連一次。
- Git 以外的原始檔控制只有簡單的檢視：**提交訊息**、**提交** 和變更清單。
