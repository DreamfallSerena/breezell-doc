# Git

В Breezell 1.4.59 есть Git в стиле IntelliJ IDEA: можно отметить файлы для коммита или только части файла; файлы, изменённые беседами с ИИ, сгруппированы по беседам; доступны граф веток, полка для отложенных изменений, просмотр того, что уйдёт при отправке, интерактивное перебазирование и список веток для переключения, сравнения и слияния. Он работает на [странице Agents](/ru/agents-page) и в IDE.

| Термин | Значение |
| --- | --- |
| Отметка | Включение в следующий коммит. Неотмеченные изменения остаются в рабочем дереве и не фиксируются. |
| Фрагмент | Один непрерывный участок изменений в файле. Можно отметить только некоторые фрагменты файла. |
| Отложить | Убрать изменения в сторону, чтобы рабочее дерево стало чистым, и вернуть их позже. |
| Upstream | Удалённая ветка, за которой следует текущая, например `origin/main`. |

## Как открыть {#open}

- **Страница Agents:** «Git» вверху списка слева; число рядом показывает, сколько файлов этого проекта изменено. Нажмите, чтобы открыть Git посередине страницы; стрелка вверху слева («Вернуться к разговору») или `Esc` возвращает назад.
- **IDE:** выполните `Git: Commit…`, `Git: Push…`, `Git: Update Project`, `Git: Show Log`, `Git: Show Shelf` или `Git: Branches…` в палитре команд (`Ctrl+Shift+P`), и откроется вкладка «Git», такая же, как на странице Agents.
- Где бы вы ни были, `` Alt+` `` открывает «Операции Git»: «Коммит…», «Отправить…», «Обновить проект», «Ветки…», «Журнал», «Полка», «Получить (fetch)».

## Какой проект показан {#project}

- Git следует за беседой, которую вы смотрите: для беседы проекта этого окна это его репозиторий; для беседы другого проекта это репозиторий того проекта, и его название показано вверху (подсказка «Git проекта «*название проекта*» из его окна»). Проекты WSL и SSH работают так же.
- Если окна этого проекта нет, Breezell открывает его в фоне, не показывая; пока это происходит, на странице написано «Подключение к окну «*название проекта*»…».
- Если в проекте несколько репозиториев, нажмите на название репозитория («Сменить репозиторий») и выберите нужный.
- Папка, которая ещё не является репозиторием Git, показывает «Этот проект ещё не является репозиторием Git.» и кнопку «Инициализировать репозиторий».

Верхняя строка слева направо:

- Название ветки: открывает [список веток](#branches). Состояние синхронизации рядом с ним такое же, как в строке состояния IDE, и по нажатию делает то же самое.
- «Обновить проект» (стрелка вниз): см. [Обновление проекта](#update).
- «Отправить…» (стрелка вверх): см. [Отправка](#push).
- «Другие действия Git» (⋯): то же, что меню «⋯» системы управления версиями IDE, например получение, удалённые репозитории, теги и рабочие деревья.

Ниже три вкладки: «Коммит» (с числом изменений), «Журнал» и «Полка».

## Коммит {#commit}

### Что отметить для коммита {#check}

- У каждого файла есть флажок: «Отметить: включить в следующий коммит», «Снять отметку: не включать в следующий коммит». Флажок в заголовке группы отмечает или снимает отметку со всей группы; если отмечены только некоторые файлы, показано тире.
- Чтобы зафиксировать только часть файла, нажмите стрелку перед его именем («Показать фрагменты (коммит части файла)») и отметьте нужные фрагменты («Отметить фрагмент: включить в следующий коммит»). У новых, удалённых и двоичных файлов фрагментов нет, они отмечаются целиком.
- Нажмите на имя файла, чтобы увидеть его изменения: справа на странице Agents, в области редактора в IDE.
- Правая кнопка на файле открывает обычные действия IDE с файлом (например, отмену изменений), а также «Отложить…» и «Показать историю» (журнал только с коммитами этого файла).

### Группы {#changelists}

- **Agent · *название беседы*:** файлы, изменённые беседами с ИИ, по одной группе на беседу. Файл, изменённый несколькими беседами, попадает в группу самой последней. Так можно зафиксировать только то, что сделала одна беседа.
- **Изменения:** остальные изменённые файлы.
- **Файлы вне системы контроля версий:** новые файлы, которые Git ещё не отслеживает; сначала свёрнуты.

### Сообщение и коммит {#message}

- Напишите сообщение в поле «Сообщение коммита» и нажмите «Зафиксировать» (`Ctrl+Enter`, на macOS `Cmd+Enter`). «Коммит и отправка…» после коммита открывает [Отправку](#push).
- Две кнопки рядом с полем: «История сообщений коммитов» (выбрать ранее использованное сообщение) и «Написать сообщение коммита с помощью ИИ (по отмеченным изменениям)».
- «Исправить последний коммит»: если отмечено, отмеченные изменения попадают в последний коммит, а не в новый, и его сообщение появляется в поле.
- «Отложить изменения…»: убирает отмеченные файлы (все изменения, если ничего не отмечено) на [полку](#shelf).
- «Проверка отмеченных изменений с помощью ИИ»: открывает новую беседу, в поле ввода которой уже стоит запрос на проверку; вы читаете и отправляете его. ИИ указывает на проблемы и не меняет файлы.

### Конфликты слияния {#conflicts}

Когда слияние, перебазирование, cherry-pick или отмена коммита приводят к конфликтам, вверху вкладки «Коммит» показано «Конфликты слияния» с числом файлов:

- «Разрешить…» рядом с файлом открывает редактор слияния. Файлы другого проекта разрешаются в его окне («Разрешить в его окне…»).
- «Пусть ИИ разрешит конфликты»: открывает новую беседу с просьбой к ИИ оставить то, что должно остаться с обеих сторон, и убрать маркеры конфликта. Он не фиксирует изменения и сам не продолжает слияние или перебазирование.
- Когда всё разрешено, нажмите «Продолжить». При перебазировании или cherry-pick можно также «Пропустить» текущий коммит; «Прервать» возвращает всё, как было до начала.

## Журнал {#log}

- Коммиты с графом веток; при прокрутке вниз подгружаются более старые.
- Фильтры вверху: «Текст или хеш», «Автор», «Путь» и выбор истории какой ветки показывать («История какой ветки»): «Все ветки», «Текущая ветка» или одна из веток.
- Нажмите на коммит, чтобы увидеть его детали и изменённые файлы рядом со списком; нажмите на файл, чтобы увидеть, что коммит изменил в нём. «Сравнить с локальной версией» вместо этого перечисляет файлы, которые отличаются между этим коммитом и вашим рабочим деревом.

Правая кнопка на коммите:

| Пункт | Что делает |
| --- | --- |
| «Копировать номер ревизии» | Копирует хеш коммита. |
| «Переключиться на эту ревизию» | Переключается на этот коммит (не на ветку). |
| «Новая ветка отсюда…», «Новый тег здесь…» | Создаёт ветку или тег, начинающиеся с этого коммита. |
| «Cherry-pick» | Применяет изменения этого коммита к текущей ветке. |
| «Отменить коммит (revert)» | Добавляет коммит, который отменяет изменения того коммита. |
| «Сбросить текущую ветку сюда» | «Soft: сохранить изменения с отметкой», «Mixed: сохранить изменения без отметки», «Hard: отбросить изменения» (спросит ещё раз). |
| «Отменить коммит» | Только у самого нового коммита текущей ветки: убирает его, его изменения возвращаются отмеченными, а сообщение возвращается в поле. |
| «Изменить сообщение коммита…», «Удалить коммит…» | Меняет сообщение этого коммита или убирает его с помощью [интерактивного перебазирования](#rebase). |
| «Интерактивное перебазирование отсюда…» | См. [Интерактивное перебазирование](#rebase). |

Если в [списке веток](#branches) выбрать «Сравнить с» текущей веткой, журнал показывает только коммиты, которые есть в той ветке и которых нет в текущей («В «*ветка*», но не в «*текущая ветка*»»); «Вернуться к ветке» возвращает обычный журнал.

### Интерактивное перебазирование {#rebase}

- «Интерактивное перебазирование отсюда…» в журнале перечисляет все коммиты от выбранного до самого нового.
- Выберите, что сделать с каждым: «Оставить (pick)», «Изменить сообщение», «Объединить (squash)», «Fixup» или «Удалить», а порядок меняйте кнопками «Выше» и «Ниже». Для изменения сообщения и объединения «Новое сообщение» или «Сообщение объединённого коммита» можно написать прямо там.
- Нажмите «Начать перебазирование». Незафиксированные изменения сначала откладываются, а потом возвращаются. Если возникнут конфликты, действуйте, как в разделе [Конфликты слияния](#conflicts).

## Полка {#shelf}

- Перечисляет отложенные изменения и их файлы.
- «Вернуть с полки»: возвращает изменения в рабочее дерево и убирает их с полки.
- «Применить и оставить на полке»: возвращает их и оставляет копию на полке.
- «Удалить»: выбрасывает их (спросит ещё раз; удалённые изменения не восстановить).

## Отправка {#push}

- «Отправить…» сначала перечисляет коммиты, которые будут отправлены. Если у текущей ветки ещё нет удалённой ветки, она помечена «новая ветка».
- Если в удалённом репозитории есть коммиты, которых нет здесь, предупреждает, что отправку могут отклонить; можно сначала нажать «Обновить проект».
- Параметры: «Отправить теги» и «Принудительная отправка (with lease)», которая принуждает отправку, только пока удалённая ветка осталась там, где вы её видели в последний раз, поэтому никогда не затирает только что отправленные чужие коммиты.
- Когда отправлять нечего, написано «Отправлять нечего: ветка совпадает с удалённой.»

## Список веток {#branches}

Нажмите на название ветки вверху, выполните `Git: Branches…` или выберите «Ветки…» в «Операции Git»:

- Сначала частые действия: «Обновить проект», «Коммит…», «Отправить…», «Новая ветка…», «Переключиться на тег или ревизию…».
- Затем «Недавние», «Локальные» и «Удалённые». Звёздочка рядом с локальной веткой — «Добавить в избранное»; избранные идут первыми среди локальных.
- У ветки показано, насколько она расходится с удалённой (↑ коммиты, ещё не отправленные, ↓ коммиты, ещё не полученные); «upstream удалён», если её удалённую ветку удалили.

Выберите ветку, чтобы увидеть, что с ней можно сделать:

- «Переключиться»: удалённая ветка переключается как локальная ветка с тем же именем.
- «Новая ветка из «*ветка*»…», «Переключиться и перебазировать на «*текущая ветка*»», «Сравнить с «*текущая ветка*»», «Показать отличия «*ветка*» от рабочего дерева».
- «Перебазировать «*текущая ветка*» на «*ветка*»», «Слить «*ветка*» в «*текущая ветка*»».
- «Переименовать…» и «Удалить»; для удалённой ветки «Удалить в удалённом репозитории». Удаление не полностью слитой ветки спрашивает ещё раз.

Если переключение затёрло бы ваши локальные изменения, Breezell предлагает «Smart Checkout»: отложить изменения, переключиться и вернуть их.

## Обновление проекта {#update}

«Обновить проект» получает изменения, затем обновляет текущую ветку по её upstream; незафиксированные изменения тем временем откладываются и возвращаются. Заканчивается сообщением «Обновлено: получено коммитов: N.» или «Уже актуально.»

По умолчанию используется слияние. Чтобы вместо него перебазировать, найдите в настройках `breezell.git` и установите Update Method в rebase.

## Клавиши в IDE {#keys}

Чтобы получить клавиши Git из IntelliJ IDEA, найдите в настройках `breezell.git` и отметьте Idea Keymap (по умолчанию выключено):

| Клавиши | Действие |
| --- | --- |
| `Ctrl+K` | Коммит |
| `Ctrl+Shift+K` | Отправка |
| `Ctrl+T` | Обновить проект |
| `Alt+9` | Журнал |
| `Alt+0` | Коммит |

На macOS вместо `Ctrl` используется `Cmd`; журнал и коммит — `Cmd+9` и `Cmd+0`, а «Операции Git» — `Ctrl+V`. Когда эти клавиши включены, они заменяют собственные сочетания IDE `Ctrl+K` и `Ctrl+T`. `` Alt+` `` не требует настройки и работает всегда.

## Текущие ограничения {#limits}

- У очень больших и двоичных файлов изменения не показываются; слишком большие файлы нельзя разбить на фрагменты, и они отмечаются целиком.
- Когда изменено очень много файлов, перечислена только часть, остальные только подсчитаны; полный список в системе управления версиями IDE.
- Интерактивное перебазирование невозможно, если в его диапазоне есть коммиты слияния; первый коммит нельзя объединить или слить с предыдущим, и его нельзя отменить.
- Git другого проекта работает через окно того проекта. Если это окно закрыто, страница пишет «Окно «*название проекта*» закрыто.»; нажмите «Повторить», чтобы подключиться снова.
- Системы управления версиями, кроме Git, показываются просто: «Сообщение коммита», «Зафиксировать» и список изменений.
