# Breezell и DSH: в чём принципиальная разница?

Один из самых частых вопросов — чем Breezell отличается от DSH (deepseek-harness). Кратко: проекты отдают приоритет разным моделям разработки и сопровождения.

## Краткое сравнение

| Область | DSH | Breezell |
| --- | --- | --- |
| Модель | Фреймворк и экосистема сообщества | Интегрированная IDE, поддерживаемая официальной командой |
| Основной опыт | Основа плюс выбранные расширения сообщества | Готовый продукт сразу после установки |
| Сопровождение | Возможности могут сильно зависеть от сообщества | Ядро и интеграции координируются официально |
| Расширяемость | Широкая свобода и быстрые эксперименты | Сейчас более контролируемая, с постепенным открытием |
| Единообразие | Опыт и качество могут различаться | Более согласованные поведение, дизайн и выпуски |
| Настройка BYOK | Может зависеть от встроенной интеграции или расширений сообщества | Единая и лёгкая настройка провайдеров и моделей |
| Поддержка моделей | Без дополнительных интеграций встроенная поддержка уже | Широкая встроенная поддержка провайдеров, API-форматов и возможностей |
| Встроенные процессы | Дополнительные процессы могут требовать плагинов или ручной сборки | Шесть режимов для общения, анализа, планирования, автономной работы, причинного анализа и параллельного взаимодействия |
| Безопасность | Зависит от источника, разрешений и реализации расширения | Официальное ядро находится в более контролируемой среде |
| Компромисс | Гибкость требует тщательной проверки расширений | Возможности могут ждать официальной разработки |

## Подход DSH

DSH ближе к фреймворку сообщества. Официальный проект предоставляет основу, а многие функции, интеграции, плагины и варианты рабочих процессов могут поступать из расширений сообщества.

Это даёт свободу, ускоряет эксперименты и позволяет глубоко настраивать среду, но повышает ответственность пользователя. Как и в любом расширяемом инструменте, ненадёжное или плохо спроектированное расширение может раскрыть учётные данные, создать путь для инъекции промптов, работать нестабильно или выполнять разрушительные операции.

Реальный риск определяется источником, разрешениями, качеством реализации и процессом проверки, а не самим фактом разработки сообществом.

## Подход Breezell

Breezell разрабатывается, интегрируется и поддерживается преимущественно как официальный продукт. Цель — предоставить готовую среду без необходимости собирать основной процесс из отдельных плагинов.

Команда может согласованно контролировать поведение, интерфейс, интеграции, совместимость, границы безопасности, обновления и поддержку.

Без ненадёжных сторонних расширений основная среда остаётся внутри официально поддерживаемой системы, снижая неопределённость, связанную с неизвестным кодом, учётными данными, инъекцией промптов и разрушительным поведением.

::: info Граница безопасности, а не абсолютная гарантия
Перед установкой стороннего расширения проверяйте источник, издателя, разрешения и репутацию.
:::

## Настройка BYOK и поддержка моделей

В Breezell **Bring Your Own Key (BYOK)** является основной возможностью продукта. Провайдеры, endpoints, API-ключи, форматы API, модели и их возможности настраиваются единообразно, легко и удобно для сопровождения.

В одном интерфейсе поддерживается широкий набор провайдеров, семейств моделей, API-форматов, уровней рассуждений, визуальных, графических и видеомоделей. По сравнению с нативным DSH без дополнительных интеграций сообщества Breezell имеет более широкую встроенную совместимость и реже требует отдельного плагина или уникальной настройки для каждого провайдера.

## Шесть встроенных интеллектуальных режимов

| Режим | Назначение |
| --- | --- |
| **Chat** | Быстрые вопросы и разговоры |
| **Agent** | Автономно изменяет файлы и использует инструменты |
| **Analyze** | Глубокий анализ без редактирования |
| **Plan** | План реализации до написания кода |
| **Entanglement** | Причинное рассуждение с учётом эмоций |
| **Teams** | Параллельные ИИ-участники для сложных задач |

Это встроенные процессы Breezell, а не режимы из отдельных плагинов. Пользователь может переходить от вопроса к анализу, планированию, автономной реализации, причинному исследованию или параллельной работе без установки расширений для каждого режима.

Режимы используют общие контекст, инструменты, разрешения, память, интерфейс и состояние задач, сохраняя специализацию и единообразие.

## Возможности Agent

Breezell Agent оптимизирован для выбора инструментов, изменения файлов, управления контекстом, восстановления после ошибок, проверки и продолжения длительных задач. В текущих сценариях программирования, поддерживаемых обоими продуктами, команда Breezell оценивает **сквозную автономность и надёжность выполнения Breezell Agent выше, чем у нативного DSH**.

::: info Область сравнения
Это оценка продукта Breezell на основе внутренней разработки и наблюдаемого использования, а не универсальный независимый тест. Результат зависит от модели, задачи, репозитория, настроек и среды.
:::

## Компромисс

Официальная координация повышает единообразие, стабильность и контроль, но может стать узким местом. Некоторые ошибки, интеграции и функции приходится ждать.

Экосистема сообщества способна расширяться быстрее. Breezell сейчас менее открыт в обмен на более предсказуемое ядро.

## Куда движется Breezell

Breezell построен на VS Code и постоянно следует его обновлениям, что создаёт сильную основу для зрелой экосистемы расширений.

Долгосрочная цель — открыть создание расширений сообществу, сохраняя ясные разрешения, изолированные границы, прозрачное происхождение, стабильные официальные API и ядро, работающее без сторонних плагинов.

## Итог

> **DSH ближе к фреймворку сообщества, ориентированному на максимальную свободу. Breezell делает ставку на целостный официальный продукт с более высокой согласованностью, стабильностью и контролируемыми границами безопасности, постепенно открывая расширяемость.**
