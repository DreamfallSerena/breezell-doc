# Git

Breezell 1.4.59에는 IntelliJ IDEA 스타일의 Git이 들어 있습니다. 커밋할 파일이나 파일의 일부만 체크하고, AI 대화가 바꾼 파일은 대화별로 묶어 보며, 브랜치 그래프를 보고, 변경을 셸브하고, 푸시가 보내는 내용을 보내기 전에 확인하고, 대화형으로 리베이스하고, 브랜치 팝업에서 체크아웃, 비교, 병합을 할 수 있습니다. [Agents 페이지](/ko/agents-page)와 IDE에서 모두 쓸 수 있습니다.

| 용어 | 의미 |
| --- | --- |
| 체크 | 다음 커밋에 포함하는 것. 체크하지 않은 변경은 작업 트리에 그대로 남고 커밋되지 않습니다. |
| 헝크 | 파일 안의 연속된 변경 한 덩어리. 파일의 일부 헝크만 체크할 수 있습니다. |
| 셸브 | 작업 트리가 깨끗해지도록 변경을 따로 치워 두었다가 나중에 되돌리는 것. |
| 업스트림 | 현재 브랜치가 따라가는 원격 브랜치. 예: `origin/main`. |

## 여는 방법 {#open}

- **Agents 페이지:** 왼쪽 목록 맨 위의 "Git"이며, 옆의 숫자는 이 프로젝트에서 변경된 파일 수입니다. 누르면 페이지 가운데에 Git이 열리고, 왼쪽 위의 화살표("대화로 돌아가기") 또는 `Esc`로 돌아갑니다.
- **IDE:** 명령 팔레트(`Ctrl+Shift+P`)에서 `Git: Commit…`, `Git: Push…`, `Git: Update Project`, `Git: Show Log`, `Git: Show Shelf`, `Git: Branches…` 중 하나를 실행하면 Agents 페이지와 같은 "Git" 탭이 열립니다.
- 어디서든 `` Alt+` ``는 "Git 작업"을 엽니다: "커밋…", "푸시…", "프로젝트 업데이트", "브랜치…", "로그", "셸프", "페치".

## 표시되는 프로젝트 {#project}

- Git은 지금 보고 있는 대화를 따라갑니다. 이 창의 프로젝트의 대화라면 그 저장소이고, 다른 프로젝트의 대화라면 그 프로젝트의 저장소이며 맨 위에 이름이 표시됩니다(툴팁 "*프로젝트 이름*"의 Git (해당 창에서)"). WSL과 SSH 프로젝트도 같습니다.
- 그 프로젝트의 창이 열려 있지 않으면 Breezell이 화면에 표시하지 않고 백그라운드에서 엽니다. 그동안 페이지에는 "*프로젝트 이름*" 창에 연결하는 중…"이라고 표시됩니다.
- 프로젝트에 저장소가 여러 개면 저장소 이름("저장소 전환")을 눌러 고릅니다.
- 아직 Git 저장소가 아닌 폴더는 "이 프로젝트는 아직 Git 저장소가 아닙니다."와 "저장소 초기화" 버튼을 보여 줍니다.

맨 위 줄은 왼쪽부터 다음과 같습니다.

- 브랜치 이름: [브랜치 팝업](#branches)을 엽니다. 옆의 동기화 상태는 IDE 상태 표시줄의 것과 같고, 누르면 같은 동작을 합니다.
- "프로젝트 업데이트"(아래쪽 화살표): [프로젝트 업데이트](#update)를 참고하세요.
- "푸시…"(위쪽 화살표): [푸시](#push)를 참고하세요.
- "기타 Git 작업"(⋯): IDE 소스 제어의 "⋯" 메뉴와 같으며, 예를 들어 풀, 원격, 태그, 워크트리가 있습니다.

그 아래에 세 개의 탭이 있습니다: "커밋"(변경 개수 포함), "로그", "셸프".

## 커밋 {#commit}

### 커밋할 것 체크하기 {#check}

- 모든 파일에 체크 상자가 있습니다: "체크: 다음 커밋에 포함", "체크 해제: 다음 커밋에서 제외". 그룹 제목의 체크 상자는 그룹 전체를 체크하거나 해제하며, 일부 파일만 체크되어 있으면 대시가 표시됩니다.
- 파일의 일부만 커밋하려면 파일 이름 앞의 화살표("헝크 보기(파일 일부만 커밋)")를 누르고 원하는 헝크를 체크합니다("이 헝크 체크: 다음 커밋에 포함"). 새 파일, 삭제된 파일, 바이너리 파일은 헝크가 없고 통째로 체크됩니다.
- 파일 이름을 누르면 변경 내용이 보입니다. Agents 페이지에서는 페이지 오른쪽에, IDE에서는 편집기 영역에 열립니다.
- 파일을 오른쪽 클릭하면 IDE 자체의 파일 동작(예: 변경 취소)과 함께 "셸브…", "기록 보기"(그 파일의 커밋만 보여 주는 로그)가 나옵니다.

### 그룹 {#changelists}

- **Agent · *대화 제목*:** AI 대화가 바꾼 파일로, 대화마다 한 그룹입니다. 여러 대화가 바꾼 파일은 가장 최근 대화의 그룹에 들어갑니다. 그래서 한 대화가 한 일만 커밋할 수 있습니다.
- **변경 사항:** 그 밖의 변경된 파일.
- **버전 관리되지 않는 파일:** Git이 아직 추적하지 않는 새 파일로, 처음에는 접혀 있습니다.

### 메시지와 커밋 {#message}

- "커밋 메시지"에 메시지를 쓰고 "커밋"(`Ctrl+Enter`, macOS에서는 `Cmd+Enter`)을 누릅니다. "커밋 후 푸시…"는 커밋한 뒤 [푸시](#push)를 엽니다.
- 상자 옆의 두 버튼: "커밋 메시지 기록"(전에 쓴 메시지를 고름)과 "AI로 커밋 메시지 작성(체크한 변경 기준)".
- "이전 커밋 수정": 체크하면 체크한 변경이 새 커밋이 아니라 마지막 커밋에 들어가고, 그 커밋의 메시지가 상자에 들어옵니다.
- "변경 셸브…": 체크한 파일(체크한 것이 없으면 모든 변경)을 [셸프](#shelf)에 넣습니다.
- "체크한 변경을 AI에게 검토받기": 검토 요청이 이미 입력창에 채워진 새 대화를 열어 주며, 읽고 보내면 됩니다. AI는 문제를 지적할 뿐 파일을 바꾸지 않습니다.

### 병합 충돌 {#conflicts}

병합, 리베이스, 체리픽, 되돌리기에서 충돌이 나면 "커밋" 탭 맨 위에 파일 수와 함께 "병합 충돌"이 표시됩니다.

- 각 파일 옆의 "해결…"은 병합 편집기를 엽니다. 다른 프로젝트의 파일은 그 창에서 해결합니다("해당 창에서 해결…").
- "AI에게 충돌 해결 맡기기": 양쪽이 남겨야 할 것을 남기고 충돌 표시를 지우도록 AI에게 요청하는 새 대화를 엽니다. 커밋하지 않으며, 병합이나 리베이스를 스스로 이어 가지도 않습니다.
- 모두 해결했으면 "계속"을 누릅니다. 리베이스나 체리픽에서는 현재 커밋을 "건너뛰기"할 수도 있고, "중단"은 시작하기 전 상태로 되돌립니다.

## 로그 {#log}

- 브랜치 그래프와 함께 커밋이 나열되며, 아래로 스크롤하면 더 오래된 커밋을 불러옵니다.
- 맨 위의 필터: "텍스트 또는 해시", "작성자", "경로", 그리고 어느 브랜치의 기록을 볼지("어느 브랜치의 기록인지"): "모든 브랜치", "현재 브랜치" 또는 브랜치 하나.
- 커밋을 누르면 목록 옆에 상세와 변경된 파일이 보이고, 파일을 누르면 그 커밋이 그 파일에서 바꾼 내용이 보입니다. "로컬과 비교"는 대신 그 커밋과 작업 트리에서 다른 파일을 나열합니다.

커밋을 오른쪽 클릭합니다.

| 항목 | 동작 |
| --- | --- |
| "리비전 번호 복사" | 커밋의 해시를 복사합니다. |
| "이 리비전 체크아웃" | 그 커밋을 체크아웃합니다(어느 브랜치에도 속하지 않음). |
| "여기에서 새 브랜치…", "여기에 새 태그…" | 그 커밋에서 시작하는 브랜치 또는 태그를 만듭니다. |
| "체리픽" | 그 커밋의 변경을 현재 브랜치에 적용합니다. |
| "커밋 되돌리기" | 그 커밋의 변경을 취소하는 커밋을 추가합니다. |
| "현재 브랜치를 여기로 재설정" | "Soft: 변경 유지, 체크함", "Mixed: 변경 유지, 체크 안 함", "Hard: 변경 버리기"(한 번 더 확인). |
| "커밋 취소" | 현재 브랜치의 가장 최근 커밋에만 있습니다. 그 커밋을 없애고, 변경은 체크된 채로 돌아오며 메시지는 상자로 돌아옵니다. |
| "커밋 메시지 편집…", "커밋 삭제…" | [대화형 리베이스](#rebase)로 그 커밋의 메시지를 바꾸거나 그 커밋을 없앱니다. |
| "여기부터 대화형 리베이스…" | [대화형 리베이스](#rebase)를 참고하세요. |

[브랜치 팝업](#branches)에서 현재 브랜치와 "비교"를 고르면 로그에는 그 브랜치에는 있고 현재 브랜치에는 없는 커밋만 표시됩니다("*브랜치*"에 있고 "*현재 브랜치*"에 없는 것). "브랜치로 돌아가기"를 누르면 평소 로그로 돌아옵니다.

### 대화형 리베이스 {#rebase}

- 로그의 "여기부터 대화형 리베이스…"는 그 커밋부터 가장 최근 커밋까지를 모두 나열합니다.
- 각 커밋에 할 일을 고릅니다: "픽", "메시지 변경", "스쿼시", "픽스업" 또는 "삭제". 순서는 "위로"와 "아래로"로 바꿉니다. 메시지 변경과 스쿼시에서는 그 자리에서 "새 메시지" 또는 "스쿼시한 커밋의 메시지"를 쓸 수 있습니다.
- "리베이스 시작"을 누릅니다. 커밋하지 않은 변경은 먼저 따로 치워 두었다가 나중에 되돌려 놓습니다. 충돌이 나면 [병합 충돌](#conflicts)과 같이 처리합니다.

## 셸프 {#shelf}

- 셸브한 변경과 그 파일을 나열합니다.
- "셸브 해제": 변경을 작업 트리로 되돌리고 셸프에서 지웁니다.
- "적용하고 셸프에 남기기": 되돌리면서 셸프에 사본을 남깁니다.
- "삭제": 버립니다(한 번 더 확인하며, 삭제한 변경은 되살릴 수 없습니다).

## 푸시 {#push}

- "푸시…"는 먼저 푸시될 커밋을 나열합니다. 현재 브랜치에 아직 원격 브랜치가 없으면 "새 브랜치"로 표시됩니다.
- 원격에 여기 없는 커밋이 있으면 푸시가 거부될 수 있다고 경고하며, 먼저 "프로젝트 업데이트"를 누를 수 있습니다.
- 옵션: "태그 푸시", 그리고 "강제 푸시(with lease)"는 원격이 마지막으로 본 위치에 그대로 있을 때만 강제로 푸시하므로 다른 사람이 방금 푸시한 커밋을 덮어쓰지 않습니다.
- 푸시할 것이 없으면 "푸시할 커밋이 없습니다(원격과 같습니다)."라고 표시됩니다.

## 브랜치 팝업 {#branches}

맨 위의 브랜치 이름을 누르거나, `Git: Branches…`를 실행하거나, "Git 작업"에서 "브랜치…"를 고릅니다.

- 자주 쓰는 동작이 먼저 나옵니다: "프로젝트 업데이트", "커밋…", "푸시…", "새 브랜치…", "태그 또는 리비전 체크아웃…".
- 그다음 "최근", "로컬", "원격"입니다. 로컬 브랜치 옆의 별은 "즐겨찾기에 추가"이며, 즐겨찾기는 로컬 브랜치 중 맨 앞에 옵니다.
- 브랜치에는 원격과 얼마나 떨어져 있는지가 표시됩니다(↑ 아직 푸시하지 않은 커밋, ↓ 아직 풀하지 않은 커밋). 원격 브랜치가 삭제되었으면 "업스트림 삭제됨"입니다.

브랜치를 고르면 할 수 있는 일이 나옵니다.

- "체크아웃": 원격 브랜치는 같은 이름의 로컬 브랜치로 체크아웃됩니다.
- ""*브랜치*"에서 새 브랜치…", "체크아웃 후 "*현재 브랜치*"(으)로 리베이스", ""*현재 브랜치*"와(과) 비교", ""*브랜치*"와(과) 작업 트리의 차이 보기".
- ""*현재 브랜치*"을(를) "*브랜치*"(으)로 리베이스", ""*브랜치*"을(를) "*현재 브랜치*"에 병합".
- "이름 바꾸기…"와 "삭제"가 있고, 원격 브랜치는 "원격에서 삭제"입니다. 완전히 병합되지 않은 브랜치를 삭제할 때는 한 번 더 묻습니다.

체크아웃이 로컬 변경을 덮어쓰게 되면 Breezell이 "스마트 체크아웃"을 제안합니다. 변경을 셸브하고, 체크아웃하고, 변경을 되돌려 놓습니다.

## 프로젝트 업데이트 {#update}

"프로젝트 업데이트"는 페치한 다음 현재 브랜치를 업스트림에 맞춰 최신으로 만듭니다. 커밋하지 않은 변경은 그동안 따로 치워 두었다가 되돌려 놓습니다. 끝나면 "업데이트했습니다: 커밋 N개를 받았습니다." 또는 "이미 최신입니다."가 표시됩니다.

기본값은 병합입니다. 대신 리베이스하려면 설정에서 `breezell.git`를 검색해 Update Method를 rebase로 바꾸세요.

## IDE의 키 {#keys}

IntelliJ IDEA의 Git 키를 쓰려면 설정에서 `breezell.git`를 검색해 Idea Keymap을 체크하세요(기본값은 꺼짐).

| 키 | 동작 |
| --- | --- |
| `Ctrl+K` | 커밋 |
| `Ctrl+Shift+K` | 푸시 |
| `Ctrl+T` | 프로젝트 업데이트 |
| `Alt+9` | 로그 |
| `Alt+0` | 커밋 |

macOS에서는 `Ctrl` 대신 `Cmd`를 쓰며, 로그와 커밋은 `Cmd+9`와 `Cmd+0`, "Git 작업"은 `Ctrl+V`입니다. 이 키를 켜면 IDE 자체의 `Ctrl+K` 코드와 `Ctrl+T`를 대신합니다. `` Alt+` ``는 설정이 필요 없고 항상 작동합니다.

## 현재의 제한 {#limits}

- 아주 큰 파일과 바이너리 파일은 변경 내용이 표시되지 않습니다. 너무 큰 파일은 헝크로 나눌 수 없고 통째로 체크됩니다.
- 변경된 파일이 아주 많으면 일부만 나열하고 나머지는 개수로만 표시합니다. 전체 목록은 IDE의 소스 제어에 있습니다.
- 범위에 병합 커밋이 있으면 대화형 리베이스를 할 수 없습니다. 첫 커밋은 앞의 커밋에 스쿼시하거나 픽스업할 수 없고, 취소할 수도 없습니다.
- 다른 프로젝트의 Git은 그 프로젝트의 창을 거칩니다. 그 창이 닫혔으면 페이지에 ""*프로젝트 이름*" 창이 닫혔습니다."라고 표시되며, "다시 시도"를 누르면 다시 연결합니다.
- Git이 아닌 다른 소스 제어는 간단한 화면입니다: "커밋 메시지", "커밋", 변경 목록.
