# Breezell과 DSH: 근본적인 차이

가장 자주 받는 질문 중 하나는 Breezell과 DSH(deepseek-harness)가 어떻게 다른가입니다. 간단히 말하면 두 프로젝트는 개발 및 유지 관리 모델에서 서로 다른 우선순위를 가집니다.

## 빠른 비교

| 영역 | DSH | Breezell |
| --- | --- | --- |
| 제품 모델 | 커뮤니티 중심 프레임워크와 생태계 | 공식 팀이 주로 유지 관리하는 통합 IDE |
| 기본 경험 | 기반과 선택한 커뮤니티 확장으로 구성 | 설치 후 바로 사용할 수 있는 완성형 제품 |
| 유지 관리 | 기능과 통합이 커뮤니티에 크게 의존할 수 있음 | 핵심 기능과 통합을 공식적으로 조정 |
| 확장성 | 높은 자유도와 빠른 실험 | 현재는 더 통제되며 단계적으로 개방 |
| 일관성 | 확장에 따라 경험과 품질이 달라질 수 있음 | 동작, 디자인 및 릴리스 기준이 더 일관됨 |
| BYOK 설정 | 통일되고 가벼운 공급자 및 모델 설정 | 기본 통합 또는 커뮤니티 확장에 의존할 수 있음 |
| 모델 지원 | 공급자, API 형식 및 모델 기능을 폭넓게 기본 지원 | 추가 통합 없이는 기본 지원 범위가 더 좁음 |
| 기본 워크플로 | 6개 모드로 대화, 분석, 계획, 자율 작업, 인과 추론 및 병렬 협업 지원 | 추가 워크플로에 플러그인이나 사용자 구성이 필요할 수 있음 |
| 보안 경계 | 각 확장의 출처, 권한 및 구현에 좌우됨 | 공식 핵심 기능을 더 통제된 경계 안에서 유지 |
| 주요 절충점 | 사용자의 신중한 확장 검토가 필요 | 수정과 기능이 공식 개발을 기다릴 수 있음 |

## DSH 방식

DSH는 커뮤니티 중심 프레임워크에 가깝습니다. 공식 프로젝트가 기반을 제공하고 많은 기능, 통합, 플러그인 및 워크플로 선택은 커뮤니티 확장에서 제공될 수 있습니다.

높은 자유도와 빠른 실험, 세밀한 사용자 지정을 제공하지만 사용자 책임도 커집니다. 모든 확장형 개발 도구와 마찬가지로 신뢰할 수 없거나 설계가 부족한 확장은 자격 증명 노출, 프롬프트 인젝션, 불안정한 동작 또는 파괴적인 작업을 유발할 수 있습니다.

실제 위험은 단순히 커뮤니티 제작 여부가 아니라 출처, 요청 권한, 구현 품질 및 검토 절차에 따라 달라집니다.

## Breezell 방식

Breezell은 공식 제품으로서 개발, 통합 및 유지 관리됩니다. 사용자가 핵심 워크플로를 여러 플러그인으로 직접 조립하지 않아도 바로 사용할 수 있는 경험을 목표로 합니다.

공식 팀은 제품 동작, 인터페이스, 모델과 도구 통합, 호환성 테스트, 보안 경계, 업데이트 및 지원을 일관되게 조정할 수 있습니다.

신뢰할 수 없는 타사 확장을 설치하지 않는 한 핵심 경험은 공식 유지 관리 환경 안에 남아 있어 알 수 없는 코드, 자격 증명 처리, 프롬프트 인젝션 및 파괴적 동작의 불확실성을 크게 줄입니다.

::: info 보안 경계는 절대적인 보장이 아닙니다
타사 확장을 설치하기 전에 출처, 게시자, 권한 및 평판을 확인하세요.
:::

## BYOK 설정과 모델 지원

Breezell은 **Bring Your Own Key(BYOK)**를 핵심 제품 기능으로 제공합니다. 공급자, 엔드포인트, API 키, API 형식, 모델 및 기능 옵션을 통일된 설정 체계로 관리하여 더 가볍고 유지하기 쉽습니다.

동일한 인터페이스에서 다양한 공급자, 모델 계열, API 형식, 추론 수준, 비전, 이미지 및 비디오 모델을 설정할 수 있습니다. 추가 커뮤니티 통합이 없는 기본 DSH와 비교하면 Breezell은 더 넓은 모델 범위를 기본으로 제공하며 공급자마다 별도 플러그인이나 설정 경로를 만들 필요를 줄입니다.

## 6가지 지능형 모드 기본 제공

| 모드 | 용도 |
| --- | --- |
| **Chat** | 빠른 질문과 대화 |
| **Agent** | 파일을 편집하고 도구를 자율적으로 사용 |
| **Analyze** | 편집 없이 심층 분석 |
| **Plan** | 코딩 전에 구현 계획 작성 |
| **Entanglement** | 감정 인식을 포함한 인과 추론 |
| **Teams** | 복잡한 작업을 위한 병렬 AI 팀원 |

이 모드들은 별도 플러그인이 추가한 기능이 아니라 Breezell의 기본 워크플로입니다. 모드를 추가하기 위한 확장 설치 없이 질문, 분석, 계획, 자율 구현, 인과 탐색 및 병렬 협업을 전환할 수 있습니다.

모든 모드는 Breezell의 컨텍스트, 도구, 권한, 메모리, 인터페이스 및 작업 상태를 공유하여 전문성과 일관성을 함께 유지합니다.

## Agent 역량

Breezell Agent는 도구 선택, 파일 편집, 컨텍스트 관리, 오류 복구, 결과 검증 및 장기 작업 연속성을 최적화했습니다. 두 제품이 모두 지원하는 현재 코딩 워크플로에서 Breezell 팀은 **Breezell Agent가 기본 DSH보다 더 강한 전체 자율 실행 능력과 신뢰성을 제공한다**고 평가합니다.

::: info 비교 범위
이는 내부 개발 및 관찰된 사용 결과에 기반한 Breezell의 제품 평가이며 독립적이고 보편적인 벤치마크는 아닙니다. 결과는 모델, 작업, 저장소, 설정 및 환경에 따라 달라질 수 있습니다.
:::

## 절충점

공식 조정은 일관성, 안정성 및 통제력을 높이지만 병목이 될 수도 있습니다. 현재 Breezell은 공식 개발 리소스에 더 크게 의존하므로 일부 버그와 통합은 팀의 직접 대응을 기다려야 합니다.

커뮤니티 중심 생태계는 더 빠르게 실험하고 확장할 수 있습니다. Breezell은 현재 예측 가능한 핵심 경험을 우선합니다.

## Breezell의 방향

Breezell은 VS Code를 기반으로 하며 업데이트를 지속적으로 반영합니다.

장기적으로는 명확한 권한 표시, 격리된 보안 경계, 투명한 출처, 안정적인 공식 API, 타사 플러그인 없이도 사용할 수 있는 공식 핵심을 유지하면서 커뮤니티가 확장을 제작하고 배포할 수 있도록 할 계획입니다.

## 결론

> **DSH는 최대한의 자유를 우선하는 커뮤니티 중심 프레임워크에 가깝습니다. Breezell은 더 강한 일관성, 안정성 및 보안 경계를 갖춘 공식 유지 관리 완성형 제품에 집중하면서 확장성을 통제된 방식으로 단계적으로 개방합니다.**
