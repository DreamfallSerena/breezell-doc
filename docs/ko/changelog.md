# 변경 사항

## 1.4.55 · 핫 업데이트 · 2026-11-11

1.4.5용 핫 업데이트로, 다시 설치할 필요가 없습니다. Breezell이 알아서 제공하며, Box 사이드바 하단의 「업데이트」에서 확인할 수도 있습니다.

### 하이라이트

- **초보자 가이드:** 아직 자신의 API를 연결하지 않은 새 사용자에게 Box, 공식 모델, 자신의 키나 중계 서비스를 연결하는 곳, 모델을 바꾸는 메뉴를 차례로 안내하는 짧은 가이드가 나타납니다. 다시 보려면 Help 메뉴의 "초보자 가이드"를 여세요.
- **협업 방식:** Breezell은 사용자가 직접 보낸 메시지를 보고 어떻게 일하기를 원하는지(질문 줄이기, 파일을 바꾸기 전에 확인하기, 답변을 간결하게) 추측합니다. 하지만 사용자가 "좋아요"라고 하기 전에는 아무것도 바꾸지 않습니다.
- **더 많은 모델:** Claude Fable 5.2와 Claude Mythos 5.2(Fast 포함)를 지원하고, OpenRouter와 Meta에 새 모델이 추가되었으며, Qwen에 "플랜" 선택이 생겼고, 이미지 생성이 Seedream 5.5를 지원합니다.
- **OpenAI 호환 공급자 하나에 여러 개의 키와 주소를 저장할 수 있습니다.** 모델 목록은 선택한 키를 따릅니다.
- **프로젝트 그룹:** 메시지 입력창 위에 그룹 캡슐이 생겼고, AI 권한이 네 개의 스위치로 바뀌었으며, 같은 그룹의 창끼리 대화를 읽을 수 있습니다. 자세한 내용은 [프로젝트 그룹과 메모리 공유](/ko/project-group)를 참고하세요.
- **채팅에서 낭비되는 재시도 감소:** 모델이 출력 한도를 모두 생각에 쓰면 짧게 생각해 한 번만 다시 시도하도록 요청하고, 그래도 안 되면 안내와 함께 멈춥니다. 요금이 청구되는 세 번의 재전송은 사라졌습니다. 일부 모델이 텍스트로 쓰는 도구 호출도 이제 정상적으로 실행됩니다.
- **위험한 변경은 먼저 확인:** "편집 자동 승인"을 켜 두어도 MCP 설정, git hooks, 셸 프로필, 자격 증명 파일 등을 바꾸기 전에는 먼저 묻습니다. Breezell 브라우저의 페이지와 Computer Use가 카메라, 마이크, 화면, 데스크톱을 쓰려 할 때도 먼저 묻습니다.
- **편집기 수정:** "N files changed · Next" 막대가 더 이상 멈추지 않고, AI가 여러 곳을 바꾼 긴 파일을 열어도 창이 멈추지 않으며, 오래 사용해도 메모리가 계속 늘지 않습니다.

### 초보자 가이드

- **누가 보나요:** 아직 자신의 API를 연결하지 않은 새 사용자에게 말풍선으로 이어지는 짧은 가이드가 나타나며, "다음"을 눌러 넘어갑니다. 이미 자신의 API를 쓰는 사용자에게는 자동으로 나타나지 않습니다.
- **무엇을 알려 주나요:** Box, "공식 모델(Breezell)", 자신의 API 키나 중계 서비스를 연결하는 곳, 채팅 입력창 아래에서 모델을 바꾸는 메뉴입니다. 언제든 "건너뛰기"를 할 수 있습니다.
- **다시 보기:** Help 메뉴의 "초보자 가이드"를 엽니다.

### 협업 방식

- **바꾸기 전에 매번 확인:** Breezell은 사용자가 직접 보낸 메시지를 보고 어떻게 일하기를 원하는지(예: "질문을 줄여 달라", "파일을 바꾸거나 명령을 실행하기 전에 먼저 확인해 달라", "답변을 간결하게") 추측합니다. 바꾸기 전에 매번 "좋아요", "그대로 두기", "다시 묻지 않기" 중에서 물어보며, 응답하지 않으면 아무것도 바뀌지 않습니다.
- **"협업 방식" 카드:** Box ▸ 슈퍼 메모리 ▸ 예산 및 유지 관리의 카드에서 현재 선호를 볼 수 있습니다. "지금 추측"은 최근 메시지를 다시 읽고, "초기화"는 알아낸 내용을 지웁니다.
- **개인정보:** 사용자가 직접 보낸 메시지만 읽으며, 결과는 이 컴퓨터에만 저장됩니다.

### 모델

- **Claude Fable 5.2와 Claude Mythos 5.2:** 둘 다 Fast를 포함해 지원합니다.
- **OpenRouter와 Meta:** OpenRouter에 Nex N2.6, Inkling 2 Small(무료), Muse Ember가 추가되었고, Meta에 Muse Ember 1.0이 추가되었습니다.
- **Qwen의 "플랜":** "DashScope"(사용량 기준 결제) 또는 "Token Plan"(구독 요금제)을 고를 수 있습니다.
- **이미지 생성의 Seedream 5.5:** Box와 Image Studio에서 1K, 1.5K, 2K를 고를 수 있고, 투명 배경(PNG로 전달됩니다)과 최대 10장의 참고 이미지를 쓸 수 있습니다.
- **로그인 연결:** Gemini(Google 로그인)와 Kimi Code 로그인의 연결을 각각의 최신 버전에 맞게 업데이트했습니다.

### Box ▸ 모델(OpenAI 호환)

- **여러 개의 키와 주소:** 호환 공급자 하나에 여러 개의 키("키 추가")와 여러 개의 요청 주소("주소 추가", "속도 측정" 가능)를 저장할 수 있습니다. 모델 목록은 선택한 키를 따르고, 각 모델은 그 모델을 가진 키로 전송됩니다.
- **서비스가 더 이상 제공하지 않는 모델:** 목록에서 빠지고 알림이 나오며, "실행 취소"할 수 있습니다. 확실하지 않은 모델은 먼저 물어보며 "유지"를 고를 수 있습니다.
- **모델 ID로 추가:** 모델 검색창에 모델 ID를 바로 입력해 추가할 수 있습니다.

### 프로젝트 그룹

기능 전체는 [프로젝트 그룹과 메모리 공유](/ko/project-group)를 참고하세요.

- **메시지 입력창 위의 그룹 캡슐:** 그룹, 프로젝트 수, 켜진 권한, 같은 그룹의 다른 창에서 AI가 하고 있는 일(대기 중, 작업 중, 사용자를 기다리는 중)이 표시됩니다. 어떤 파일이나 명령을 다루는지는 "대화 공유"를 켜 두었을 때만 보입니다. 펼치면 각 구성원의 상태와 모델을 볼 수 있고, "창으로 이동", 그 대화 보기, "맡기기…", 권한 전환, "그룹 페이지" 열기를 할 수 있습니다.
- **네 가지 AI 권한:** 그룹 페이지의 "AI 권한"이 네 개의 스위치로 바뀌었습니다. "파일 읽기", "파일 수정", "메모리 공유", "대화 공유"입니다. "파일 수정"은 기존의 "AI가 그룹 프로젝트를 수정하도록 허용"을 대신합니다.
- **대화 공유:** "대화 공유"를 켜면 같은 그룹 창의 AI가 서로의 대화 기록을 읽을 수 있습니다. "보기"는 편집기 영역에 읽기 전용 탭을 열며, 닫을 때 저장할지 묻지 않습니다. "다음 메시지에 첨부"는 입력창에 태그를 붙입니다.
- **턴 도중에 그룹을 만든 경우:** 진행 중인 턴도 그룹을 알게 되고, 그 전의 답변에는 그룹이 반영되지 않았다고 알려 줍니다.
- **"외부 파일 접근"을 꺼 둔 경우:** 이 창에서 읽을 수 있는 그룹 프로젝트는 계속 읽을 수 있습니다.
- **수정:**
  - 같은 그룹의 다른 프로젝트에 대해 물으면 AI가 현재 프로젝트에서 검색하고 "일치하는 결과가 없다"고 답했습니다.
  - 하나의 창으로 합친 뒤 AI에게 이 프로젝트가 이미 그룹에 없다고 잘못 전달되었습니다.
  - 다른 환경(예: WSL)에 있는 그룹 프로젝트의 변경이 승인 전에 실행되었고 되돌릴 수 없었습니다. 이제 이런 프로젝트는 읽기와 검색만 하고, 수정은 그 창에 맡기는 제안으로 바뀝니다.
  - "파일 수정"을 꺼 두어도 AI가 전체 경로로 그룹 프로젝트를 수정할 수 있었습니다.
  - 프로젝트 그룹 안의 대화에 제목이 생기지 않았습니다.
- **Cross-Check:** AI가 그룹 프로젝트의 창을 통해 바꾼 파일도 Cross-Check 검사를 받습니다.

### 채팅

- **생각하다 끊긴 답변:** 모델이 출력 한도를 모두 생각에 쓰고 답변을 쓰지 못했을 때는 짧게 생각한 뒤 다시 시도하도록 요청합니다. 그래도 안 되면 멈추고 "추론 강도"를 낮추거나 출력 한도가 더 큰 모델로 바꾸라고 안내합니다. 예전에는 같은 요청을 세 번 다시 보내며 매번 요금이 청구되었고, 마지막에 "the model returned an empty reply 3 times in a row"가 표시되었습니다.
- **텍스트로 쓰인 도구 호출:** 일부 모델(예: 중계 서비스를 통한 Qwen3-Coder, GLM)이 도구 호출을 텍스트로 쓰는 경우에도 이제 정상적으로 실행됩니다. 빈 답변으로 처리되어 멈추지 않습니다.
- **채팅 탭에 끌어다 놓기:** 편집기 탭에서 연 채팅에서 파일이나 폴더를 입력창에 끌어다 놓으면 탭이나 창으로 열리지 않고 메시지에 첨부됩니다.
- **코드 블록:** 코드 블록이 하나의 카드로 바뀌었습니다. 파일 이름, 줄 번호, 버튼이 제목 줄에 나란히 놓이고, 너무 긴 파일 이름은 잘립니다.
- **중지한 뒤:** 중지를 누른 뒤에는 승인을 요청하는 창이 더 이상 뜨지 않습니다. 연결이 도중에 응답하지 않으면 완료가 아니라 답변이 중단되었다고 표시됩니다.
- **더 부드러운 답변:** 일부 중계 서비스의 답변이 한 글자씩 표시되며, 한 번에 통째로 나타나지 않습니다. AI가 아주 긴 내용을 써도 화면이 느려지지 않고, 첨부한 PDF가 매 턴 다시 업로드되지 않습니다.
- **Gemini:** Gemini 네이티브에서 첨부한 이미지, PDF, 도구 스크린샷이 전달됩니다.
- **생각 중에 언급한 도구:** 모델이 생각하는 중에 언급만 한 도구는 실행할 호출로 취급되지 않습니다.
- **수정:**
  - 대화 내용을 고친 뒤 Claude를 계속 쓰면 요청이 거부될 수 있었습니다.
  - 일부 모델에서 도구를 연달아 호출하면 앞선 턴의 결과가 사라졌습니다.

### 편집기

- **"N files changed · Next" 막대:** 멈추거나, 앞뒤로 오가거나, 파일을 건너뛰던 문제를 수정했습니다. "Next"는 막대에 표시된 파일에서 이어서 넘어가며, 파일 하나를 남겨 두면 그다음 파일로 넘어갑니다.
- **긴 파일:** AI가 여러 곳을 바꾼 아주 긴 파일을 열어도 창이 몇 초간 멈추지 않습니다.
- **메모리:** 오래 사용하면 메모리가 계속 늘어나던 문제를 여러 곳에서 수정했습니다.
- **포커스 폴더:** 포커스 폴더 표시가 실행 중인 명령 막대를 더 이상 가리지 않습니다.
- **WSL과 SSH의 포커스 폴더:** Windows에서 WSL이나 SSH 폴더를 "포커스 폴더"로 설정하면 AI가 실행하는 모든 명령이 바로 실패했습니다. 이제 정상적으로 실행됩니다.

### 보안

- **계속 먼저 묻는 변경:** "편집 자동 승인"을 켜 두어도 MCP 설정, git hooks, 자동 실행 작업, 셸 프로필, 규칙과 스킬, 자격 증명 파일을 바꾸기 전과 작업 영역 폴더 전체 또는 작업 영역 밖 폴더 전체를 삭제하기 전에는 먼저 묻습니다.
- **프로젝트의 MCP 서버와 신뢰하지 않는 폴더:** 프로젝트에 포함된 MCP 서버는 실행할 명령을 허용해야 시작됩니다. 명령이 바뀌면 다시 묻습니다. 신뢰하지 않는 폴더에서는 프로젝트의 규칙, 스킬, MCP 서버를 불러오지 않습니다.
- **Breezell 브라우저 안의 페이지:** 페이지가 카메라, 마이크, 위치, 화면 녹화, 클립보드, 연결된 장치를 사용하려 하면 먼저 묻습니다. AI가 쿠키를 읽을 때 HttpOnly 쿠키의 값은 보이지 않습니다.
- **Computer Use:** 클릭, 입력, 앱 실행은 먼저 묻습니다. Box ▸ 기능 옵션 ▸ 도구 권한에서 "데스크톱 작업 자동 승인"을 켠 경우는 제외합니다.
- **메모리:** 메모리에 저장되는 내용에서는 키와 비밀번호 같은 비밀 정보가 먼저 제거됩니다. Windows 줄바꿈 형식의 메모리 파일에서 메모리가 누락되던 문제를 수정했습니다.
- **삭제와 가져오기:** 스킬을 삭제하기 전에 먼저 확인합니다. 대화를 삭제하면 그 대화를 위해 Breezell이 저장한 파일만 삭제됩니다. 대화 백업을 가져올 때 유효하지 않거나 내용이 없는 대화는 건너뛰고 알려 줍니다.

### 플러그인

- **제거할 때:** 플러그인을 제거하면 그 플러그인이 연 창도 함께 닫힙니다.
- **떠 있는 창:** Breezell을 최소화했을 때 플러그인이 다른 앱 위에 띄우는 창(예: "활동 아일랜드")의 위치가 어긋나던 문제를 수정했습니다.
- **슬래시 명령:** 플러그인이 잠시 메시지를 받지 않는 동안에는 그 플러그인의 슬래시 명령이 전송되지 않으며, "플러그인 ▸ 설치됨"에서 확인하라고 안내합니다.

## 1.4.54 · 핫 업데이트 · 2026-11-09

1.4.5용 핫 업데이트로, 다시 설치할 필요가 없습니다. Breezell이 알아서 제공하며, Box 사이드바 하단의 「업데이트」에서 확인할 수도 있습니다.

### 프로젝트 그룹

- **대화 중 그룹 제안:** 대화에서 열려 있는 다른 프로젝트(이름, 경로, 파일, API 경로나 포트)를 언급하면 입력창 위에 "이 프로젝트들을 한 그룹으로 묶을까요?"가 나타나고, 언급한 프로젝트에는 이미 체크가 되어 있습니다. "그룹으로 묶기" 또는 "그룹으로 묶고 하나의 창으로 합치기"를 누르거나, "이번에는 안 함" 또는 "이 프로젝트들은 다시 묻지 않기"를 고를 수 있습니다. 누르지 않으면 아무것도 바뀌지 않고 AI는 평소처럼 답합니다.
- **그룹 페이지:** "프로젝트 그룹과 메모리 공유"가 편집기 영역의 탭으로 열립니다. 탐색기 위쪽 "현재" "전체" 옆의 버튼으로 엽니다. "Folders" 보기를 탐색기 밖으로 옮겼다면 그 제목 표시줄에도 같은 버튼이 있고, 명령 팔레트에서도 열 수 있습니다.
- **구성원의 위치:** 탭에는 각 구성원이 어느 환경(Windows, WSL, SSH)에 있는지, 창이 열려 있는지, 닫혀 있지만 여기서 파일을 읽을 수 있는지, 닫혀 있는지가 표시됩니다. 닫힌 구성원 옆에는 "열기"가 있습니다.
- **프로젝트 추가:** "열린 창 추가" 또는 "폴더를 골라 그룹에 추가…"로 추가할 수 있습니다. 폴더의 창을 먼저 열어 둘 필요는 없습니다.
- **그룹 관리:** 그룹 이름 바꾸기, "그룹 나가기", "그룹 해제"(두 번 눌러야 해제)를 할 수 있습니다. 그룹에 속해 있지 않으면 여기서 그룹을 만들거나 다른 그룹에 들어갈 수 있습니다.

### 그룹 프로젝트와 함께 작업

- **그룹 프로젝트 읽기:** AI는 그룹에 어떤 프로젝트가 있는지 알고, 그 프로젝트를 언급하면 파일을 읽을 수 있습니다. 다른 환경의 프로젝트(예: Windows 창에서 본 WSL 프로젝트)는 그 창이 열려 있을 때 읽을 수 있고, 열려 있지 않으면 열도록 안내합니다.
- **그룹 프로젝트 수정:** "AI가 그룹 프로젝트를 수정하도록 허용"을 켜면 AI가 그 프로젝트의 파일을 수정하고 그 폴더에서 명령을 실행할 수도 있습니다. 기본값은 꺼짐입니다.
- **대화 공유:** "대화 공유"를 켜면 "그룹 프로젝트의 대화…"에서 다른 프로젝트의 대화를 "보기", "이 창에서 이어서 대화", "다음 메시지에 첨부"할 수 있습니다. "그룹 프로젝트에 맡기기…"는 작업을 다른 프로젝트의 창에 맡기고, 끝나면 알려 줍니다.
- **하나의 창:** "하나의 창으로 합치기"는 그룹의 프로젝트를 여러 폴더가 있는 하나의 창으로 엽니다. Windows 프로젝트와 WSL 프로젝트도 함께 합칠 수 있습니다. 원래 창은 닫히고 대화는 복사되며, 제목 앞에 어느 프로젝트의 대화인지 표시됩니다. "별도의 창으로 나누기"로 다시 나눌 수 있습니다.

### 채팅

- **채팅 탭과 코드 탭을 같은 줄에:** 채팅 탭을 코드 탭과 같은 줄에 둘 수 있습니다. 기록에서 파일 탭 줄로 끌어온 대화, "편집기 탭에서 열기", 채팅 탭의 "New Chat"이 놓은 자리에 그대로 있고, 다른 열로 옮겨지지 않습니다.
- **대화 기록의 제목과 시간 수정:** 여러 폴더가 있는 작업 영역에서 연 적이 있는 프로젝트를 따로 열면 대화 제목이 첫 문장으로 바뀌고 시간이 모두 연 시각으로 바뀌었습니다. 이제 각 프로젝트의 대화는 원래 제목과 시간을 유지합니다.

### WSL

- **빈 창 수정:** 바로 가기로 WSL 프로젝트를 열면 가끔 창에 아무것도 표시되지 않았습니다(탐색기가 비어 있고, 소스 제어에 "No source control providers registered"가 표시됨). 이제 정상적으로 연결되어 프로젝트가 표시됩니다.

  - 여러 대화가 함께 진행 중이면 「+2」 같은 숫자. 지금 열어 둔 대화가 그중에 있으면 먼저 표시됩니다.

- **확인 대기:** AI가 답변이나 승인을 기다리며 멈추면 캡슐에 「확인을 기다리는 중」(여러 개이면 「대화 3개가 확인을 기다리는 중」)이 표시되고, 「보기」를 누르면 그 대화가 열립니다. 확인을 기다리는 대화가 작업 중인 대화보다 먼저 표시됩니다.
- **완료 또는 오류:** 턴이 끝나면 「완료」와 걸린 시간(「1:23 소요」)이 몇 초 동안 표시됩니다. 오류로 끝난 턴은 「오류가 발생했습니다」가 표시되고, 「보기」로 그 대화를 열 수 있습니다. 직접 중지한 턴은 아무것도 표시하지 않습니다.
- **빌드와 테스트 작업:** 빌드나 테스트처럼 실행한 작업은 「build 실행 중」과 시간을 표시합니다. 끝나면 「build 완료」와 걸린 시간을, 실패하면 「build 실패」와 종료 코드를 표시하며, 「보기」로 그 터미널을 엽니다. 백그라운드에서 계속 실행되는 감시 작업은 표시되지 않으며, 직접 중지한 작업도 표시되지 않습니다.
- **AI 작업 중의 작업:** AI가 일하는 동안 작업이 실행되면, 작업은 캡슐 오른쪽의 작은 점으로 표시됩니다. 마우스를 올리면 이름이 보이고, 클릭하면 터미널이 열립니다.
- **업데이트와 알림을 한곳에:**
  - 새 버전으로 업데이트하는 진행 상황(확인, 다운로드, 설치)과 업데이트가 있을 때의 버튼이 옆의 별도 표시 대신 캡슐에 나타납니다.
  - 알림 벨은 캡슐 끝에 있고, 알림 패널은 캡슐에서 펼쳐졌다가 캡슐로 돌아갑니다. 동작 줄이기를 켜 두면 패널이 바로 나타납니다.
  - 디버그 도구 모음이 같은 자리에 있는 동안에는 디버그 버튼을 쓸 수 있도록 캡슐이 평소 상태로 유지됩니다.
- **관리자 권한으로 실행할 때:** 작업 영역 이름 뒤에 방패 아이콘이 표시되며, 이름을 밀어내던 글자는 더 이상 나오지 않습니다.
- **키보드:** 알림 벨에서 Enter나 Space를 누르면 검색 대신 알림이 열리고, 캡슐 안의 버튼도 Enter와 Space로 쓸 수 있습니다.

### AI의 파일 수정

- **경로가 조금 달라도 「파일을 읽을 수 없음」으로 끝나지 않음:** AI가 존재하지 않는 경로의 파일을 수정하려 할 때(예: 폴더 하나를 빠뜨렸을 때) 지금까지는 읽기 오류만 받고, 탐색기에는 파일이 있는데도 열 수 없다고 알려 주었습니다. 다시 시작해야만 되는 것처럼 보일 때도 많았습니다. 이제는:
  - AI가 그 경로가 없다는 것과 작업 영역에 같은 이름의 파일이 무엇이 있는지 알게 되어, 올바른 파일을 수정합니다.
  - 그 이름의 파일이 작업 영역에 없으면 다른 폴더를 계속 짐작하지 않고 파일이 어디 있는지 물어봅니다.
  - 새 파일을 만들려던 것이라면 그대로 만듭니다.
- **Windows: 이유 없이 실패하던 AI 수정이 이제 진행됨:** Windows에서 문제가 없는데도 AI의 수정이나 새 파일이 거부되는 경우가 있었습니다. 이제는 AI가 쓴 그대로 처리됩니다. 이전에는:
  - 내용이 잘린 것으로 처리되어, AI가 수정을 더 작게 나누어 계속 다시 시도했지만 똑같이 실패했습니다.
  - 또는 한 번의 호출에서 서로 다른 두 파일을 가리킨다고 거부되거나, 열 수 없는 경로에 쓰였습니다.

## 1.4.51 · 핫 업데이트 · 2026-11-06

1.4.5용 핫 업데이트로, 다시 설치할 필요가 없습니다. Breezell이 알아서 제공하며, Box 사이드바 하단의 「업데이트」에서 확인할 수도 있습니다.

### 채팅

- **스크린샷이 많은 긴 대화도 계속 이어집니다:** 한 대화에서 스크린샷을 많이 보낸 뒤에는 메시지가 전송되지 않을 수 있었고, 오류에는 `NGHTTP2_ENHANCE_YOUR_CALM`이 나오는데 진단은 네트워크 탓으로 돌렸습니다. 이제:
  - 앞서 붙여넣은 이미지가 그 뒤의 메시지를 더 이상 무겁게 하지 않으므로 대화를 계속할 수 있습니다.
  - AI가 이전 이미지를 다시 봐야 할 때는 기억에 의존해 설명하지 않고 그 이미지를 다시 엽니다.
  - 메시지에 첨부한 이미지는 항상 전송되며, 편집하거나 다시 보내는 메시지의 이미지도 마찬가지입니다.
- **AI가 연 이미지도 마찬가지입니다:** AI가 보려고 연 이미지가 더 이상 대화의 나머지 부분과 함께 남아 있지 않고, AI는 필요할 때 그 이미지를 다시 엽니다. 여러 이미지를 한꺼번에 열면 모든 이미지를 봅니다.
- **표가 채팅 너비에 맞춰 줄바꿈됩니다:** 답변의 표가 가장 긴 행만큼 넓어져서 옆으로 스크롤해야 했습니다. 이제 채팅 너비에 맞춰 줄바꿈됩니다:
  - 머리글은 단어 사이에서만 줄이 바뀌고, CJK 레이블은 끊기지 않습니다.
  - 표 안의 경로와 이름이 한 줄에 한 글자씩 찌그러지지 않습니다.
  - 한 단어가 채팅보다 넓을 때만 표가 옆으로 스크롤됩니다.
- **굵은 제목이 위 문단에 붙지 않습니다:** 답변에서 한 줄을 차지하는 「(2) ...」나 「(3) ...」 같은 굵은 제목이 앞 문단 끝에 붙었고, 문장 안의 굵은 구절 앞 공백이 사라졌습니다(「this is **important**」가 「this isimportant」로 보였습니다). 둘 다 수정되었습니다.
- **스트리밍 중에도 굵은 제목의 간격이 같습니다:** 답변이 아직 스트리밍되는 동안에는 한 줄짜리 굵은 제목이 답변이 끝날 때까지 본문과 넓게 떨어져 있었습니다. 이제 스트리밍 중에도 최종 간격으로 표시되며, 사고 텍스트에서도 마찬가지입니다.
- **긴 대화에서 구분선 끌기가 더 부드럽습니다:** 대화가 길어져도 채팅 크기 조절이 느려지지 않습니다.

### Box

- **시작할 때 Box 페이지가 더 이상 비어 있지 않습니다:** Box 페이지에서 Breezell을 닫으면 다음에 열 때 왼쪽 탐색만 있고 그 옆은 비어 있었습니다. 이제 마지막으로 보던 페이지로 열립니다.

### 인터페이스

- **「Breezell 새 UI」 미리보기가 워크벤치 축소판으로 바뀌었습니다:** 제목 표시줄 테마 패널에 있는 「Breezell 새 UI」 카드의 미리보기는 회색 블록 세 개였습니다. 이제 사용 중인 테마의 색으로 그린 축소판입니다: 메뉴가 있는 제목 표시줄, 작업 표시줄, 탐색기, 탭·코드·커서·미니맵이 있는 편집기, 터미널, Breezell 채팅, 상태 표시줄. 켜면 각 부분이 떠 있는 둥근 카드이고, 끄면 각지고 서로 맞붙어 가는 선으로 나뉘므로 둘을 쉽게 구분할 수 있습니다.
- **모든 구분선 손잡이의 밝기가 같습니다:** 탐색기 옆 구분선의 점 세 개 손잡이가 다른 것보다 밝아 보였습니다. 이제 모두 같아 보이며, 끌기는 바뀌지 않았습니다.
- **구분선 강조가 강조 색상을 따릅니다:** 테마 패널에서 「강조 색상」을 고르면 구분선에 마우스를 올리거나 끌 때 그 강조 색상으로 강조선이 표시되고, 강조 색상을 재설정하면 지워집니다. 각 테마의 기본 구분선 강조는 다음 전체 설치 프로그램과 함께 제공됩니다.

### WSL, SSH와 원격

- **WSL과 SSH 창에서 AI가 Breezell이 저장해 둔 파일을 열 수 있습니다:** Breezell은 긴 터미널 출력이나 MCP 도구의 이미지 같은 것을 AI가 필요할 때 읽을 수 있도록 파일로 저장합니다. WSL과 SSH 창에서는 AI가 이 파일을 열 수 없었습니다. 이제:
  - 이 파일은 워크스페이스의 `.breezell/tool-results` 폴더에 보관되며, 읽기 도구, 터미널, 스크립트 모두 접근할 수 있습니다.
  - Git과 검색이 이 폴더를 스스로 무시하므로 `git status`, 커밋, 검색 결과에 나타나지 않으며, `.gitignore`를 바꿀 필요가 없습니다.
  - 열린 폴더가 없으면 이전처럼 홈 폴더에 보관됩니다.
- **포트 보기가 시간이 지나도 메모리를 더 쓰지 않습니다:** 포트 보기가 열려 있는 동안 목록이 갱신될 때마다 메모리를 조금씩 더 차지했습니다. 이제 그렇지 않습니다.

### 모델

- **OpenRouter Auto Router:** `openrouter/auto`는 OpenRouter가 모델을 고르게 하며, 각 요청은 고른 모델의 가격으로 청구되므로 정가가 없습니다. 이미지·동영상·오디오 입력, 도구, 2M 컨텍스트. 사고는 꺼진 상태로 시작하며, 켜면 low, medium, high로 설정할 수 있습니다.

- **플러그인이 할 수 있는 일:**
  - 스킬, 규칙, MCP 서버를 추가합니다. 이름이 같으면 사용자의 스킬이나 서버가 우선합니다.
  - Agent에 도구를 제공하고, 어떤 모드에서 제공할지 정합니다(「채팅」, 「에이전트」, 「얽힘」, 「분석」, 「팀」). 이 도구도 사용자의 승인이 필요하며, 자체 도구 카드를 갖습니다. 플러그인은 Agent의 도구 호출을 실행 전에 살펴보고 거부할 수도 있습니다.
  - 자체 창을 엽니다. 이 창은 편집기 창 없이도 시작할 수 있습니다. 플러그인 상세 페이지의 「창」 카드에는 바로 가기를 만드는 「시작 메뉴에 추가」(Windows), 「애플리케이션 메뉴에 추가」(Linux), 「응용 프로그램에 추가」(macOS)가 있습니다. macOS에서는 플러그인 창도 다른 창처럼 ⌘Z, ⌘A, ⌘W를 받습니다.
  - Breezell 화면을 바꿉니다: 버튼과 메뉴 항목, 슬래시 메뉴의 명령, 자체 페이지, 일부 영역의 대체, 특정 언어의 코드 블록을 직접 그리기, 새 모드, 채팅 입력창 위에 떠 있는 동반자, 「기능 옵션」의 설정 카드(Box 검색으로 찾을 수 있습니다). 색, 글꼴, 모양을 바꾸고, 플러그인 자체 설정으로 이를 전환할 수도 있습니다.
  - 대화를 읽고, 대화에 메시지를 보내고, 도구 호출을 승인하고, 채팅 모델을 사용하거나 전환하고, 자신의 텍스트를 Breezell의 인터페이스 언어로 표시하고, Breezell을 다시 시작하도록 요청합니다.
  - 입력기 플러그인: 후보 패널을 코드 편집기와 채팅 입력창에 표시할 수 있습니다. 다른 곳을 클릭하거나, 포커스가 벗어나거나, 입력기가 꺼지면 패널이 닫히고, 입력을 확정한 뒤 제시되는 단어는 저절로 사라집니다. 긴 후보는 채팅 입력창 밖으로 넘치지 않고 줄바꿈됩니다.
  - 플러그인 개발자가 쓸 수 있는 기능과 그에 필요한 권한은 「개발」 페이지의 「개발자 가이드」에 있습니다.
- **플러그인이 건드릴 수 없는 것:** 로그인, 플랜, 할당량, 결제, 사용자 지정 API 설정, 권한 대화 상자, 도구 승인, 플러그인 페이지는 플러그인이 바꿀 수 없으며, 사용자의 응답을 기다리는 항목은 항상 플러그인 화면 위에 표시됩니다. 어느 창에서든 로그아웃하거나 플러그인이 차단되면 그 플러그인이 추가한 것은 즉시 사라집니다.
  - 플러그인의 버튼에는 「플러그인 제공: 이름」이 표시됩니다. 버튼을 오른쪽 클릭하면 「이 버튼 숨기기」나 「플러그인 관리」를 고를 수 있고, 플러그인 상세 페이지의 「숨긴 버튼 표시」로 되돌릴 수 있습니다. 플러그인이 대체한 화면에는 「Breezell 기본 화면 보기」가 있습니다.
- **권한:** 플러그인은 필요한 권한을 선언하며, 선언하지 않은 것은 사용할 수 없습니다. 일반 권한(대화 턴이 언제 시작되고 끝나는지 알기, 채팅 모델 전환, 버튼 추가 등)은 기본으로 켜져 있습니다. 위험한 권한(채팅 모델 사용, 대화 읽기, 메시지 보내기, 도구 호출 승인, 코드나 채팅 입력창 읽기, 보내기 전에 메시지 수정, 사용자 지정 API 키 읽기 등)은 플러그인이 처음 사용할 때 묻고, 그 답은 기억됩니다.
  - 플러그인 상세 페이지의 「권한」에는 각 권한의 종류(「자동」 또는 「먼저 물어봄」), 상태(「켜짐」, 「꺼짐」, 「처음 사용할 때 물어봄」), 스위치가 나열되며, 「모두 켜기」와 「모두 끄기」가 있습니다. 설치된 플러그인의 마켓 상세 정보에도 같은 스위치가 있습니다.
  - 설치 대화 상자에는 체크되지 않은 확인란이 있습니다: 「요청하는 모든 권한을 지금 허용합니다(처음 사용할 때 묻지 않음)」.
  - 사용자 지정 API 키 읽기는 플랜에 Custom API가 포함된 계정에서만 동작합니다.
  - 제거하면 플러그인의 권한이 기본값으로 초기화됩니다.
- **업데이트와 제거:**
  - 마켓에서 설치한 플러그인에 새 버전이 나오면 Breezell이 한 번 알리고, 「버전(으)로 업데이트」(여러 개일 때는 「모두 업데이트」)와 「보기」를 제공합니다.
  - 실행 중인 플러그인을 업데이트하거나 제거한 뒤에는 확장 호스트가 다시 시작될 때까지 이전 버전이 계속 실행됩니다. Breezell이 이를 알리고 「확장 호스트 다시 시작」을 제공합니다. 한 세션에서 플러그인을 제거했다가 다시 설치할 때도 마찬가지입니다.
  - 「제거」는 마켓 카드, 상세 정보, 「설치됨」에 있으며, 먼저 확인을 묻습니다. 플러그인이 추가한 스킬, 규칙, MCP 서버, 창은 함께 제거되고, 그 설정은 남습니다.
  - 플러그인은 설치, 업데이트, 제거 후에 플러그인, 창 또는 Breezell 전체를 다시 시작하도록 요청할 수 있으며, 설치 대화 상자는 이를 맨 먼저 보여 줍니다. 실행 중인 플러그인이 다시 시작을 요청하면 「지금 다시 시작」이나 「나중에」를 고릅니다. 묻지 않고 다시 시작하려면 사용자의 허락이 필요하며, 버전마다 최대 한 번만 일어나고, 작성 중인 답변이 끝날 때까지 기다리며, 미리 알립니다.
- **차단 목록:** 마켓 관리자는 해로운 것으로 드러난 플러그인을 차단할 수 있습니다. 차단된 플러그인은 꺼지고, 실행 중이던 플러그인은 즉시 멈추며 그 창이 닫힙니다. Breezell은 한 번 알리고 제거를 제안합니다. 마켓에서 더 이상 보이지 않고, 설치하거나 다시 켤 수 없으며, 「설치됨」에는 「차단됨」과 그 이유가 표시됩니다.

### 채팅

- **창이 충돌해도 채팅 기록이 남습니다:**
  - 충돌한 빈 창을 다시 열어도 더 이상 채팅 기록을 잃지 않습니다. 이런 충돌 뒤 「New Window」는 종료되지 않고 실제로 창을 엽니다.
  - 세션이 정상적으로 닫히지 않았으면 Breezell이 이를 알리고(「The window closed unexpectedly last time…」), 보고 있던 대화를 다시 여는 「Open Conversation」을 제공합니다. 대화가 저절로 열리지는 않습니다. 정상 종료 뒤에는 더 이상 이 알림이 나오지 않습니다.
  - 디스크가 바쁘거나 가득 차도 워크스페이스의 대화가 모두 빈 상태로 열리지 않습니다.
- **오래된 긴 대화가 제대로 동작합니다:**
  - 이전 형식의 긴 대화가 처음 저장될 때 더 이상 메시지를 잃지 않습니다.
  - 아주 오래된 긴 대화를 열어도 메모리 부족으로 창이 충돌하지 않습니다.
  - 다시 연 대화의 최신 턴에 빈 공간이 보이지 않습니다.
- **되돌리기가 파일을 비우지 않습니다:** 되돌리기에서 파일의 백업을 찾지 못하면 이전에는 그 파일을 빈 상태로 다시 썼습니다. 이제 백업이 없다고 알리고 그 파일은 그대로 둡니다. 다른 파일은 평소처럼 되돌려집니다.
- **대화를 삭제해도 분기가 깨지지 않습니다:** 다른 대화에서 분기하거나 복사한 대화는 원본이 삭제되거나 정리된 뒤에도 되돌릴 수 있습니다.
- **Claude 4.6 이후에서 더 이상 400이 나오지 않습니다:** Anthropic 형식의 사용자 지정 슬롯에서, 긴 대화의 답변이 잘린 뒤 Claude 4.6+가 「This model does not support assistant message prefill」로 응답했습니다. 이제 이런 일이 없습니다. 긴 대화의 답변도 더 이상 일찍 잘리지 않습니다.
- **의도한 첨부만 전송됩니다:** 입력창에 대기 중인 이미지가 후속 제안, 대기열 메시지, 계획의 프롬프트, 플러그인의 메시지와 함께 전송되지 않습니다. 편집하려고 연 대기열 메시지가 이미지를 두 번 보내지 않습니다. 비전을 지원하지 않는 모델에서 후속 제안을 클릭해도 반응이 없는 일이 없어졌습니다.
- **슬래시 메뉴:** 슬래시 메뉴가 열린 동안 입력한 내용이 입력창에 남으므로 Esc를 눌러도 잃지 않고, 일치하는 명령이 없을 때 Enter를 누르면 메시지가 전송됩니다. 이제 /로 시작하는 메시지를 보낼 수 있습니다. 입력기 후보가 입력창에서 열리는 메뉴 아래에 가려지지 않습니다.
- **채팅의 수식:** 수식이 올바른 글꼴로 그려지므로 노름의 이중 세로선이 두 개의 슬래시로 보이지 않습니다. Windows에서 LaTeX 코드 블록의 첫 줄이 사라지지 않고, 한 줄짜리 블록도 표시됩니다.
- **채팅에서 언급된 파일이 열립니다:**
  - WSL 및 SSH 원격 창과 다중 폴더 워크스페이스에서 채팅의 파일 카드와 링크가 「파일을 찾을 수 없음」으로 열리지 않습니다.
  - 답변의 경로에 `:42`, `#L42`, `#L42-L50`이 붙어 있으면 그 줄에서 열립니다.
  - 답변에서 언급된 폴더: 워크스페이스 밖에 있으면 시스템 파일 관리자에서 열리고, 안에 있으면 탐색기 보기에서 표시됩니다. 압축 파일 같은 바이너리 파일은 더 이상 텍스트 편집기에서 열리지 않고 메뉴가 나타나며, 첫 항목인 「열기」가 시스템 앱에 넘깁니다.
  - 채팅에서 복사한 경로에 보이지 않는 문자가 섞이지 않습니다.
- **Cross-Check가 실제로 기본 꺼짐:** 기존 설치에서는 Cross-Check를 한 번 끕니다. 그 뒤에 켜면 켜진 상태로 유지됩니다.
- **작은 채팅 수정:**
  - 보이지 않는 문자로만 된 답변(Kimi K3.1 Pro가 이런 답변을 보내기도 합니다)이 빈 행으로 표시되지 않습니다.
  - 모델이 작성하는 중에 중지한 턴은 후속 제안이나 Cross-Check를 불러오지 않습니다.
  - 같은 도구를 연달아 여러 번 호출하면 접힌 헤더가 개수만이 아니라 무엇이었는지(예: 어떤 스킬을 사용했는지)를 보여 줍니다.
  - 시작 페이지의 제안이 더 이상 쓰지 않는 `.breezellrules` 대신 `.breezell/rules/breezell.md`를 만듭니다.

### Agent 도구

- **터미널 명령:**
  - 개발 서버처럼 스스로 끝나지 않는 명령은 턴을 붙잡지 않고 즉시 백그라운드로 갑니다.
  - 다른 명령도 이유 없이 오래 멈춰 있지 않습니다.
  - 명령 카드에 「백그라운드로」가 있습니다: 명령은 계속 실행되고 턴은 이어집니다.
  - 백그라운드 명령이 끝나면 AI가 항상 압니다. 사용자가 명령을 중지하면, 쉬고 있던 AI는 중지를 확인했다고 말하고 그 명령을 다시 실행하지 않습니다.
  - 완료 소리, 음성, 시스템 알림은 작업이 실제로 끝날 때까지 기다립니다: 명령이 아직 실행 중인 채로 끝난 턴은 조용히 있다가, 그 명령이 끝나면 한 번 알려 줍니다.
  - AI가 직접 중지한 명령은 카드에 사용자가 중지했다고 쓰지 않고 「[Stopped by the agent]」로 표시되며, AI는 아무도 하지 않은 중지에 대해 더 이상 묻지 않습니다.
  - 끝난 터미널 카드에 다음 명령의 「열기」와 「중지」가 더 이상 나타나지 않고, 이 버튼들 때문에 카드가 높아지지 않습니다.
- **AI의 검색이 프로젝트에 있는 것을 찾습니다:**
  - 파일 이름 검색은 대소문자를 구분하지 않습니다. 이전에는 Windows에서 `readme.md`로 `Docs/README.md`를 찾지 못했습니다.
  - AI의 검색은 `build`, `out`, `dist` 같은 폴더나 로그, 이미지 같은 파일을 항상 건너뛰는 대신, 프로젝트의 `.gitignore`와 Search: Exclude 설정에 따라 무엇을 건너뛸지 정합니다.
  - Git을 쓰지 않는 프로젝트(SVN, Perforce, Plastic, 또는 압축을 푼 사본)도 전체를 검색하지 않고 무시 규칙을 적용합니다.
  - Unity, Unreal, Godot 프로젝트는 엔진이 생성하는 폴더를 건너뜁니다.
  - 날짜나 버전 번호가 들어간 파일 또는 폴더 이름(예: `2024-10-29-notes.md`)의 검색 결과가 엉뚱한 파일을 열지 않습니다.
- **코드 조회:** AI가 더 많은 언어에서 함수와 클래스를 찾습니다: Lua, Go 타입, C# 구조체, 클래스 밖에서 정의된 C++ 메서드, Ruby, Kotlin, Dart, Scala, Solidity, Elixir, OCaml, Objective-C. 다중 폴더 워크스페이스에서는 코드 조회가 첫 번째 폴더만이 아니라 모든 폴더를 다룹니다.
- **AI가 끝없이 검색하지 않습니다:** AI가 파일을 하나도 열지 않고 새 단어로 계속 검색하면 턴이 멈추고 그 이유를 알립니다.
- **AI가 설정을 찾아 줍니다:** 어떤 설정이 어디 있는지 물으면 AI가 Box에서의 위치를 인터페이스 언어로 알려 주거나, 그 옵션을 표시한 채 Box를 엽니다. 「채팅」 모드에서 사용할 수 있습니다. 설정으로 안내하는 오류도 Box의 올바른 위치를 알려 줍니다.
- **기타:**
  - AI가 이미 적용된 편집을 계속 다시 보내지 않습니다.
  - 아주 긴 파이프라인 명령이 턴이 끝날 때 창을 멈추게 하지 않습니다.
  - 새 내장 스킬: HyperFrames 스킬과 Office 문서 스킬. Superpowers 스위치는 자체 스킬에만 적용됩니다.

### 메모리

### Teams

- **승인 카드에서 팀원마다 모델 고르기:** 「Teams 자동 승인」이 꺼져 있으면 새 팀은 승인 카드에서 기다립니다. 이제 각 구성원 행이 모델 메뉴(「이 팀원의 모델」)이며, 실제로 실행될 모델로 설정되어 있습니다. 이전에는 카드가 읽기 전용 미리보기여서 실제로 실행된 모델과 다른 모델을 표시할 수 있었습니다. 선택한 모델은 다시 불러온 뒤에도 유지되며, 카드, 시스템 알림, 알림의 링크 중 어디서 승인하든 적용됩니다. 자동 승인이 켜져 있으면 달라지는 것이 없습니다: 카드 없이 팀이 바로 시작됩니다.
- **다른 모델로 팀원 다시 시도:** 팀원의 오류 카드에는 다시 시도 옆에 모델 메뉴(「다시 시도에 쓸 모델」)가 있으며, 고른 모델이 이후 그 팀원의 모델이 됩니다.
- **팀원에게 직접 메시지 보내기:** 지금까지 잠겨 있던 팀원 페이지의 입력창이 이제 그 팀원에게 메시지를 보냅니다. 메시지는 현재 단계를 멈추지 않고 팀원의 다음 단계 전에 읽히며, 유휴 상태이거나 완료, 실패, 중지된 팀원을 깨웁니다.
  - 대기 중인 메시지는 입력창 위의 대기열 바에 단계마다 하나씩 놓이며, 팀원이 읽기 전까지 「보내기 취소」로 거둘 수 있습니다.
  - 보내기를 취소한 메시지는 대화에 나타나지 않고 리드에게 전달되지도 않습니다.

### 네트워크와 안정성

- **답변이 더 빨리 시작됩니다:** 첫 단어가 약 0.65초가 아니라 약 0.4초 만에 나오고, 보낼 때 더 이상 2~3초를 더 기다리지 않습니다. 잠시 쉬었다가 보내거나 실행 직후에 보내는 첫 메시지도 마찬가지입니다.
- **채팅 요청이 실패할 때의 재시도를 직접 설정:** Box ▸ 성능 ▸ 네트워크와 대화의 「첫 바이트 시간 제한」 아래에 「채팅 요청 실패 시 자동 재시도」가 있습니다.
  - 「기본값」은 오류 종류에 따라 횟수를 정하고, 「재시도 안 함」은 오류 카드를 바로 표시합니다. 횟수를 고르거나, 「사용자 지정」으로 1–20회를 정할 수도 있습니다.
  - 로그아웃되었거나 크레딧이 없는 경우처럼 재시도로 해결되지 않는 오류, 이미 표시된 답변, 중지를 누른 뒤의 모든 것은 재시도하지 않습니다.
- **끊긴 연결의 오류가 더 빨리 표시됩니다:** 연결이 계속 끊기면 이제 거의 30초가 아니라 약 5초 만에 오류가 표시됩니다.
- **하위 에이전트와 긴 대화의 비용이 줄었습니다:** 하위 에이전트와 긴 대화를 실행하는 데 드는 비용이 줄었습니다. Claude와 Gemini의 하위 에이전트도 더 이상 각 파일의 앞부분만 읽지 않습니다.

### 이미지와 동영상

- **GPT Image 2.6:** `gpt-image-2.6-sunburst`와 `gpt-image-2.6-flare`가 OpenAI, OpenRouter, Image Studio에 추가되었으며, 2.5에 있는 모든 기능(최대 3:1 비율, 1K / 2K / 4K, xhigh와 max 품질, 투명 배경)을 갖습니다.
  - 「복잡도」(「낮음」, 「중간」, 「높음」, 기본은 높음): Box에서 설정하며, AI가 채팅에서 그릴 때 직접 정할 수도 있습니다.
  - SVG 출력(새 이미지만, 한 번에 한 장)과 GIF: 2–16프레임(「GIF 프레임 수」), 프레임당 20–2000 ms(「프레임 시간」), 프레임당 약 512 × 512, 마스크와 함께 쓸 수 없음. 둘 다 투명 배경을 지원하지 않습니다.
  - ChatGPT 로그인으로도 GIF를 만들 수 있지만, OpenAI가 아직 모든 계정에 이 기능을 열지 않아 일부 계정은 거부됩니다. Box가 이를 알려 줍니다.
  - Image Studio는 모델이 받는 형식을 SVG와 GIF를 포함해 제공합니다. SVG는 갤러리에 표시되고, SVG나 GIF를 복사하면 그 PNG가 복사되며, 저장 대화 상자에서 .svg를 고를 수 있습니다.
- **이미지 모드가 「다시 해 줘」를 이해합니다:** 이전에는 이미지 뒤에 「이건 별로야」라고 하면 관계없는 새 이미지가 나왔습니다. 이제 자체 이미지가 없는 메시지는 바로 앞의 이미지를 편집합니다. 「이건 별로야, 온라인에서 참고 자료를 찾아봐」처럼 그리기 이상을 요구하는 메시지는 이미지 모드를 끄고 채팅 모델로 갑니다.
- **「이 이미지 편집」은 채팅 모델로 갑니다:** 일반 채팅에서 이미지 카드의 「이 이미지 편집」이나 「영역 편집」을 눌러도 채팅이 이미지 모드로 바뀌지 않습니다. 이미지가 입력창에 들어가고 채팅 모델이 사용자의 지시를 받습니다: 먼저 자료를 찾아본 뒤 그 이미지를 참고로 그릴 수 있습니다. 채팅이 이미 이미지 모드이거나 채팅 모델이 할 수 없을 때는 여전히 이미지 모드가 편집을 맡습니다.
  - 카드에 이미지 모델용으로 작성된 긴 프롬프트가 더 이상 표시되지 않고, 상세 정보에는 이미지 파일만 나열됩니다.
  - Breezell이 그린 이미지에는 모델 행에 Breezell이 한 번만 표시됩니다.
- **어떤 모델이든 자체 이미지 인식 모델을 가질 수 있습니다:** Box ▸ 모델에서 모델의 고급 설정 ▸ 이미지에 「모델이 직접 이미지 인식」 스위치와 「이미지 인식 모델」 선택기가 있으며, 바로 적용됩니다. 스위치를 끄면 첨부한 이미지를 선택한 모델이 대신 읽습니다. Box는 이 모델을 텍스트 전용으로 표시하고, 메뉴에 「비전 프록시」가 있습니다.
  - 비전 프록시가 설정되어 있으면 「비전 프록시」 대화 상자에 「비전 프록시 제거」가 있습니다. 이전에는 비전 프록시를 끄는 방법을 찾기 어려웠습니다.
- **Image Studio:**
  - 각 API 프로파일의 이미지 API와 동영상 API는 각자 네트워크 경로를 가질 수 있습니다: 「직접 연결」, 「시스템 프록시」, 「전역 프록시」, 「사용자 지정 프록시」(HTTP / HTTPS / SOCKS5, 사용자 이름과 비밀번호 포함, 또는 URL로 붙여넣기). 기본값은 계속 시스템 프록시입니다. 모델 목록 가져오기도 그 경로를 쓰며, 실패하면 이유를 알려 줍니다.
  - ID로 모델을 추가할 수 있으며, 목록을 다시 가져와도 남습니다.
  - MiniMax H3가 중계 서비스를 통해 동작합니다.
  - Riverflow V2.6 Pro: Box ▸ 모델 ▸ 이미지 생성의 OpenRouter 아래와 Image Studio에 있습니다(1K / 2K / 4K, 참고 이미지 최대 10장).
  - Gemini Omni 1.1 Flash(OpenRouter의 동영상 모델): Image Studio에 이 모델용 동영상 프리셋이 있습니다(360p–4K, 16:9 또는 9:16, 3–10초, 첫 프레임과 마지막 프레임, 소리 포함).
- **Seedream 5.0 Lite가 Box에서 그려집니다:** 중계 서비스를 통하면 Image Studio에서는 그려지는데 Box에서는 실패했습니다. Image Studio에서 Seedream 5.0 Lite와 Pro의 크기와 참고 이미지 수가 이제 공식 사양을 따릅니다: Lite는 2K / 3K / 4K와 참고 이미지 14장, Pro는 1K / 1.5K / 2K와 참고 이미지 10장입니다.
- **Box의 이미지 편집이 더 많은 중계 서비스에서 동작합니다.**

### 내장 브라우저와 Computer Use

- **「에이전트 따라가기(브라우저)」(신규, 기본 꺼짐):** 기능 옵션 ▸ 코드 동작에서 「에이전트 따라가기(브라우저)」를 켜거나, 브라우저 도구 모음의 눈 버튼을 클릭합니다. 그러면 Agent가 「Agent」 표시가 붙은 전용 탭에서 작업하며, 실시간으로 지켜볼 수 있고 사용자의 탭은 건드리지 않습니다. 페이지를 읽기만 할 때는 브라우저를 앞으로 가져오지 않습니다.
- **봐야 할 페이지는 열어 줍니다:** 「헤드리스 브라우저」가 켜져 있으면(기본값) 로그인, 캡차, 완료된 페이지가 화면 밖에 머물러 Agent가 보여 줄 방법이 없었습니다. 이제 보여 달라고 요청한 페이지, 직접 조작해야 하는 페이지(로그인, 캡차, QR 코드, 결제 확인), 또는 마지막 결과는 「브라우저」 탭을 열어 보여 줍니다. Agent 자체 확인은 여전히 화면 밖에서 실행됩니다.
- **Cloudflare 확인이 반복되지 않습니다:** 내장 브라우저가 Cloudflare의 사람 확인을 되풀이하며 멈추지 않습니다.
- **Computer Use (Windows):**
  - 앞에 있는 창이나 디스플레이 하나를 캡처하고, 그 일부를 확대하고, 보조 키를 누른 채 클릭하고, 세 번 클릭하고, 마우스를 올리고, 창이나 컨트롤이 나타나거나 사라질 때까지 기다릴 수 있습니다. 버튼, 확인란, 펼침 메뉴 클릭이 더 안정적입니다.
  - 암호 입력란에는 절대 입력하지 않습니다.
  - 이미 실행 중인 앱을 열면 그 창으로 전환하고(트레이에 있어도), 창이 여러 개면 목록을 보여 줍니다(예: QQ 계정 두 개).
  - QQ나 WeChat이 앞에 있을 때도 창을 인식합니다.
  - Claude 모델은 Anthropic 자체 computer 도구를 사용합니다: Box ▸ 실험적 ▸ Computer Use (Windows) ▸ 「Claude 전용 컴퓨터 조작 도구」.
  - 새 명령 「Breezell: Run Computer Use Evaluation」은 데스크톱 작업 아홉 개로 모델을 테스트하고 각 결과를 확인합니다.

### Box

- **데이터 정리:**
  - 확보할 수 있는 공간이 이제 파일이 실제로 디스크에서 차지하는 크기로 표시됩니다.
  - 현재 워크스페이스를 정리할 때 다른 워크스페이스가 아직 필요로 하는 파일을 삭제하지 않습니다.
  - 정리로 확보할 수 있는 공간이 「정리 알림」 설정값(끄기, 200 MB, 500 MB(기본값), 1 GB)을 넘으면 왼쪽 아래에 카드가 나타납니다. 「지금 정리」는 안전 정리를 실행하고 끝까지 보여 주며, 「나중에」를 누르면 그만큼 다시 쌓이지 않는 한 7일 동안 모든 창에서 카드가 나타나지 않습니다. 이 카드는 핫 업데이트 카드와 같은 열에 놓여 서로 겹치지 않습니다.
  - 새로 정리할 수 있는 항목: 더 이상 아무것도 쓰지 않는 체크포인트 백업(「Expired checkpoints」에 포함); 「삭제한 프로젝트의 저장소」, 즉 폴더가 사라진 워크스페이스가 남긴 데이터로, 그 대화도 함께 삭제되므로 미리 선택되지 않고, 모든 프로젝트를 나열해 먼저 묻고, 예약된 유지 관리나 알림으로는 절대 실행되지 않습니다; 그리고 더 많은 「Space left by deleted content」.
- **데이터베이스 ▸ 데이터 브라우저 재설계:** 페이지가 하나의 화면이 되었고, 이 페이지가 열려 있는 동안 Box 탐색이 아이콘 레일로 접힙니다.
  - 왼쪽 탐색기는 끌어서 크기를 조절하거나 「탐색기 접기」로 접을 수 있으며, 둘 다 기억됩니다. 모든 연결이 상태와 함께 나열되며, 열린 연결은 연결 해제, 이름 변경, 채팅으로 보내기, 삭제를 할 수 있습니다. 그 아래에는 행 수가 표시된 테이블, 검색, 정렬, 새 테이블, 「SQL 콘솔」이 있습니다.
  - 데이터베이스 개요는 모든 테이블의 행, 열, 기본 키를 나열하며, 필터, 정렬, 「첫 글자로 묶기」가 있습니다. 일부 서버 데이터베이스는 추정 행 수를 표시합니다.
  - 테이블 보기에는 WHERE 필터(Enter로 실행), 「표시할 열」, 전체 행 수가 있으며, 행 번호와 키는 왼쪽에 고정됩니다.
  - 「행 상세」가 그리드 옆에 고정됩니다: 모든 필드의 전체 내용, 정리된 JSON, 「이전 행」 / 「다음 행」, 편집(또는 더블 클릭), 「JSON으로 복사」, 삭제. 테이블 삭제는 「구조」 탭으로, 워크스페이스 스캔은 새 연결 양식으로 옮겨졌습니다.
  - 마우스를 올릴 때만 나타나던 버튼과 스크롤바가 없어졌습니다.
- **모델 모니터 ▸ Breezell:** 사용자의 플랜에 해당하는 회선의 상태(예: 「Breezell Pro/Pro+」)를 보여 줍니다. 각 행은 최근 90분을 1분에 막대 하나씩 보여 주고, 24H / 7D / 30D로 가용성 수치를 전환하며, 제목에 그 평균이 표시됩니다. 탭을 열 때와 「다시 확인」을 누를 때 갱신됩니다. 플랜에 아직 모니터가 없으면 탭이 그렇게 알려 줍니다. 다른 탭은 이전처럼 사용자의 컴퓨터에서 확인합니다.
- **모델 페이지:**
  - 카테고리 줄(Breezell, 로그인, API 공급자, OpenAI 호환, 이미지 생성)이 위에 고정되고, 그 아래 내용만 스크롤됩니다.
  - OpenAI 호환 슬롯을 이름, URL, 모델로 검색할 수 있습니다(「opus 4.8」로 `claude-opus-4-8`을 찾습니다). 현재 채팅이 쓰는 슬롯은 「사용 중」으로 표시되어 맨 앞에 오고, 나머지는 마지막으로 사용한 순서대로 이어집니다.
  - Box가 좁으면 이름이 먼저 줄어들고, 들어가지 않는 배지는 통째로 빠지며, 「사용 중」은 체크 표시만 남습니다. 툴팁은 텍스트가 잘린 곳에만 나타납니다.
  - 가져온 모델 목록의 닫기 버튼에 「닫기」라고 표시됩니다. 목록 밖을 클릭하거나 Esc를 누르면 목록이 닫힙니다(목록에서 모델을 체크한 경우 제외).
- **성능 ▸ 네트워크와 대화:** 진단 카드와 최근 요청에 「OpenAI-Compatible 9」 같은 이름 대신 OpenAI 호환 슬롯에 붙인 별칭이 표시됩니다.
- **Rules & Skills & Memory:** 첫 탭이 규칙인데도 Skills & Memory라는 이름이었던 패널이 이제 모든 곳에서 Rules & Skills & Memory입니다: Box 탭(MCP & Rules & Skills & Memory), 그 진입 카드, 제목 표시줄 버튼.
- **사이드바:** 계정 이름 옆의 플랜이 테두리 있는 알약 모양 대신 색이 있는 글자로 표시되고, 하단의 「업데이트」 아이콘은 타일이 없어지지만 색은 그대로입니다.

### 계정과 로그인

- **로그인이 이유 없이 풀리지 않습니다:** 일부 사용자가 계정에 아무 문제가 없는데도 로그아웃되거나 아예 로그인할 수 없었습니다. 이제:
  - 네트워크 끊김, 웹사이트 접속 불가, 확인 페이지, 프록시 오류, 여러 창을 연 상태, 한 컴퓨터에 설치된 Breezell 두 개, 틀린 컴퓨터 시계 때문에 더 이상 로그아웃되지 않습니다. Breezell이 실제로 로그인을 종료할 때만 로그아웃됩니다.
  - 모든 창이 같은 로그인 상태를 보여 주므로, 로그인이 사라졌는데도 로그인된 것처럼 보이는 창이 없습니다.
  - Box에서 설정한 프록시로만 인터넷에 연결할 수 있으면 로그인도 그 프록시를 사용합니다.
  - 로그인 코드를 입력할 때 Breezell이 코드가 맞지 않은 경우, 이 네트워크에서 시도가 너무 많은 경우, Breezell에 연결할 수 없는 경우를 구분해서 알려 줍니다.
  - 로그아웃되면 그 이유를 알려 줍니다: 「이 기기에서 로그아웃되었습니다」 또는 「로그인이 만료되었습니다」.
- **로그인이 만료된 뒤에도 Breezell 모델이 계속 실패하지 않습니다:** 이전에는 로그인이 만료되면 다시 로그인할 때까지 모든 메시지가 실패했습니다. 이제 Breezell이 스스로 이어 갑니다.
- **여섯 번째 기기는 거부되기만 합니다:** 이전에는 여섯 번째 기기가 계정 전체를 24시간 동안 차단하고 나머지 다섯 대를 로그아웃시켰습니다. 이제 새 기기만 거부됩니다: 새 기기는 로그인 페이지에 머물며 이유를 알려 주고, 나머지 다섯 대는 계속 사용됩니다. 모든 자리가 찬 상태에서 절전에서 깨어난 기기는 로그인 상태를 유지한 채 기다리는 중이라고 표시하고, 자리가 나면 스스로 이어 갑니다. 계정 페이지에서 이 내용을 설명합니다. 닫힌 편집기가 몇 시간 동안 기기 자리를 차지하는 일도 없어졌습니다.
- **로그인 정보 암호화 저장:** 로그인 정보는 사용자의 컴퓨터에 암호화되어 저장됩니다.
- **중지하면 생성된 만큼만 청구됩니다:** Breezell 자체 모델에서 중지하거나 요청이 중간에 끊기면 전체 답변이 아니라 생성된 만큼만 청구됩니다.

### 원격 개발

- **Remote-SSH:**
  - 보안 수정: 포트 포워딩이 이 컴퓨터에서만 수신 대기하므로 로컬 네트워크의 다른 컴퓨터가 접근할 수 없습니다.
  - 「Connect to Host」는 SSH 설정에 있는 호스트를 나열하고 `user@host:port`를 받습니다.
  - Windows 호스트에서 cmd, PowerShell, Git Bash를 구분합니다.
  - ProxyJump와 암호가 걸린 PEM 키가 동작하며, macOS와 최소 구성 Linux 시스템에서 설치 스크립트에 있던 문제가 수정되었습니다.
  - 폴더가 없는 워크스페이스에서 더 이상 오류가 표시되지 않습니다.
- **Remote-WSL:** 설치 스크립트 수정, Alpine 지원, 스크립트가 실패할 때 이유 표시. 폴더가 없는 워크스페이스에서 더 이상 오류가 표시되지 않습니다.
- **원격 창의 플러그인:** 「설치됨」에 플러그인마다 한 행이 표시되고, 업데이트 후 반대편에서 이전 버전이 계속 실행되는 일이 없습니다.

### 성능

- **긴 대화에서 더 부드러운 스크롤:** 메시지가 수천 개인 대화도 끊김 없이 스크롤됩니다.
- **Box는 닫혀 있는 동안 쉽니다:** 닫힌 Box가 더 이상 백그라운드에서 리소스를 쓰지 않습니다.
- **기억 소환이 메모리를 덜 씁니다:** 기억 소환이 차지하는 메모리가 약 40% 줄었습니다.
- **아주 큰 대화를 저장할 때 메모리를 덜 씁니다:** 아주 큰 이전 대화를 저장할 때 메모리를 훨씬 적게 씁니다.

### 인터페이스

- **빈 채팅 페이지의 새 마크:** 모던 UI와 클래식 UI의 빈 페이지에 BREEZELL이 가운데를 가로지르는 큰 RSI가 표시됩니다. 움직이지 않습니다.
- **턴 작업 표시줄의 크기 통일:** 오른쪽의 Request ID, 소요 시간, 리뷰, Git, 도구 수가 이제 왼쪽의 복사 및 분기 버튼과 같은 크기입니다.
- **「빠른 문구」 재설계:** 팝오버에 제목, 추가 버튼, 「관리」가 있습니다. 「자주 씀」의 각 문구는 유형 아이콘, 이름, 한 줄 미리보기(터미널 명령은 고정폭 글꼴)가 있는 한 행입니다. 관리 대화 상자는 스타일이 바뀌었고 이전과 같이 동작합니다. 양식은 이름 칸에서 Enter, 내용 칸에서 Ctrl/Cmd+Enter를 누르면 저장됩니다.
- **모던 UI의 Auto:** Auto 라우팅 스위치가 올바르게 그려집니다. Auto 모델 메뉴가 옆의 채팅 기록 사이드바에 더 이상 가려지지 않고, 창 오른쪽 가장자리를 넘어가지 않습니다.
- **인라인 diff에서 삭제된 줄이 줄바꿈됩니다:** 자동 줄바꿈(Alt+Z)을 켜도 편집의 빨간 영역에 있는 긴 삭제 줄이 한 줄로 남아 가장자리에서 잘렸습니다. 이제 편집기의 다른 줄처럼 줄바꿈됩니다.
- **기타:**
  - 삭제 도구 카드는 삭제된 파일 이름에 취소선을 긋고, 코드 블록의 파일 헤더는 이름과 아이콘의 크기가 맞춰졌습니다.
  - 반짝이는 대기 텍스트가 분석 카드에서 이중으로 보이지 않습니다.
  - Teams 승인 카드의 구성원 행에 있는 모델 힌트가 시스템의 흰 툴팁 대신 Breezell 자체 툴팁을 사용합니다.

### 설치와 업데이트

- **더 안정적인 Windows 업데이트:** 다운로드에 실패하면 바로 오류가 표시되고, 오래된 설치 프로그램이 실수로 설치되지 않습니다.
- **시스템 요구 사항:** 이 버전부터 macOS 13 이상이 필요하며, 빌드는 64비트 전용입니다. Linux ARM32(armhf) 편집기는 더 이상 없고, 다운로드 페이지도 ARM32 컴퓨터에 x64 패키지를 권장하지 않습니다. SSH로 ARM32 호스트에 연결하는 것은 계속 가능합니다.
- **Linux 패키지:** deb와 rpm 패키지의 의존성이 새 버전에 맞게 업데이트되었습니다.
- **Electron 45.2.2:** 내장 Chromium이 156 버전으로 업데이트되었고, 보안 수정을 포함해 의존성이 업데이트되었습니다.

## 1.4.4 · 2026-10-27

### 하이라이트

- **Cross-Check:** Agent가 완료라고 말하기 전에 독립된 두 번째 시선으로 확인합니다(기본은 꺼짐).
- **완료된 턴은 접힙니다:** 끝난 턴이 「Worked for 2m 10s」 한 줄로 접히고, 답변은 그 아래에 표시됩니다.
- **긴 대화는 압축 후에도 방향을 잃지 않습니다:** 컨텍스트를 접어도 방향을 유지하고, 접는 비용도 줄었습니다.
- **맥락으로 하는 기억 소환:** 어떤 언어에서도 동작하며, AI가 기억을 단계적으로 검색할 수 있습니다.
- **이미지 생성은 한곳에서:** Box ▸ 모델 ▸ 이미지 생성에서 한 번 설정하면 어디서나 쓰이며, Image Studio를 새로 만들었습니다.
- **네트워크 복구:** VPN이 끊겼다 돌아와도 요청이 스스로 복구되고, 느린 모델이 약 2분에서 시간 초과되지 않습니다.
- **핫 업데이트가 유지됩니다:** 정상 사용 후 핫 업데이트가 저절로 사라지지 않습니다.

### 채팅

- **완료된 턴은 접힙니다:** 턴이 끝나면 Agent가 그동안 한 모든 일(사고, 검색, 도구와 편집 카드, 그 사이의 텍스트)이 한 줄로 접히며, 얼마나 걸렸고 무엇을 했는지 표시됩니다. 예: 「Worked for 2m 10s · 12 files, 3 searches, 2 edits」. 클릭하면 원래대로 펼쳐집니다. 최종 답변은 접힘 밖에 남고, 오류와 그 턴이 만든 이미지도 마찬가지입니다. 직접 멈춘 턴, 오류로 끝난 턴, 단순한 답변은 접히지 않습니다. 기록에 있는 턴도 같은 방식으로 접힙니다.
- **Cross-Check(신규, 기본 꺼짐):** 「기능 옵션 ▸ Cross-Check」(「모델 자기 개선」)에서 켭니다. Agent가 큰 변경(파일 두 개 이상, 파일 하나에서 30줄 이상, 또는 승인된 계획)에 최종 답을 내기 전에, 도구가 없는 별도의 모델 호출이 요청과 결과를 대조합니다: diff, 새로 생긴 컴파일 오류, 실행된 명령과 종료 코드. 수용 체크리스트를 작성하고 각 항목을 통과·실패·알 수 없음으로 표시합니다. 빠진 것으로 판단한 부분만 Agent로 돌아가고, Agent는 코드에서 항목별로 확인해 실제로 빠진 것을 고친 뒤 한 번 답합니다.
  - 결과는 턴 아래 카드입니다. 펼치면 체크리스트가 나오고 「다시 확인」과 「빈틈 채우기」가 있습니다.
  - 대기 줄의 「건너뛰기」는 그대로 진행합니다. 답변 후 중지하거나 새 메시지를 보내면 확인만 끝납니다.
  - Box ▸ Cross-Check에서 전용 모델을 고르지 않으면 그 대화의 모델을 사용합니다. 비밀이 있을 수 있는 파일(`.env`, 키, 자격 증명)은 이름만 나열되고 내용은 전혀 전송되지 않습니다.
  - 느린 확인은 90초 후 잘리지 않습니다. 계속 지켜보며 API가 실제로 중단된 것이 확인될 때만 실패합니다.
- **메시지를 편집해 다시 보내도 이미 처리한 변경이 되살아나지 않습니다:** 이전에는 다시 보내면 이전 체크포인트의 모든 파일이 되돌아갔습니다. 「모두 유지」 후에도 이미 수락한 변경에 「수락/거부」가 다시 나타나고, 수락한 구간이 다시 대기 상태가 되고, 거부한 변경이 돌아왔습니다. 이제 다시 보내면 그 메시지 이후 AI가 편집한 파일만 복원합니다. 그 후에 직접 한 일(이후 AI가 건드리지 않은 파일에 입력한 내용 포함)은 그대로 남습니다.
- **「모두 유지」와 「모두 수락」이 깔끔하게 정리합니다:** 「모두 유지」는 이제 그 대화가 편집한 모든 파일의 대기 중 변경도 수락합니다. Code Review의 「모두 수락」은 모든 단계가 결정된 파일을 커밋합니다. 수락으로 표시된 단계는 더 이상 편집기에 「수락/거부」 버튼을 남기지 않습니다.
- **긴 대화는 접기(컨텍스트 압축) 후에도 방향을 잃지 않습니다:**
  - 접어도 AI가 예전 작업을 계속하지 않습니다. 요약에는 이전 각 요청이 어떻게 끝났는지 기록되고, 그 직후에 최신 요청이 다시 적힙니다.
  - 사용자의 이전 메시지는 요약 옆에 그대로 함께 들어갑니다.
  - 요약은 고정된 절로 작성됩니다: 목표, 사용자 말로 된 의도, 결정, 기술 메모, 상태, 다음.
  - 가능하면 Agent가 방금 보낸 요청(제공자가 아직 캐시한 것)에 대해 요약을 작성합니다. 대부분 캐시 읽기로 청구되어 더 빨리 돌아옵니다.
  - 요약 옆에 그대로 남기는 최근 대화는 최대 15,000 토큰입니다(이전에는 창의 20%, 1M 모델에서 최대 약 192k). 그래서 한 번 접으면 훨씬 많은 여유가 생깁니다.
  - 창을 넘어 커지는 단일 턴(수백 개의 도구 결과)은 이제 한도를 넘겨 「upstream」 오류로 실패하는 대신 중간에서 접을 수 있습니다.
- **백그라운드 분석: 하나씩 중지하거나 다시 실행할 수 있습니다:**
  - 한 분석(그 카드나 보고서 페이지)에서 중지하면 그것만 멈춥니다. 라운드는 찾은 내용을 가지고 계속됩니다.
  - 「재시도」는 실패·중지·중단된 분석을 같은 카드 아래에서 다시 실행합니다.
  - 리드는 이제 각 라운드를 한 번만 받고, 모든 분석이 어떻게 끝났는지(완료, 오류와 함께 실패, 중지) 함께 받습니다.
  - 재시작으로 끊긴 분석은 「중단됨」으로 돌아오고, 다음 메시지에 찾은 내용이 전달됩니다.
  - 보고서 페이지는 위로 스크롤할 때까지 새 출력을 따라가고(「최신으로 이동」), 상태 줄(단계, 시간, 토큰, 모델)과 「보고서 복사」를 표시합니다.
  - 하위 에이전트가 질문을 던져 라운드를 멈추지 않습니다.
- **Teams는 라운드로 동작합니다:** 리드의 후속은 자체 작업을 가진 새 라운드를 시작하므로 이전 라운드의 보고서가 새 라운드의 것으로 오인되지 않습니다. 리드의 중지는 파일을 되돌리거나 팀을 해산하지 않고 팀원을 멈춥니다. 팀원 자신의 페이지에서 중지하면 중지됨으로 표시되고 리드에게 알립니다. 다음 메시지에서 다시 깨어납니다.
- **DarkSelene은 API 문제를 견디고 멈춘 곳에서 이어갑니다:**
  - 각 분석 호출은 연결 끊김, 시간 초과, 408/429/5xx, 빈 응답 후 약 2분 동안 다시 전송됩니다. 페이지와 채팅 카드에 재연결이 표시됩니다.
  - 중지된 세션은 채팅 카드에 이유를 빨간색으로 표시하고 「분석 계속」(완료된 단계 유지)과 「다시 분석」을 제공합니다.
  - 실행 턴이 오류로 끝나면 검토를 유지한 채 일시 정지합니다. 「실행 계속」(또는 「다시 시도」)이 이어받고, 「종료하고 요약」이 지금까지 한 일을 정리합니다.
  - 느린 호출은 3분이나 15분에 잘려 재전송되지 않습니다. 조용한 호출은 지켜보며 API가 중단된 것이 확인될 때만 실패합니다.
- **Entanglement 모드:** 이제 수정을 무엇이 증명하는지(진단, 테스트, 사용자의 확인)를 메시지에서 단어 목록으로 추측하지 않고 모델이 결정합니다. 「아직 안 됩니다」라고 해도 마지막 변경이 조용히 되돌려지지 않고, 유지·조정·되돌리기를 모델이 판단합니다. 설명과 확인에 인과 기록을 다시 요구하지 않고, Entanglement로 전환할 때 인과 추적을 첫 단계로 강제하지도 않습니다.
- **작은 채팅 수정:**
  - 답변이 끝난 뒤 복사/재시도 바가 나타날 때 위로 튀지 않습니다.
  - 편집 카드 헤더에서 불필요한 「N changes」 개수가 빠지고 파일 이름과 +X/−Y만 남습니다.
  - 답변 후 Agent가 계속할 때(Cross-Check, 복구, 다음 라우팅된 하위 작업) 빈 화면 대신 「다음 단계 결정 중」이 표시됩니다.
  - 제공자가 도중에 중단한 도구 호출(중계 서비스의 `gpt-6-astra`에서 나타난 「Tool arguments stopped making progress…」 등)은 네트워크 오류로 턴을 끝내는 대신 실패로 닫히고 다시 기록됩니다.

### 채팅 기록과 입력창

- **채팅 기록 패널 재설계:** 「새 Agent」 버튼, 전환 가능한 검색, Agents／Teams／Favorites 탭, 고정 헤더가 있는 날짜 그룹, 두 줄 항목(제목과 시간, 그다음 첫 프롬프트와 턴 수 또는 팀 구성원). 스트리밍 중인 대화가 목록을 매 프레임 다시 그리지 않습니다.
- **기록 사이드바 크기 조절:** 200~600 px 사이로 끌 수 있습니다(기본 260, 이전에는 220 고정이라 「새 Agent」가 잘렸습니다). 좁아지면 버튼이 잘리지 않고 재배치됩니다.
- **입력창 태그가 차분해졌습니다:** 파일, 스킬, 터미널, 인용, 문제 등이 하나의 중립 칩을 공유하고, 종류별 색은 아이콘에만 적용됩니다. 스킬 칩은 슬래시 메뉴처럼 `/이름`으로 표시됩니다. 첨부 썸네일은 중립 테두리, 원형 제거 배지, 호버 미리보기를 갖습니다.
- **다른 에이전트의 스킬:** `npx skills`와 다른 에이전트가 설치한 스킬을 `.agents/skills`와 `.claude/skills`(각 워크스페이스 폴더와 홈 폴더), 그리고 `~/.config/agents/skills`에서 찾습니다. 이름이 충돌하면 Breezell 자체 `.breezell/skills`가 우선합니다. 규칙 패널은 가져온 폴더와 함께 이들을 나열합니다. 재시작 직후 트레이의 스킬 점이 표시됩니다.
- **모드 선택기:** 새 Agent와 Entanglement 아이콘, 라벨의 그라데이션 제거, 중립적인 모드 전환 카드.

### Agent 도구

- **`run_script`가 실제로 한 일을 보고합니다:**
  - 스크립트가 파일을 편집한 뒤 그 편집이 유발한 오류(`path:line` 메시지)를 실패나 시간 초과 후에도 나열합니다. 이전에는 의미 없는 「0 errors」를 반환했습니다.
  - 편집이 미치는 다른 파일도 나열합니다.
  - 편집을 전혀 하지 않는 스크립트는 승인 없이 읽기 전용으로 실행됩니다.
  - 브리지 호출은 최대 1,000회이며, 한도를 넘은 호출은 조용히 삼켜지지 않고 보고됩니다.
  - 정확한 텍스트를 이스케이프한 JavaScript 대신 데이터로 전달할 수 있고, `edit_file`은 `dry_run`을 받습니다.
  - 같은 파일에 대한 편집은 순서대로 실행됩니다.
  - 카드는 실행이 실패한 이유(라벨, 줄, 메시지)를 알려주고 예외를 던진 호출에 「N failed」를 표시합니다.
- **찾아내는 코드 탐색:**
  - `grep_search` 결과 행은 그것이 속한 함수, 메서드, 클래스 아래로 묶입니다.
  - 편집 후 영수증에 「이 변경이 미치는 다른 파일」(변경·제거·이름이 바뀐 선언의 호출자와 TypeScript 오류)이 나열됩니다.
  - `find_symbol`은 파일당 4,000개 심볼(이전 500)과 최대 2M 문자 파일을 인덱싱하고, 인덱스가 차가우면 잠시 기다리며, kind 이름을 느슨하게 해석하고 「calcTot」 같은 약어도 맞춥니다.
  - `lsp` 참조는 파일별로 묶이고, `call_hierarchy`는 깊이 1–3을 받습니다.
- **터미널과 검색 수정:**
  - Agent 터미널 폭보다 긴 출력 줄이 다음 줄이 붙은 채 끊겨 돌아오지 않습니다.
  - `grep_search`가 CRLF 파일에서, 그리고 절대 경로의 폴더 glob(예: `docs/**`)에서 동작합니다.
  - PowerShell에서 `&&`／`||`와 `exit` 재작성이 문자열 안의 텍스트를 바꾸지 않습니다: `git commit -m "Stop on Ctrl+C; exit cleanly"`는 쓴 그대로 커밋됩니다.
  - Linux와 macOS에서 `/mnt/d/…` 경로가 D: 드라이브로 오인되지 않습니다.
- **MCP 출력이 컨텍스트를 부풀리지 않습니다:** 20,000자를 넘는 MCP 결과는 긴 터미널 출력처럼 미리보기와 함께 파일로 저장됩니다. MCP 이미지는 파일로 저장되고 현재 턴의 최신 세 개만 모델로 전송됩니다. 이전에는 스레드의 모든 MCP 이미지가 이후 요청마다 다시 전송되었습니다.

### 메모리

- **맥락으로, 어떤 언어에서도 소환:** 이제 기억은 사용자의 요청, 그 이전 대화, 열린 파일을 읽는 작은 로컬 모델이 고릅니다. 키워드와 고정 단어 목록은 사라졌습니다. 태국어, 힌디어, 한국어, 악센트가 있는 라틴 문자를 포함한 모든 언어에서 동작하고, 대화를 따라갑니다. 아무것도 지목하지 않는 짧은 후속 질문도 그 대화가 다루는 기억을 찾습니다. 오래된 기억과 잠든 기억도 공정한 기회를 얻고, 턴이 분명히 필요로 하면 잠든 기억이 깨어납니다. 학습한 적 없는 테스트 세트(10개 언어)에서 기억이 필요했던 턴이 기억을 받은 비율은 41%에서 62%로 올랐습니다.
- **AI가 기억을 단계적으로 조회할 수 있습니다:** `memories_recall`이 이제 색인(종류, 우선순위, 상태, 날짜, 일치 방식)을 나열하고, 연결 관계와 함께 전체 기록을 열고, AI가 결과를 좁힐 수 있게 합니다: 정확한 텍스트, 날짜, 종류, 우선순위, 또는 질의의 다른 표현으로. Super Memory 플랜이 필요 없고, 검색 시 오래된 기억이 나이 때문에 밀려나지도 않습니다. 채팅 카드는 열린 모든 기록을 표시합니다.
- **더 명확한 기억 상태:** 채팅은 기억 소환이 실행 중인지, 그 턴에 기억을 쓰지 않았는지, 관련 기억이 이미 이 대화 앞부분에 있는지를 보여줍니다. 큰 라이브러리에서도 소환이 창을 멈추게 하지 않습니다. 이후 기억이 틀렸다고 밝혀진 기억은 유지되고, 대체한 것에 대한 링크와 함께 「더 이상 유효하지 않음」으로 표시되며 다시 제공되지 않습니다. 메모리로 보이는 내용에 도구 이름이 나타나지 않습니다.
- **클라우드 텔레메트리:** 클라우드 텔레메트리가 켜져 있으면 소환이 판단에 사용한 수치도 전송됩니다: 텍스트는 없고, 기억은 솔트가 붙은 해시로만 전달됩니다. 동의 문구가 모든 언어에서 이를 설명하므로 다시 동의를 요청합니다.

### 이미지

- **이미지 모델은 한곳에: Box ▸ 모델 ▸ 이미지 생성:** 모델에서 설정한 제공자의 이미지 모델이 제공자당 타일 하나로, 기본 모델과 자체 매개변수와 함께 나열됩니다. 각 제공자의 카탈로그에서 더 추가할 수 있습니다. 채팅의 `generate_image`, 입력창의 이미지 모드, Image Studio 모두 이 목록으로 그립니다.

### 네트워크와 안정성

- **VPN 변화 후 궤도 복귀:** VPN이나 프록시 클라이언트가 끊겼다 돌아오면 요청이 죽은 연결에서 수 분을 기다릴 수 있었습니다. 이제 실패한 요청이 있으면 다음 요청은 새 연결을 열고 시스템 프록시를 다시 읽습니다.
- **느린 답변이 약 2분에서 실패하지 않습니다:** Breezell 모델에서 첫 단어까지 수 분 생각하는 모델이나 2분 이상 걸리는 이미지가 524 오류로 실패했습니다. 이제 연결은 열린 채 유지되고, 얼마나 기다릴지는 편집기가 정합니다.
- **설정 가능하고 학습하는 첫 바이트 시간 초과:** Box ▸ 네트워크와 채팅 ▸ 첫 바이트 시간 초과: 40(기본), 60, 90, 120, 180초 또는 20–240. 그 한도 안에서 대기는 각 모델의 최근 첫 바이트에 적응하므로 멈춘 요청이 더 빨리 재시도됩니다(10초가 아니라 2초마다 확인). 네트워크 상태 목록은 각 요청이 재시도된 이유(예: 「retry #1 after no first byte」)와 첫 바이트 대기 시간을 보여줍니다.
- **채팅 요청에 HTTP/2:** 채팅 요청은 이제 기본으로 HTTP/2를 쓰며, 직접 연결과 HTTP·HTTPS·SOCKS 프록시 모두에 적용됩니다. Box ▸ 네트워크와 채팅에서 HTTP/1.1로 되돌릴 수 있습니다. 응답 전에 HTTP/2 연결을 닫는 서버에는 요청이 다시 전송됩니다.
- **재시도 규칙은 한곳에:** 모든 제공자가 같은 재시도 규칙을 따릅니다. 사용자가 중지한 뒤, 할당량 소진, 거부된 요청, 이미 보이는 텍스트 뒤에는 재시도하지 않습니다. 「terminated」로 끊긴 스트림은 연결 끊김으로 재시도됩니다. 오류 문구의 「451」은 더 이상 지역 차단으로 해석되지 않습니다.

- **Agent 모드가 더 이상 Entanglement 모드로 전환되지 않습니다:** 적응형 전략을 켠 상태에서 Agent 모드가 "엄격"으로 판정한 작업(오류 증상을 설명한 메시지나 수정 내용을 정리한 업데이트 노트를 붙여넣은 경우 등)은 기존에 Entanglement 모드로 실행되어 LOCATE／VERIFY／FIX 조사 패널, 완료 조건, "이런 증상은 사용자의 확인으로 확정합니다"라는 엄격한 검증이 표시되었습니다. 이제 Agent 모드는 항상 Agent로 전체 도구 세트와 함께 실행됩니다. Entanglement 조사 패널과 엄격한 검증은 사용자가 직접 Entanglement 모드를 선택했을 때만 나타납니다.
- **위로 스크롤할 때 빈 화면이나 맨 아래로 튀지 않습니다:** 매우 긴 메시지가 있는 대화에서 해당 메시지 근처까지 위로 스크롤하면 화면이 갑자기 비어 버리고, 한 번 더 스크롤하면 목록 전체가 맨 아래로 되돌아가던 문제가 대화를 다시 열 때마다 발생했습니다. 원인은 긴 메시지가 처음에는 전체 높이로 표시되었다가 다음 순간 접히면서 대화 목록이 앞뒤로 다시 배치되었기 때문입니다. 이제 긴 메시지는 처음부터 접힌 높이로 표시되며, 위로 스크롤하면 스크롤한 위치에 그대로 멈춥니다.
- **응답을 붙잡아 두는 중계 서비스에서는 기다립니다:** 일부 중계 서비스는 모델의 사고 과정을 통째로 붙잡아 두었다가 사고가 끝난 뒤 한 번에 내보내기 때문에 채팅 화면이 십수 초에서 몇 분간 전혀 움직이지 않을 수 있습니다. "스트리밍 검사"로 표시된 모델은 이제 다음과 같이 동작합니다.
  - 설정한 추론 강도 그대로 전송하며 자동으로 낮추지 않습니다.
  - 오랜 침묵을 이유로 시간 초과로 판단해 중단하고 재시도하지 않고 응답이 올 때까지 기다립니다.
  - 대기하는 동안 5초마다 API를 확인하고, 20초마다 짧은 "안녕하세요"를 보내 모델이 응답하는지 확인합니다. 확인에 실패하면 점검 주기를 앞당기고, 성공하면 원래 주기로 돌아옵니다.
  - 화면에 "모델이 생각 중입니다. 이 중계 서비스는 사고 과정을 붙잡아 둡니다 · 32초 · API 정상(3초 전 확인)"이 표시되어 계속 작업 중임을 알 수 있습니다.
  - 점검 결과 API가 실제로 응답하지 않는 것이 확인된 경우에만 중단하고 "API 응답 없음 확인됨"을 표시하며 자동 재시도하지 않습니다. 펼치면 점검 횟수와 마지막 오류를 볼 수 있습니다.
- **대화 내용 복사:** 대화에서 텍스트를 선택해 복사하고 붙여넣으면 화면에서 보이던 레이아웃이 유지되고 `**`, `#`, `-` 같은 Markdown 기호가 더 이상 따라붙지 않습니다. "인용"은 여전히 Markdown을 유지하며, 문단과 목록 사이도 올바르게 줄바꿈됩니다.

### 모델 및 연결성

- **"스트리밍 검사" 추가:** Box ▸ 모델 ▸ OpenAI 호환 ▸ 연결성에서 모델을 선택한 뒤 "스트리밍 검사"를 누르면, 모델이 짧은 추론 문제를 푼 다음 1부터 120까지 세도록 하고 각 청크가 도착한 시각을 기록해 결과를 판정합니다.

- **비디오 첨부:** 채팅에 드롭한 비디오는 모델이 지원 목록(예: `kimi-k3`)에 없다는 이유로 차단되지 않고 항상 전송됩니다. 비디오 이해 여부는 모델과 제공자에 달려 있습니다. Anthropic 및 OpenAI Responses 형식은 비디오를 전달할 수 없으므로, 비디오가 첨부되지 않았음을 모델에 알리고 요청은 정상적으로 진행됩니다.
- **안정적인 도구 호출:** 모델이 도구 호출을 텍스트로 작성할 때 문자열을 받는 매개변수가 `true`, `null` 또는 `123`을 불리언이나 숫자로 변환하지 않으며, Python 코드를 교체할 때 문자열 내부의 `True`와 `None`이 `true`와 `null`로 바뀌지 않습니다.
- **중지 및 오류 처리:** 추론 도중 중지를 누르거나 오류가 발생했을 때 사고 시간이 `0.1s`로 표시되거나 초 단위로 잘리지 않고 소수점 첫째 자리까지 유지되며, 저장된 답변에 내부 마크업이 남지 않습니다.
- **모드 전환 카드:** 건너뛰기, 취소 또는 카운트다운 후 이전 실행이 끝날 때까지 기다린 뒤 계속 진행하므로 두 실행이 겹치지 않습니다. 카드가 대기하는 동안 대기열에 있는 메시지를 보내면 새 메시지가 실행을 이어받습니다.

- **할당량 소진 알림:** Breezell 계정의 할당량이 모두 소진되면 입력창 위에 "충전" 버튼이 포함된 안내가 표시되고 충전 후 자동으로 사라져, 요청을 보낸 뒤 뒤늦게 오류 메시지가 뜨는 불편을 없앴습니다.

- 디자인안 카드는 기본적으로 패널 전체 너비에서 한 장씩 표시됩니다. 탭 또는 방향키로 전환할 수 있으며, 나란히 비교하는 기능도 한 번의 클릭으로 열 수 있습니다.
- 확정된 디자인안은 `.breezell/design/` 아래에 독립 HTML 파일로 저장됩니다. 도구 결과의 사양, 계획, 구현이 모두 같은 파일을 가리키므로 선택한 디자인과 실제 구현이 어긋나는 일을 줄입니다.

#### 알림
- 알림 패널을 왼쪽 목록, 오른쪽 상세 보기 구조로 변경했습니다.
- 중요 알림은 모두 상단에 고정되며 더 이상 첫 번째 알림만 표시하지 않습니다.
- 목록과 상세 영역은 각각 독립적으로 스크롤됩니다.

### 수정

#### 대화 및 Agent
- 새 브랜치를 만들기 전에 원본 대화 본문을 먼저 복사합니다. 이미 본문이 사라진 이전 브랜치는 줄 번호를 이용해 내용을 복구할 수 있습니다.
- 다시 로드된 메시지는 본문이 복구된 뒤 플레이스홀더 높이를 해제합니다. 접힌 도구/추론 블록도 펼쳐졌을 때의 높이를 유지하지 않습니다. 브랜치 생성이 끝나기 전에는 브랜치 버튼의 중복 클릭을 무시합니다.
- 긴 대화는 하나의 연속 목록으로 열립니다. 아직 스크롤하지 않은 본문은 플레이스홀더로 유지하고 해당 위치에 도달할 때 로드합니다. “보관된 메시지” 안내와 마지막 부분만 유지하던 기존 창 방식을 제거했습니다. 다시 마운트한 뒤에도 줄 높이가 유지되며, 스트리밍 코드 하이라이트는 전체 블록을 깜빡이지 않고 증분 업데이트합니다.
- 현재 선택된 대화를 다시 열어도 전환 과정을 재생하지 않아 대화가 짧아지거나 마지막 부분 이외의 본문이 사라지지 않습니다. 로컬 Git 스냅샷이 해당 대화의 파일을 포함하지 않더라도 기록의 대기 중 diff 개수는 유지됩니다.
- 대화 본문은 현재 그 본문을 표시하는 뷰에서만 해제됩니다. 이미 에디터 탭에 열린 대화를 다시 열면 사이드바에 두 번째 복사본을 만들지 않고 기존 탭으로 돌아갑니다. 두 뷰가 서로 화면의 콘텐츠를 언마운트하는 문제를 방지합니다.
- 창이 최소화된 동안 실행 중인 작업에 대해서는 백그라운드 스로틀링을 끄고 앱 일시 중단을 막습니다. 실행 종료, 창 다시 로드, 창 닫기 이후에는 정상 동작으로 복구됩니다.
- 현재 선택한 모델이 삭제되거나 숨겨지면 모델 칩이 표시 가능한 다른 모델로 자동 전환됩니다. 모든 모델을 비활성화한 경우 먼저 모델을 하나 활성화하라는 안내가 표시됩니다.
- 한동안 외부 파일 읽기/쓰기 기본값이 꺼져 있었고 그 `false` 값이 설정에 저장되어, 이후 기본값을 바꿔도 이미 저장된 설정에는 반영되지 않았습니다. 업그레이드 시 두 권한을 다시 켜고 마이그레이션 표시를 기록하며, 이후 사용자가 직접 끈 선택은 그대로 유지합니다.
- 커밋 대화상자를 워크벤치 레이어로 옮겼습니다. 에디터 탭에서 시작한 브랜치 작업이 사이드바에 의해 잘리지 않습니다.

#### 저장소
- 대화를 삭제하면 데이터베이스를 즉시 압축해 SQLite freelist에만 남던 공간을 실제 디스크에 반환합니다. 이전 데이터베이스는 전체 `VACUUM`을 한 번 실행하며, 로그에는 실제 회수된 용량을 기록합니다.
- 정기 전체 `VACUUM`은 기록 쓰기 큐를 기다리고, 어떤 대화도 스트리밍 중이거나 도구를 실행 중이지 않을 때만 수행합니다.
- 대화 삭제 시 `breezellTranscripts`의 원본 전사 파일도 함께 삭제합니다. 여러 워크스페이스를 정리할 때는 다른 창에서 아직 활성 상태인 대화에 대해 디스크 파일과 같은 유예 기간을 유지합니다.

### 개선
- 기록 목록의 미커밋 경로 집합을 변경 시 한 번만 계산하고 SCM 상태, 경로 복원, diff 범위가 바뀔 때까지 캐시합니다. 변경 파일이 약 1,000개일 때 기존 약 25 ms였던 단일 다시 그리기 비용을 줄였고, 약 10,000개일 때 기존 약 265 ms였던 비용도 크게 낮췄습니다.
- Settings의 언어 함수는 렌더링할 때마다 새로 만들지 않고 언어별로 캐시합니다. 페이지 전체 캐시가 무효화되는 일을 줄였으며, Box 셸은 언어가 바뀔 때만 다시 렌더링합니다. 내비게이션 검색, 그룹 접기, 사이드바 접기 시 콘텐츠 페이지가 더 이상 함께 다시 그려지지 않습니다. OAuth 폴링은 상태가 변하지 않으면 이전 결과를 재사용합니다.

- 편집기가 포커스를 잃은 후 빈 콘텐츠가 저장되는 문제를 수정했습니다.

- **전체 SSH 원격 개발 지원**: 원격 SSH 호스트의 모든 도구 호출을 완전히 지원합니다.

- **“기본 모델” 레이블**: 모델 선택기에서 기본 모델을 명확히 표시합니다.
- **장기 메모리 패널 업그레이드**: “방금”, “오늘”, “이번 주”와 같은 시간 태그, 반투명 유리 스타일 및 메모리 회상 카드를 추가했습니다.
- **스트리밍 중 계획 제목 표시**: 모델이 계획을 생성할 때 스트리밍 출력 중 계획 제목을 표시합니다.
- **영구 오류의 자동 재시도 건너뛰기**: 인증 실패와 같은 영구 오류에 대해 의미 없는 자동 재시도를 하지 않습니다.

- **러시아어 인터페이스 지원**.
- **채팅 도구 카드 펼치기**: 검색 결과와 파일 읽기 등 도구 출력을 접거나 펼칠 수 있습니다.

- **대화 메시지 지연 로딩**: 긴 기록을 한 번에 모두 로드하지 않아 더 빠르게 열립니다.
- **API 캐시 메커니즘**: Responses API 캐시를 추가하여 중복 요청을 줄이고 토큰을 절약합니다.

### 개선

- 편집기 백엔드를 업그레이드했습니다. Electron은 41.2.0으로, TypeScript는 6.0으로 업그레이드하여 더 안정적이고 원활하게 작동합니다.
- 파일 작업, MCP 도구 등의 카드 스타일을 통일하도록 AI 도구 호출 인터페이스를 재설계했습니다.
- 코드 diff를 최적화하여 접힌 상태의 스크롤, 가로 스크롤바 및 배경색 표시를 수정했습니다.
- 시스템 알림을 최적화하여 중복 푸시를 방지하고 최소화할 때 연결 해제 보고를 하지 않습니다.
- 터미널 명령 감지를 최적화하여 명령 실행 여부를 더 정확히 식별합니다.
- 시작 흐름과 대화 목록 렌더링을 최적화하여 시작 성능을 개선했습니다.
- 장시간 실행 중 누적된 메모리를 자동으로 정리하여 백그라운드 메모리 오버플로를 방지합니다.

### 수정

- 대화 스레드 사이를 전환할 때 대기 중인 메시지가 잘못된 스레드로 전송될 수 있는 문제를 수정했습니다.
- 이미지 첨부 파일을 삭제할 때 다른 파일 첨부 파일이 삭제될 수 있는 문제를 수정했습니다.
- AI 응답 시간 초과 후에도 백그라운드 프로세스가 계속 실행되는 문제를 수정했습니다.
- TrustedHTML 호환성 문제로 인해 빈 페이지가 표시되는 문제를 수정했습니다.
- 내장 브라우저에서 링크를 클릭해도 새 페이지가 올바르게 열리지 않는 문제를 수정했습니다.
- AI에 질문할 때 옵션 버튼이 가끔 표시되지 않는 문제를 수정했습니다.
- 편집기 탭 아이콘이 정렬되지 않는 문제를 수정했습니다.
