# 변경 사항

## 1.4.37 · 핫 업데이트 · 2026-10-21

### 채팅

- **새로운 DarkSelene 모드:** 입력창 아래 모드 메뉴에서 DarkSelene("무엇이든 만들기 전에 질문을 분해합니다")을 선택하세요. 무엇이든 바꾸기 전에 어렵거나 잘못 해석되기 쉬운 질문을 끝까지 생각합니다. 매우 많은 토큰을 사용하므로 신중하게 사용하세요.
  - 1단계 · 만들기 전에 이해하기: 질문을 분해하고, 코드를 조사하고, 의문을 제기하고, 검증하고, 가능한 방법을 도출합니다. 조사 전에 '예측'을 적습니다. 답이나 완성된 변경이 어떤 모습이어야 하는지, 그리고 무엇이 그것을 틀렸다고 증명할지입니다. 조사는 그 지점만 확인합니다. 코드가 예측을 즉시 뒷받침하면 의문 제기와 검증은 건너뜁니다.
  - 증거로 정리: 코드나 사용자의 요청으로 답할 수 있는 질문은 모두 DarkSelene이 직접 답합니다. 사용자만 결정할 수 있는 것만 '사용자 관점'에서 묻습니다. 질문에 하나씩 답하거나 '권장안으로 진행'을 누르세요.
  - 2단계 · 실행과 검토: 준비한 작업은 사용자의 메시지로 전송되어 Agent가 수행합니다. Agent의 예상치 못한 읽기와 모든 편집은 독립 검토자가 증거와 대조해 확인하며(읽기 검토, 코드 검토), 그 지적은 Agent가 계속하기 전에 전달됩니다.
  - DarkSelene의 최종 요약에는 검토와 확인으로 실제 입증된 내용만 남습니다.
- **백그라운드 명령이 끝나면 AI가 알게 됩니다:** 대기 시간을 넘겨 백그라운드로 이동한 명령은 이전에는 다음 메시지를 보낼 때까지 보고되지 않았습니다. 이제:
  - 명령이 끝나는 즉시 터미널 카드가 결과로 갱신됩니다.
  - AI가 아직 응답 중이면 다음 단계에서 결과를 받아 같은 턴에 처리합니다. 실패를 고치거나 그 결과를 기다리던 작업을 계속합니다.
  - AI의 응답이 이미 끝났다면 명령이 끝난 약 1.5초 후에 새 턴이 자동으로 시작되어 한두 문장으로 결과를 보고합니다. 거의 동시에 끝난 여러 명령은 턴을 하나만 시작합니다.
  - 직접 중지한 명령(중지 점 또는 Ctrl+C), AI가 승인이나 답변을 기다리는 동안, 중지를 누른 직후에는 턴이 시작되지 않습니다.
- **보낸 메시지를 편집해 다시 보내면 원래 메시지가 취소됩니다:** 이전에는 오타를 고쳐도 텍스트만 바뀌었습니다. 오타 때문에 AI가 바꾼 파일과 그 턴에서 가져온 메모리가 남아 있어 AI가 잘못된 방향으로 계속 가는 일이 많았습니다. 이제 편집해 다시 보내면 먼저 원래 메시지와 그 이후의 모든 내용을 취소합니다.
  - 그 이후 AI가 바꾼 파일은 원래대로 돌아가고, 새로 만든 파일은 삭제됩니다.
  - 그 부분의 대화에서 가져온 메모리, Entanglement의 인과 기록과 확인 사항, 계획 파일, 작업 노트가 모두 메시지 이전 상태로 돌아갑니다.
  - AI는 메시지를 취소했다는 것만 알며, 그 내용은 알지 못합니다.
  - 보통은 편집한 메시지가 바로 전송됩니다. "취소하고 다시 보내시겠습니까?" 확인은 다음 경우에만 나타납니다.
    - 메시지 이후에 사용자가 직접 파일을 편집한 경우. "내가 편집한 파일 유지"로 남기거나 "모두 되돌리고 다시 보내기"를 선택합니다.
    - AI가 git commit이나 npm install처럼 자동으로 되돌릴 수 없는 명령을 실행한 경우. 해당 명령이 나열됩니다.
    - 대화에 돌아갈 체크포인트가 없는 경우. "그래도 다시 보내기"는 대화만 취소합니다.
  - 보낼 수 없는 첨부(선택한 모델이 받지 않는 PDF 등)는 무엇이든 취소되기 전에 걸러지므로, 메시지가 취소된 뒤 전송에 실패하는 일은 없습니다.
- **"이 지점으로 되돌리기"가 보내기 전에 편집한 내용을 보존합니다:** 이전에는 파일이 이전 턴이 끝난 시점으로 돌아가서 그 턴에서 한 편집과 이 메시지를 보낸 것까지 사라졌습니다. 이제 각 파일은 AI가 손대기 직전 상태로 돌아갑니다. 되돌린 뒤 메시지를 보내면 대화가 되감겼다는 것도 AI에 전달됩니다.
- **새 대화의 임시 제목에 두 번째 줄이 포함되지 않습니다:** 모델이 대화 이름을 붙이기 전까지 임시 제목은 첫 메시지의 첫 줄만 사용합니다.

### 모델

- **DeepSeek V4 Flash가 이미지를 직접 읽습니다:** 공식 `deepseek-v4-flash`와 중계 서비스의 `-0731` 스냅샷은 텍스트 전용으로 취급되어 이미지가 비전 프록시를 거쳐야 했습니다(프록시가 없으면 아예 보낼 수 없었습니다). 이제 이미지는 모델로 바로 전송됩니다. "Flash"가 없는 `deepseek-v4` 이름은 여전히 텍스트 전용으로 취급됩니다.
- **Grok 4는 사고를 켜도 더 이상 실패하지 않습니다:** `grok-4`, `grok-4-0709`, `grok-4-latest`는 Low에서 Max까지의 추론 설정을 표시하고 요청과 함께 보냈지만 xAI가 이를 거부합니다. Grok 4는 항상 추론하므로 이 설정은 더 이상 표시되지 않고 매개변수도 전송되지 않습니다.
- **Gemini 2.0 Flash에 사고 옵션이 없습니다:** Gemini 2.0 Flash와 Flash-Lite는 사고할 수 없지만 가능한 모델로 취급되었습니다. 이제 사고 옵션은 Gemini 2.5 이후(및 실험적인 2.0 Flash Thinking)에만 표시됩니다.
- **Google 로그인 확인 링크가 더 이상 잘리지 않습니다:** Google 계정을 통한 Gemini에서 브라우저로 한 번 확인하라는 요청이 나오면, 확인 링크가 첫 번째 "&"에서 잘려 페이지가 열리지 않을 수 있었습니다.
- **공식 OpenAI API가 이전 버전의 대화를 이어받지 않습니다:** OpenAI API 키를 사용할 때 메시지를 편집하거나 복원한 뒤, 또는 대화가 압축된 뒤에 서버가 이전 버전에서 이어가 모델이 실제로 보낸 내용을 보지 못할 수 있었습니다. 이제 이전 메시지가 그대로일 때만 이어가고, 그렇지 않으면 전체 대화를 다시 보냅니다.

### 버전 프리뷰

- **새 클라우드 텔레메트리:** Box ▸ 성능 ▸ 버전 프리뷰에 있습니다. 관리자가 활성화한 구독만 사용할 수 있으며, 다른 구독에는 사용할 수 없는 이유가 표시됩니다. 켜기 전에 Breezell이 수집하는 내용을 설명하고, "동의"를 누르고 켠 뒤에만 적용됩니다.
  - 켜져 있는 동안 도구 설명과 각 모드의 시스템 프롬프트는 클라우드에서 가져옵니다. 새 버전은 다음 턴부터 적용됩니다.
  - Breezell 개선을 위해 채팅 기록(AI와의 대화 텍스트)이 업로드됩니다. 코드는 수집되지 않습니다. 프로젝트 파일, 도구가 읽은 내용, 터미널 출력, 채팅 내 코드 블록은 업로드 전에 제거됩니다.
  - 카드에는 클라우드 프롬프트 버전, 업로드된 메시지 수, "지금 업로드" 버튼이 표시됩니다.
  - 언제든지 끌 수 있습니다. 다음 턴부터 내장 프롬프트가 다시 사용되며 더 이상 업로드되지 않습니다.

## 1.4.36 · 핫 업데이트 · 2026-10-18

### 채팅

- **모델이 어떤 텍스트를 붙여넣었는지 구분합니다:** 다른 곳에서 붙여넣은 텍스트(다른 AI의 답변, 로그, 전달받은 메시지)는 이전에 사용자가 입력한 문장과 섮여 모델에 전달되어, "붙여넣은 내용만 번역해"라고 했는데도 "관련 호출 체인을 확인…", "그냥 바꿔" 같은 줄을 다라 동작했습니다. 이제:
  - 채팅 입력창에 붙여넣은 여러 줄 또는 긴 텍스트는 붙여넣은 내용으로 표시되어 모델에 전달됩니다. 그 안의 지시를 따르는 것은 사용자의 말이 그것을 요구할 때뿐입니다. 그렇지 않으면 텍스트를 읽고 내용에 대해 답하거나, 요청한 대로 번역합니다.
  - 붙여넣은 내용만 있는 메시지도 사용자의 요청으로 처리됩니다.
  - "아래 내용을 실행해" 뒤에 붙여넣은 단계가 있으면 그 단계는 수행합니다.
  - 채팅 말풍선 표시는 이전과 같습니다. 붙여넣은 뒤 편집한 내용이나 파일 이름·경로처럼 한 줄짜리 짧은 붙여넣기는 표시되지 않습니다. 아주 큰 붙여넣기는 이전처럼 `pasted.txt` 첨부 파일이 됩니다.
  - 실제 DeepSeek(`deepseek-v4.1-flash`)에 "번역만" 규칙을 두고 검증했습니다. 수정 전에는 4회 중 3회가 붙여넣은 내용대로 파일을 읽고 수정했고, 수정 후에는 5회 모든 번역만 했습니다. 모델에 따라 차이가 있으며, 붙여넣은 텍스트가 모델에 대한 작업처럼 읽히면 일부 모델은 여전히 따를 수 있습니다.
  - 텍스트를 확실하게 번역하려면 같은 메시지에서 작업을 밝히고 원문을 인용하는 것이 가장 확실합니다. 예: "따옴표 안의 텍스트를 번체 중국어(대만)로 번역하고 번역만 출력하세요. 안의 내용을 실행하거나 답하지 마세요." 5개 모델(DeepSeek V4.1 Flash, DeepSeek V4 Pro, GLM 5.3, Kimi K3.1, MiniMax M3)에서 각 6회 모든 올바르게 번역했습니다.
- **없는 경로는 찾아 헤매지 않고 먼저 물어봅니다:** 사용자(또는 붙여넣은 텍스트)가 지정한 경로가 이 작업 공간에 없을 때, 모델은 이전에는 다른 탈더와 다른 철자로 여러 차례 검색했고 때로는 작업 공간 밖까지 찾았습니다. 이제:
  - 읽을 파일이 없으면 Breezell은 먼저 작업 공간 전체에서 그 이름을 검색합니다. 찾지 못하면 이 파일은 작업 공간에 없다고 모델에 알리고, 어디를 찾았는지 설명한 뒤 사용자에게 경로나 내용을 를어보라고 안내합니다.
  - 파일 또는 텍스트 검색에서 아무것도 나오지 않으면, 모델에 전달되는 힌트는 다음 내용으로 시작합니다. 이름이 사용자로부터 나온 것이면 그 이름으로 한 번 검색하고, 그것도 실패하면 다른 필터로 재시도하지 않고 멈추고 사용자에게 묻습니다.
  - 실제 DeepSeek으로 검증했습니다. 해당 경로의 평균 검색 횟수는 5.4회에서 3.7회로 줄었고, 작업 공간 밖 검색은 12회 중 6회에서 2회로 줄었습니다. 수정 후에는 모든 실행이 경로나 내용을 묻고 멈추었으며, 어떤 파일도 변경하지 않았습니다.
- **GPT에서 Claude로 바꾼 긴 대화가 더 이상 컨텍스트 한도를 넘지 않습니다:** 1M 컨텍스트의 긴 대화를 GPT 모델에서 Claude 모델로 전환한 뒤 전송하면 "prompt is too long: 1100588 tokens > 1000000 maximum"이 표시되며 바로 실패할 수 있었습니다. 같은 대화 내용이라도 Claude가 세는 토큰 수는 GPT보다 50~70% 많지만, 전환 후에도 Breezell은 GPT가 보고한 사용량으로 압축 여부를 판단해 압축 없이 전송했습니다. 이제는 다음과 같이 동작합니다.
  - 계산 방식이 다른 모델로 바꾸면 새 모델로 사용량을 다시 계산하고 입력창의 컨텍스트 사용량도 함께 갱신합니다. 한도에 가까워지면 전송 전에 자동으로 압축합니다. 같은 계열끼리의 교체(예: GPT에서 GPT, 공식 Claude에서 중계 서비스의 Claude)는 기존의 정확한 사용량을 그대로 사용합니다.
  - OpenAI 호환 중계 서비스나 OpenRouter 등을 통해 사용하는 Claude 모델은 Claude 방식으로 토큰을 계산하여 더 이상 10~20% 적게 계산하지 않습니다.
  - 모델이 컨텍스트 한도 초과를 보고하면 자동 압축은 반드시 이전 내용을 먼저 접은 뒤 재시도합니다. 이전에는 이미 압축된 긴 대화에서 아무것도 접지 않고 그대로 다시 보내 또 실패할 수 있었습니다.
- **중지한 뒤나 응답 도중 새 메시지를 보내면 모델이 이전 응답이 끝나지 않았음을 압니다:** 이전에는 응답이 중단되어도 모델이 전혀 알지 못해, 하던 작업을 계속 이어서 해야 하는 것으로 여기거나 한 문장의 보충을 작업 전체로 해석할 수 있었습니다. 이제는 다음과 같이 동작합니다.
  - 입력창의 중지 버튼(사각형 아이콘)이나 Esc를 누른 뒤 메시지를 보내면 모델은 사용자가 의도적으로 멈췄음을 압니다. 계속하기를 요청하거나 그 작업에 보충·수정이 있지 않는 한 이어서 하지 않고 먼저 꺼내지도 않습니다.
  - 응답이 실행 중일 때 대기열에서 "지금 전송"을 누르면, 새 메시지가 방금 한 작업의 보충이나 수정(예: "그리고 휴대폰 번호는 읽기 전용으로", "계속")이면 그 변경을 반영해 작업을 끝냅니다. 다른 용건이면 새 용건만 처리하고 이전 응답이 끝나지 않았음을 최대 한 문장으로 언급합니다.
  - 같은 파일이나 페이지만 언급한 새 요청은 예전 작업을 이어 하라는 신호로 처리되지 않습니다.
### 메모리

- **메모리 파일이 더 이상 검색 결과에 나오지 않습니다:** 메모리 파일(프로젝트의 `.breezell/memories/workspace_memories.md`와 홈 폴더의 `global_memories.md`)은 작성 당시의 상황을 적은 노트입니다. 코드 검색에서는 이전에 코드와 함께 반환되어, 모델이 오래전 기록을 현재 사양으로 오해하고 최근에 요청한 내용을 되돌릴 수 있었습니다. 이제:
  - 텍스트 검색, 심벌 검색, 파일 이름 검색은 무시된 파일을 포함하도록 지정해도 이 두 메모리 파일을 반환하지 않습니다. 같은 폴더의 규칙 파일(`global_rules.md`, `global_skills.md` 등)과 `.breezell/` 하위의 다른 파일은 이전처럼 검색되며, 시점이 붙은 노트로 취급되지 않습니다.
  - 모델이 메모리 파일을 직접 열면, 기록이 오래되어 틀릴 수 있는 시점별 노트라고 안내받습니다. 최신 요청과 현재 코드가 우선이며, 모델은 불일치를 지적하고 해당 항목을 업데이트할지 묻습니다.
  - 모델은 메모리를 "이 날짜 기준 상황"과 적용 조건으로 쓰고 영구적인 규칙으로 쓰지 않습니다. 자신의 변경으로 항목이 틀리게 되면 같은 턴에 그 항목을 업데이트하거나 삭제합니다.
- **대화에서 추출된 메모리는 그 대화에 다시 주입되지 않습니다:** "메모리 N개 주입(… 상주 · … 관련)"의 관련 메모리에 현재 대화에서 추출된 메모리가 포함되지 않습니다. 그 내용은 이미 대화 안에 순서대로 존재하며, 다시 메모리로 주입되면 상시 규칙처럼 읽혀 모델을 이전 요청으로 끌어당기고 다른 대화의 메모리 자리를 차지했습니다. 다른 대화에서는 이 메모리가 평소대로 사용되며, 직접 저장한 메모리는 영향을 받지 않습니다. 메모리와 코드가 맞지 않으면 모델은 요청하지 않은 코드를 고치지 않고 그 점을 지적합니다.

### 편집기

- **"파일 N개 변경됨" 버의 "다음 →"이 동작하지 않았습니다:** AI가 파일을 편집하면 편집기 하단에 "파일 9개 변경됨"과 "다음 →"이 표시됩니다. 그 목록의 첫 번째 파일이 더 이상 열리지 않으면(나중에 삭제·이름 변경되었거나 이전 세션의 변경이 남아 있음) "다음 →"은 아무 반응이 없었습니다. 열어 둔 파일이 목록에 없어서 클릭할 때마다 같은 파일을 재시도했고, 버튼이 계속 동작하지 않았습니다. 이제:
  - 열리지 않는 파일은 건너뛰고, 열리는 다음 변경 파일로 이동합니다. 버의 좌우 화살표(이전/다음 파일)와 단축키 Ctrl+Alt+Shift+→／←(Mac: Ctrl+Option+→／←)도 같습니다.
  - 목록의 어떤 파일도 열리지 않으면 이유를 알림으로 표시합니다.
  - 포커스가 편집기에 없을 때(예: 다른 패널을 클릭한 직후)도 버튼이 작동합니다.
  - 원격 작업 공간(SSH, WSL)에 남은 변경이 Breezell을 다시 시작한 뒤 열 수 없는 로컬 경로로 돌아오지 않습니다.

### Entanglement 모드

- **"인간 개입 모드"가 도구를 지정할 수 없는 모델에서 멈추지 않습니다:** "Entanglement 모드 엄격 검증"의 "인간 개입 모드"를 켜면 Breezell은 모델에게 질문 패널로 요구 사항을 확인하도록 요청합니다. 일부 모델은 이를 수행하지 못합니다. GLM은 요청을 무시하고 텍스트로 답하는데, 그 응답이 오류(AI_ToolChoiceViolationError)로 버려지고 오류 카드는 네트워크 문제라고 표시했습니다. Kimi와 DeepSeek V4는 사고를 켠 상태에서 이 요청을 그대로 거부합니다(HTTP 400). 확인이 끝나지 않아 이후의 모든 메시지도 같은 방식으로 실패했습니다. 이제는 다음과 같이 동작합니다.
  - 모델이 질문 패널을 쓰지 않고 텍스트로 답하면 그 응답을 보존합니다.
  - 모델이 거부하면 도구를 지정하지 않고 다시 보냅니다.
  - Breezell은 그 모델을 기억하고 이후에는 질문 패널을 요구하지 않습니다.
  - 모델이 응답 안에서 질문하고, 해당 행에는 "이 모델은 질문 패널을 쓸 수 없어 응답에서 질문합니다. 다음 메시지가 답변입니다"라고 표시됩니다. 답변하면 "대화에서 이해를 확인했습니다"가 표시되며 확인이 완료되고 도구가 해제됩니다.
  - 오류 카드는 모델이 지정한 도구를 호출하지 않았다고 정확히 표시하며, 네트워크 문제라고 하지 않습니다.

### 채팅

- **Agent 모드가 더 이상 Entanglement 모드로 전환되지 않습니다:** 적응형 전략을 켠 상태에서 Agent 모드가 "엄격"으로 판정한 작업(오류 증상을 설명한 메시지나 수정 내용을 정리한 업데이트 노트를 붙여넣은 경우 등)은 기존에 Entanglement 모드로 실행되어 LOCATE／VERIFY／FIX 조사 패널, 완료 조건, "이런 증상은 사용자의 확인으로 확정합니다"라는 엄격한 검증이 표시되었습니다. 이제 Agent 모드는 항상 Agent로 전체 도구 세트와 함께 실행됩니다. Entanglement 조사 패널과 엄격한 검증은 사용자가 직접 Entanglement 모드를 선택했을 때만 나타납니다.

  - 오랜 침묵을 이유로 시간 초과로 판단해 중단하고 재시도하지 않고 응답이 올 때까지 기다립니다.

## 1.4.33 · 핫 업데이트 · 2026-10-15

- **비디오 첨부:** 채팅에 드롭한 비디오는 모델이 지원 목록(예: `kimi-k3`)에 없다는 이유로 차단되지 않고 항상 전송됩니다. 비디오 이해 여부는 모델과 제공자에 달려 있습니다. Anthropic 및 OpenAI Responses 형식은 비디오를 전달할 수 없으므로, 비디오가 첨부되지 않았음을 모델에 알리고 요청은 정상적으로 진행됩니다.
- **안정적인 도구 호출:** 모델이 도구 호출을 텍스트로 작성할 때 문자열을 받는 매개변수가 `true`, `null` 또는 `123`을 불리언이나 숫자로 변환하지 않으며, Python 코드를 교체할 때 문자열 내부의 `True`와 `None`이 `true`와 `null`로 바뀌지 않습니다.
- **중지 및 오류 처리:** 추론 도중 중지를 누르거나 오류가 발생했을 때 사고 시간이 `0.1s`로 표시되거나 초 단위로 잘리지 않고 소수점 첫째 자리까지 유지되며, 저장된 답변에 내부 마크업이 남지 않습니다.
- **모드 전환 카드:** 건너뛰기, 취소 또는 카운트다운 후 이전 실행이 끝날 때까지 기다린 뒤 계속 진행하므로 두 실행이 겹치지 않습니다. 카드가 대기하는 동안 대기열에 있는 메시지를 보내면 새 메시지가 실행을 이어받습니다.
- **Agent Teams:** 모든 팀원이 동일한 첫 메시지에서 시작하며, 시스템 알림 대신 사용자의 원본 요청을 담고 작업 ID를 포함하며 완료 검사와 동일한 검증을 요구합니다. 팀원을 중지하거나 해산하면 리소스가 완전히 정리됩니다.
- **도구 목록:** 폐기된 `create_team`이 더 이상 Agent, Entanglement, Analyze 또는 Plan에 나타나지 않아 모델이 작동하지 않는 진입점을 호출하지 않습니다.
- **파일 검증:** 이미 확인된 파일이 전체 덮어쓰기되거나 스크립트로 변경되면 이전 확인은 무효화되며 파일을 다시 확인해야 합니다.
- **적응형 전략(Adaptive Strategy):** 타임아웃된 분류(Triage) 요청은 백그라운드에서 모델을 계속 점유하지 않고 항상 취소됩니다.

### 수정

#### 대화 및 Agent
- 새 브랜치를 만들기 전에 원본 대화 본문을 먼저 복사합니다. 이미 본문이 사라진 이전 브랜치는 줄 번호를 이용해 내용을 복구할 수 있습니다.
- 다시 로드된 메시지는 본문이 복구된 뒤 플레이스홀더 높이를 해제합니다. 접힌 도구/추론 블록도 펼쳐졌을 때의 높이를 유지하지 않습니다. 브랜치 생성이 끝나기 전에는 브랜치 버튼의 중복 클릭을 무시합니다.
- 긴 대화는 하나의 연속 목록으로 열립니다. 아직 스크롤하지 않은 본문은 플레이스홀더로 유지하고 해당 위치에 도달할 때 로드합니다. “보관된 메시지” 안내와 마지막 부분만 유지하던 기존 창 방식을 제거했습니다. 다시 마운트한 뒤에도 줄 높이가 유지되며, 스트리밍 코드 하이라이트는 전체 블록을 깜빡이지 않고 증분 업데이트합니다.
- 현재 선택된 대화를 다시 열어도 전환 과정을 재생하지 않아 대화가 짧아지거나 마지막 부분 이외의 본문이 사라지지 않습니다. 로컬 Git 스냅샷이 해당 대화의 파일을 포함하지 않더라도 기록의 대기 중 diff 개수는 유지됩니다.
- 대화 본문은 현재 그 본문을 표시하는 뷰에서만 해제됩니다. 이미 에디터 탭에 열린 대화를 다시 열면 사이드바에 두 번째 복사본을 만들지 않고 기존 탭으로 돌아갑니다. 두 뷰가 서로 화면의 콘텐츠를 언마운트하는 문제를 방지합니다.
- 창이 최소화된 동안 실행 중인 작업에 대해서는 백그라운드 스로틀링을 끄고 앱 일시 중단을 막습니다. 실행 종료, 창 다시 로드, 창 닫기 이후에는 정상 동작으로 복구됩니다.
- 현재 선택한 모델이 삭제되거나 숨겨지면 모델 칩이 표시 가능한 다른 모델로 자동 전환됩니다. 모든 모델을 비활성화한 경우 먼저 모델을 하나 활성화하라는 안내가 표시됩니다.
- 한동안 외부 파일 읽기/쓰기 기본값이 꺼져 있었고 그 `false` 값이 설정에 저장되어, 이후 기본값을 바꿔도 이미 저장된 설정에는 반영되지 않았습니다. 업그레이드 시 두 권한을 다시 켜고 마이그레이션 표시를 기록하며, 이후 사용자가 직접 끈 선택은 그대로 유지합니다.
- 커밋 대화상자를 워크벤치 레이어로 옮겼습니다. 에디터 탭에서 시작한 브랜치 작업이 사이드바에 의해 잘리지 않습니다.

#### 저장소
- 대화를 삭제하면 데이터베이스를 즉시 압축해 SQLite freelist에만 남던 공간을 실제 디스크에 반환합니다. 이전 데이터베이스는 전체 `VACUUM`을 한 번 실행하며, 로그에는 실제 회수된 용량을 기록합니다.
- 정기 전체 `VACUUM`은 기록 쓰기 큐를 기다리고, 어떤 대화도 스트리밍 중이거나 도구를 실행 중이지 않을 때만 수행합니다.

### 개선
- 기록 목록의 미커밋 경로 집합을 변경 시 한 번만 계산하고 SCM 상태, 경로 복원, diff 범위가 바뀔 때까지 캐시합니다. 변경 파일이 약 1,000개일 때 기존 약 25 ms였던 단일 다시 그리기 비용을 줄였고, 약 10,000개일 때 기존 약 265 ms였던 비용도 크게 낮췄습니다.

- **MCP 마켓:** 카테고리별로 정리하고 페이지를 다시 설계했습니다.
- 개인정보 안내를 카드 레이아웃으로 바꾸고 내용을 보강했습니다.

#### Breezell Mind
- 대화가 작업 노트를 자동으로 유지합니다. 긴 스레드가 예산 한도에 닿으면 이전 기록을 접고 노트와 요지만 남깁니다.

- 컨텍스트 압축은 백그라운드에서 인수인계 문서를 준비하고 갱신합니다. 원본 기록은 로컬에 남습니다. 압축이 너무 잦으면 경고합니다.

#### 대화

- 보내기 전 첨부 token 추정이 정확하고, 긴급 압축이 현재 턴도 접을 수 있습니다.
- 오류 카드에 표시된 공급자가 실제로 실패한 쪽과 같습니다.

### 수정

- 긴 채팅이 더 이상 멈추지 않습니다. 메시지가 너무 많을 때 인터페이스가 멈추는 문제를 수정했습니다.
- 채팅 기록을 볼 때 스크롤이 더 이상 하단으로 되돌아가지 않습니다.
- 터미널 하위 프로세스 누수를 수정하여 잔여 프로세스로 인한 메모리 급증이나 충돌을 방지했습니다.
- 파일 경로 표시를 수정하여 줄임표 때문에 링크가 가짜 경로로 손상되지 않습니다.
- Super Memory가 비어 보이는 문제를 수정했습니다. AI 사고 태그가 더 이상 유출되어 메모리 표시를 비우지 않습니다.
- 터미널 명령 접기를 수정하여 실패한 명령이 이후 성공한 명령에 의해 숨겨지지 않습니다.
- 계획 할 일의 부동 알림 스타일을 수정했습니다(이중 레이어 배경 문제).
- 파일 목록을 펼칠 때 채팅이 튀는 문제를 수정했습니다.
- AI가 더 이상 “계속할까요?”라고 반복해서 묻지 않고 자율적으로 실행합니다(자체 테스트가 필요합니다).
- Skills 콘텐츠 상자의 스크롤바를 정렬했습니다.
- 명령 실행이 종료 코드 0으로 인식되었지만 실제 빌드가 실패하는 경우를 수정했습니다.

- 파일 작업, MCP 도구 등의 카드 스타일을 통일하도록 AI 도구 호출 인터페이스를 재설계했습니다.
